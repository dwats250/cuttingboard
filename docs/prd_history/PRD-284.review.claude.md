## Critical Problems (required edits — all APPLIED)

- **Problem:** R2's proportional recompute `(d/c)×c` does not reliably reproduce
  `decision.dollar_risk` at multiplier 1.0, so R3's "value-for-value" guarantee
  was not structural.
- **Root cause:** `dollar_risk` is cents-rounded at the producer
  (`options.py:299`), so `decision.dollar_risk / decision.contracts` is not
  exactly `risk_per_contract`, and `(d/c)×c != d` in float (e.g. `d=100.0,
  c=3`).
- **Fix:** Add a unity short-circuit — when `size_multiplier == 1.0`
  (equivalently `materialized_contracts == decision.contracts`) leave
  `contracts` and `dollar_risk` untouched, changing only the policy fields, as
  `execution_policy.py:179–185` does today. R3 is then structural (PRD-198
  invariant 6). **APPLIED** — SCOPE (unity short-circuit bullet), R2 (positive
  path narrowed to `materialized_contracts != decision.contracts`), R3
  (reworded "structural"), STOP-AND-AMEND #4.

- **Problem:** The R2 recompute emitted an unrounded float, diverging from the
  cents convention every `dollar_risk` carries.
- **Root cause:** `assert_valid_contract` (`contract.py:746–754`) checks only
  finite ≥ 0, so it would not catch an unrounded value.
- **Fix:** Specify `round(dollar_risk_per_contract × materialized_contracts, 2)`.
  **APPLIED** — SCOPE and R2; R2 FAIL line now includes the `66.67` rounded
  boundary case.

- **Problem:** SCHEMA claimed `size_rounds_to_zero` has "zero occurrences in any
