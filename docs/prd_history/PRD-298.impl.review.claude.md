## REQUIRED EDITS

### 1. The `halt_cause == MARKET_STRESS` guard has no red test; a test comment falsely claims it does

- Guard: `cuttingboard/runtime/__init__.py:302`
  `return bool(system_halted) and halt_cause == HaltCause.MARKET_STRESS and not errors`
- False comment: `tests/test_prd298_halt_execution_semantics.py:63`
  (`test_validation_halt_is_failure`): "(Mutation: dropping the MARKET_STRESS
  check flips a VALIDATION halt to True.)"

Failure scenario (verified by mutation): replacing the predicate tail with
`return bool(system_halted) and not errors` (i.e. deleting the
`halt_cause == HaltCause.MARKET_STRESS` clause) leaves **all 15 tests in
`tests/test_prd298_halt_execution_semantics.py` green**. The mutation is not
caught. The comment on `test_validation_halt_is_failure` is therefore false:
that test passes `errors=["missing HALT symbol"]`, so the independent
`not errors` clause returns `False` for it regardless of whether the
`MARKET_STRESS` clause is present. Every VALIDATION-arm test in the suite
carries a non-empty `errors` list, so none of them exercises the
`MARKET_STRESS` clause in isolation.

This violates the PRD's own CHANGE SURFACE line ("Each guard ships a red test
(PRD-198 #4)") and PRD-198 invariant #4's ban on "any test that cannot fail"
for a shipped guard. The `not errors` guard, by contrast, *does* ship a genuine
red test (`test_market_stress_halt_with_errors_is_failure` dies when
`not errors` is dropped — verified).

Fix (additive, ~3 lines): add a predicate case asserting a non-MARKET_STRESS
halt with an EMPTY errors list is `False`, e.g.

```python
def test_non_market_stress_halt_without_errors_is_failure():
    # Red test for the MARKET_STRESS guard: only MARKET_STRESS promotes a halt,
    # independent of the `not errors` clause. Dies if the MARKET_STRESS check is dropped.
    assert _is_execution_success(
        verification_pass=True, status=FAIL, system_halted=True,
        halt_cause=HaltCause.VALIDATION, errors=[],
    ) is False
```

This case returns `True` under the MARKET_STRESS-drop mutation, so it dies as
required. Also correct the false parenthetical on
`test_validation_halt_is_failure:63` (that test actually exercises the
`not errors` clause, not the `MARKET_STRESS` clause).

Severity note for the merger: this is a **test-completeness / PRD-198-#4
defect, not a live masquerade**. On the real daily path a VALIDATION halt
always appends `halt_reason` to `errors`
(`cuttingboard/runtime/__init__.py:1080`) while a MARKET_STRESS kill-switch
halt does not (`1082-1097`), so the correlated `not errors` clause
independently prevents any non-MARKET_STRESS halt from reaching
execution-success in production. Invariant I3 holds at runtime today. The
required edit restores the guard's independent red-test coverage that the PRD
explicitly promised.

## RECOMMENDED

1. **SUCCESS arm could be hardened defensively.** `_is_execution_success`
   returns `True` at `:300-301` for `status == SUCCESS` without re-checking
   `system_halted`. This is safe today by construction — `_build_run_summary`
   (`:1496`) sets `status=FAIL` whenever `system_halted or errors`, and
   `execute_run`'s recompute (`:332-336`) only ever downgrades — so a halted
   run can never present `status == SUCCESS` to the predicate. An explicit
   `and not system_halted` on the SUCCESS arm would make the no-masquerade
   property local to the predicate rather than dependent on an invariant two
   call-sites away. Optional; no current defect.

2. **Send-failure-zero on a market-stress halt is now unbacked (accepted by
   design).** With rc=0 for a valid halt, the workflow `if: failure()` backstop
   (`.github/workflows/cuttingboard.yml:457`) no longer fires, so if
   `send_notification` returns `False` for a market-stress halt the run yields
   zero notifications with no fallback. This is consistent with the PRD's
   stated design ("the runtime's own send is the only channel") and matches how
   any SUCCESS run already behaves on a failed send, so it is not a regression
   against intent. A follow-up could consider a fail-loud on halt-send failure;
   out of scope here.

3. Consider an end-to-end `cli_main` test that drives a real (unmocked)
   market-stress halt to `rc == 0` in one assertion. R1 is currently covered by
   composition (`test_execute_run_market_stress_halt_...` proves
   `RunResult.execution_success is True`; the mocked `cli_main` tests prove the
   `getattr` mapping), which is adequate but split.
