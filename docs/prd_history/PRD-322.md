REQUIREMENTS

R1 — Health-aware trend summary (honesty defect 1)
`_tape_trend_summary(ts_records, ts_health)` (pure, beside
`_build_tape_slots`) returns (text, derivation token): rows whose
`trend_alignment` is in {BULLISH, BEARISH, MIXED} are "computed"; all
six computed -> byte-identical current healthy string ("N of 6 bullish",
derivation `bullish-row-count`); some computed -> "N of M bullish · K
n/a"; zero computed with records present -> wording from `_ts_health`
("Market closed — awaiting intraday data" for MARKET_CLOSED/
AWAITING_DATA, "Trend stale" for STALE, else "Trend data unavailable"),
derivation `trend-health`; records absent -> "Trend unavailable",
derivation `trend-health`. The TAPE trend item consumes it (replacing
the raw BULLISH count) — the first TAPE-side consumer of `_ts_health`
(today consulted only in DETAILS); the macro gate in R2 likewise gives
the genuinely-dead `_tape_health` local its first consumer.
FAIL: a fixture with six DATA_UNAVAILABLE rows renders "0 of 6 bullish"
(mutation: revert to the raw count -> red); or the healthy six-computed
string/derivation differs by one byte from today's.

R2 — Macro honesty (honesty defect 2) + pressure note
The MACRO zone-item renders bias + votes exactly as today when macro
data is present and not suppressed; when `_tape_health == "MISSING"` it
renders "Macro unavailable" instead of a fabricated bias (keying on
MISSING only — FALLBACK also fires on missing tradables and must not
trip the gate); when `integrator_suppress["macro_bias"]` is set the
item is omitted exactly as today. A `zone-note` under the MACRO item
renders per-driver pressure states from `_build_pressure_snapshot`
components (volatility/dollar/rates/bitcoin) via a closed display map
(RISK_ON->"risk-on", RISK_OFF->"risk-off", NEUTRAL->"neutral",
UNKNOWN->"n/a"); `pressure is None` -> "Pressure unavailable".
`overall_pressure` never renders in TAPE.
FAIL: an empty-macro fixture renders any "MACRO BIAS" text INSIDE the
`id="tape-zone"` block (the DETAILS macro-tape block is out of scope
and unchanged; mutation: remove the gate -> red); a suppressed-bias
fixture renders a bias line in the TAPE zone; the pressure `zone-note`
contains the word "overall" or any token outside the closed four-state
display map (the bias line's own legitimate "MIXED" vote-tie wording is
not in scope for this clause); or any pressure token outside the closed
map renders.

R3 — Seven-driver strip
The TAPE driver strip iterates all seven driver slots data-driven from
`MACRO_ROW_2` + `MACRO_ROW_1` (`cuttingboard/delivery/
macro_tape_layout.py`), rendering each slot's display label + arrow +
formatted value; an absent driver renders a na-styled chip with the
existing "--" placeholder (absence is visible, never zero). The strip
does NOT reuse `macro-tape-slot`/`macro-tape-value` classes or
`data-symbol` attributes (they are regex-harvested and order-pinned in
DETAILS).
FAIL: fewer than seven chips render when all drivers are present; an
absent-driver fixture drops its chip instead of rendering the na chip;
or `macro-tape-value`/`data-symbol` appears inside the TAPE zone.

R4 — Trend chips
Six per-symbol chips in `config.TREND_STRUCTURE_SYMBOLS` order: symbol +
the `_TS_ALIGN_ABBR` token (BULL/BEAR/MIX) + `_trend_structure_composite_display`
arrows + a vs-VWAP glyph — a closed three-token vocabulary NEW to this
PRD (V↑/V↓/V=) — only when `price_vs_vwap` is a computed comparison; a
non-computed row renders a na-styled "SYM —" chip. Chip colour classes reuse the existing `.tape-slot`
up/down/flat/na set keyed on alignment. Breadth-vs-concentration is
carried by enumeration only — no computed breadth metric, ratio, or
score.
FAIL: chip order differs from the curated tuple; an alignment/arrow/
glyph token renders that does not come verbatim from the existing
translators or the PRD-defined closed V↑/V↓/V= set; or a banned
agreement word (ALIGNED, DIVERGING, CONFLUENT,
"systems agree", "agreement", "confluence") appears anywhere in the
TAPE zone in any healthy or degraded render (extends the existing ban
test).

R5 — GEX / participation honest-unavailable
When `_ms_gex_card` is None the TAPE renders a GEX zone-item with the
exact existing label literal and value "unavailable", shaped to keep
`test_gex_decision_outputs_unchanged`'s literal regex matching; when
`_ms_movement_card` is None a PARTICIPATION item renders "not captured".
Both rows stay last in the zone grid. The invariance test updates to
strip the GEX summary row from BOTH documents; the movement
baseline-neutrality tests stay green unmodified.
FAIL: a gex-absent render says nothing about GEX in the TAPE zone
(mutation: restore silent omission -> red); or the updated invariance
test passes while the absent-side GEX row shape diverges from the
regex.

R6 — Structural preservation and overflow
Zone set/order unchanged (`class="block operator-zone"` count stays 4;
the five zone ids keep their pinned order); nothing moves out of
DETAILS; the 430px phone block stays byte-identical to
`_PRD318_PHONE_BLOCK` (all new styling lives in base CSS, flex-wrap
strips, nowrap within a chip); the golden regenerates exactly once from
the test's own frozen-clock absent-path render; browser evidence shows
zero horizontal overflow at 360/390/430/1280 and no new multi-screen
wall before WATCHING.
FAIL: any pinned zone/order/phone-block/derivation test needs an edit
beyond the two FILES-listed test surfaces; horizontal overflow at any
of the four widths; or the extended TAPE zone's rendered height exceeds
340 CSS px at 390px width in the browser evidence.
