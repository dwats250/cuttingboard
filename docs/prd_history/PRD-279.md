GOAL
Make `#system-state` state its verdict in the three words a trader
scans for — HALT / STAY FLAT / TRADE PERMITTED — as a prominent label
above its current verdict/context/timestamp lines, with a safe
fallback when the state can't be determined.

SCOPE
Two new lines inside `#system-state` (`render_dashboard_html`),
derived from the already-computed `title`/`_verdict_cls`, plus CSS.

OUT OF SCOPE
No new contract/schema fields; no change to `_decision_title`,
`_ctx_reason`, or any existing rendered line/block; no change to
`notifications/formatter.py` or `ui/app.js`; no "changed since
previous run" (already covered by `#run-delta` — future proposal, not
a blocker); no new freshness algorithm; no broad refactor.

M cuttingboard/delivery/dashboard_renderer.py
M tests/test_dashboard_renderer.py

CHANGE SURFACE (CONSUMER, HIGH-RISK; FILES intersects HIGH-RISK FILES)
Only `#system-state` changes: two new `w(...)` calls plus a CSS rule.
No other function, block, or existing rendered line is modified.

REQUIREMENTS

R1 — Three-word decision state derived from the existing `title`
value (`_decision_title(outcome, bool(system_halted), status)`,
already computed, never independently recomputed): `"SYSTEM HALT"` ->
`"HALT"`; `"TRADE SETUP ACTIVE"` -> `"TRADE PERMITTED"`; any other
value (`"NO TRADE"`, `"MONITOR"`) -> `"STAY FLAT"`. `"TRADE PERMITTED"`
is thus only reachable via the affirmative `outcome == "TRADE"` path
already inside `_decision_title`, never via absence of halt.
FAIL: `title == "SYSTEM HALT"` doesn't render `"HALT"`; `title ==
"TRADE SETUP ACTIVE"` doesn't render `"TRADE PERMITTED"`; or
`"NO TRADE"`/`"MONITOR"` renders anything but `"STAY FLAT"`.

R2 — Wrap the R1 mapping in try/except; render `"STATE UNAVAILABLE"`
(neutral CSS class) on any exception instead of propagating.
FAIL: an unexpected error crashes `render_dashboard_html` instead of
yielding `"STATE UNAVAILABLE"`.

R3 — Reuse `_verdict_cls` (already computed for `sys-verdict`) as the
new line's color class, so the two verdicts never disagree in color;
`"STATE UNAVAILABLE"` (R2) always uses `sys-flat`.
FAIL: the new line's CSS class differs from `_verdict_cls`, other than
the R2 fallback case.

R4 — Existing lines unchanged: `<h2>SYSTEM STATE</h2>`, `.sys-verdict`,
`.sys-context` (incl. kill-switch line), and `UPDATED` render
byte-identical to current output for every existing fixture.
FAIL: any existing `test_dashboard_renderer.py` assertion fails.

DATA FLOW
`outcome`/`system_halted`/`status` -> `_decision_title` (unchanged) ->
R1 mapping -> new `w()` lines, styled via R3's `_verdict_cls`.

FAIL CONDITIONS
Each requirement's inline FAIL: line is the complete, binary condition.
