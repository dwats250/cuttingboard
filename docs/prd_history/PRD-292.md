WHY NOW
`_OPTIONAL_MACRO_DRIVERS = frozenset({"oil", "gold", "silver"})` is declared
twice — in `cuttingboard/contract.py` and `cuttingboard/delivery/payload.py`.
The payload copy carries a comment admitting the duplication is a deliberate
hack "to keep this module free of cross-package imports," but that rationale is
already void: `delivery/payload.py` imports `PipelineContract` from the leaf
`cuttingboard/contract_types.py`. Two frozensets that "must not drift" are
latent drift risk with no guard.

MAX EXPECTED DELTA
~0 net production LOC (a dedup): removes two duplicate declarations, adds one
authoritative declaration in the leaf, and two import references. Plus one new
test file (~30 lines, test-only, uncapped). No schema, behavior, producer, or
contract change. Binding ceiling: <= 5 net production LOC.

GOAL
Single-source the optional-macro-driver vocabulary in the existing leaf
`contract_types.py`; import it from both consumers; delete both duplicate
declarations; prove both paths resolve to one authority, with no new
`payload -> contract` edge and no behavior change.

SCOPE
- Add the authoritative `_OPTIONAL_MACRO_DRIVERS` to `contract_types.py` (the
  leaf, which imports only `typing` and is already imported by both consumers).
- `contract.py` and `delivery/payload.py` import it from the leaf; both
  duplicate declarations deleted; exact vocabulary preserved.
- Add a test proving single-authority identity + preserved vocabulary + no
  residual duplicate declaration.

OUT OF SCOPE
- No new module (the existing leaf hosts it).
- No `payload -> contract` dependency.
- No change to `_build_macro_drivers`, `assert_valid_contract`,
  `_require_macro_drivers`, the contract schema, or any runtime behavior.
- No unrelated cleanup in the touched files.
