## RECOMMENDED EDITS

1. `cuttingboard.yml` Commit-artifacts step (lines 390, 416): `CB_STAGE` is set
   to `render_commit` and later `artifact_validate` inside a single step. A
   failure of the `git commit`/`git checkout` sub-phase *after* line 416 would
   be reported by the notifier as stage `artifact_validate` (there is no
   distinct commit sub-stage). This is faithful enough for the PRD (R9 only
   requires the four named new stages be distinct, which they are) and commit
   failure is rare; a dedicated `commit`/`push` sub-stage marker would sharpen
   the alert but is out of PRD scope. Non-blocking.

2. `check_runtime_readiness.check_writable_dirs` writes a `.readiness_write_probe`
   under `logs/`, `reports/`, `data/cache/` and unlinks it. Because this gate
   runs before execute and the probe is removed in the same call, it cannot
   pollute a committed artifact; still, an interrupted run (SIGKILL between
   write and unlink) would leave a stray dotfile. `git add -f logs/` later
   would then stage it. Extremely low likelihood; a `finally: probe.unlink(missing_ok=True)`
   would harden it. Non-blocking.

## RATIONALE

PRD-297 executes the atomic gate-swap exactly as scoped: it deletes the
redundant morning-path lint/test gate, adds an exact-SHA CI-authority proof that
is provably total and fail-closed (only a `completed`+`success` push run of
`ci.yml` at the exact HEAD returns 0; every other condition — pending past
budget, missing, failed, and every HTTP/auth/parse/schema error — exits
non-zero and is named), a narrow network-free runtime-readiness gate, a
`REVISION_DRIFT` HEAD re-check before execute, and a post-render / pre-commit
artifact-health validation that reuses the hourly run-health checks while
leaving the flagless hourly path bit-identical. The non-blocking
`drift_full_suite.yml` is structurally incapable of gating, publishing, or being
selected by the proof. `latest_run.json`'s schema and single write site are
untouched, and the fail-loud notifier now names the four new stages while still
deriving only from current workflow context. Every guard ships a red test
(PRD-198 #4), and the negative tests are behavioral, not source-order theater.
The two recommended edits are hardening niceties outside the PRD's binding
requirements. No correctness defect blocks the merge.
