WHY NOW
A valid market-stress kill-switch HALT is a correct, intended live observation (quotes validated, regime computed, kill switch correctly halts new positions) but today concludes the GitHub executor as FAILURE and never publishes: cli_main (cuttingboard/runtime/__init__.py:237) returns 0 only when status==SUCCESS, and a halt is status=FAIL by construction (_build_run_summary:1436; verify invariant :1757). So rc=1 -> PUBLISH_READY stays false (cuttingboard.yml:298) -> no publish, conclusion=failure. The dashboard shows the stale prior board (client-side BOARD-N-OLD banner) instead of today's real halt observation, and a valid observation is indistinguishable from a crash to any GitHub-native consumer. Upstream authority: MATERIAL packet audits/halt-execution-semantics-2026-08/PACKET.md (rev 2, corrected+confirmed head 6c8837d; independent adversarial review REQUIRED-CHANGES->ACCEPT + exact-head confirmation ACCEPT) and the owner 2026-08-11 Option-B routing ruling ("a valid market-stress HALT is domain HALT but execution SUCCESSFUL VALID OBSERVATION; do NOT flip status; distinguishable from degraded halt"). Prerequisite to the Cloudflare clock/executor first-success coordination.

GOAL
Decouple EXECUTION success from DOMAIN status on the daily path so a valid market-stress HALT concludes the executor successfully (exit 0), publishes the halt board, owns its single HALT notification, and satisfies the OPEN slot - while remaining truthfully HALTed (status=FAIL / system_halted=True / outcome=HALT / errors=[] / kill_switch=True unchanged) in domain artifacts. VALIDATION halts, crashes, unusable-data, and readiness/artifact-validation/publish failures stay execution FAILURE (exit 1, no publish).

SCOPE
1. In cuttingboard/runtime/__init__.py, compute an in-memory execution-success signal in execute_run and drive cli_main's exit code from it (not from status): execution_success = verification.pass AND (status==SUCCESS OR (system_halted AND halt_cause==MARKET_STRESS AND not errors)). Conveyed on EVERY return path (exception path -> False); cli_main treats an absent signal as failure (fail-closed). No key is added to the persisted summary dict.
2. The daily (LIVE/SUNDAY) path always sends its single market-stress HALT notification (bypass the state-key dedup for that outcome) so a dedup-suppressed repeat halt cannot yield ZERO notifications.
3. Behavioral tests per outcome class and per touched consumer.

OUT OF SCOPE
- No change to domain truth: status stays FAIL for a halt; system_halted / outcome=HALT / errors / kill_switch unchanged; no flip of status to SUCCESS.
- No logs/latest_run.json or contract schema change; no new persisted field; halt_cause is not surfaced.
- No change to the HOURLY path (alert_runner / _execute_notify_run) or to shared classify_notification_priority semantics.
- No Cloudflare surface / dispatch contract / CF-D1b / CF-E2.
- No .github/workflows/** change (the rc==0 gate already suffices).
- No new authority model or persisted attempt/idempotency state.

REQUIREMENTS

R1 - cli_main returns exit 0 for a valid market-stress HALT (system_halted AND halt_cause==MARKET_STRESS AND errors==[] AND verification passed) and for TRADE/NO_TRADE; exit 1 for a VALIDATION halt, a crash, or any run with a non-empty errors list.
FAIL: a valid market-stress halt exits non-zero, OR a VALIDATION halt / crash / errors!=[] run exits 0.

R2 - The `not errors` clause is explicit in the predicate (RC1): a constructed summary with system_halted AND halt_cause==MARKET_STRESS AND errors!=[] exits 1.
FAIL: a market-stress-labelled summary with a non-empty errors list exits 0.

R3 - The execution-success signal is conveyed on every execute_run return path; the exception path conveys False; cli_main treats an absent signal as failure (fail-closed) (RC2). No key is added to the persisted summary dict.

R4 - The persisted domain summary for a market-stress halt is unchanged: status=FAIL, system_halted=True, outcome=HALT, errors=[], kill_switch=True.

R5 - A valid market-stress halt exits 0 -> PUBLISH_READY=true -> the freshly-rendered halt board passes check_readiness --profile morning and is committed+pushed. A VALIDATION halt does not publish.
FAIL: a valid market-stress halt does not publish, OR a VALIDATION halt publishes.

R6 - Exactly one HALT notification is sent for a market-stress halt on the daily path, including a repeat halt whose coarse state key equals the prior published key. No double, no zero.
FAIL: a market-stress halt sends zero or two notifications on a single run.

R7 - The hourly path (alert_runner / _execute_notify_run), shared classify_notification_priority, verify_run_summary, and check_readiness are unchanged.
