WHY NOW
Dustin's session charter (2026-08-03) is the design-direction ruling
and Gate A: "Start the next product slice: Opportunity Survival
Summary." The dashboard already receives the full scanned-universe
survival picture — `payload.meta.symbols_scanned` (the surfaced total)
and the authoritative `sections.rejected` / `sections.watchlist`
record lists — but renders none of it. A trader cannot see, at a
glance, how many symbols were surfaced, how many survived to qualified,
and how many were rejected. PRD-281 explicitly named "no
opportunity-survival summary" as OUT OF SCOPE, deferring this slice to
its own PRD; this is that PRD.

Classified NOT MATERIAL per GOV-2 §1: renderer-only, stays within
`cuttingboard/delivery`, reuses already-authoritative payload values
(no new schema, contract, taxonomy, cross-layer seam, or tracked
finding resolved). LANE is HIGH-RISK regardless of diff size because
`cuttingboard/delivery/dashboard_renderer.py` is a HIGH-RISK FILE for
CLASS CONSUMER (same basis as PRD-279 / PRD-280 / PRD-281).

MAX EXPECTED DELTA
~30 production lines added in `dashboard_renderer.py` (one new
`#opportunity-survival` block appended after the `#system-state`
block, reusing the existing `.block` / `.kv-grid` / `.label` /
`.value` CSS — no new CSS rule); ~110 test lines in

GOAL
Render a small, self-contained OPPORTUNITY SURVIVAL block on the
dashboard showing four authoritative counts — surfaced, qualified,
watchlist, rejected — plus the primary (most frequent) rejection reason
when rejections exist. Derived entirely from values already present in
the payload at the renderer; no upstream, schema, or contract change.

SCOPE
- Add one new `<div class="block" id="opportunity-survival">` block,
  appended immediately after the existing `#system-state` block closes
  (`dashboard_renderer.py` `#system-state` block, `w('<div class=
  "block" id="system-state">')` through its closing `w("</div>")`) and
  before the `#alert-watchlist` block. No change to `#system-state`
  itself.
- Read only already-present payload values at the renderer:
  - surfaced = `payload.meta.symbols_scanned` (the aggregate produced
    at `cuttingboard/delivery/payload.py` as
    `qualified_count + rejected_count + watchlist_count`);
  - rejected = `len(payload.sections.rejected)` (the REGIME +
    QUALIFICATION rejection records, `payload.py` `rejected` list);
  - watchlist = `len(payload.sections.watchlist)` (WATCHLIST-stage
    records, `payload.py` `watchlist` list);
  - qualified = `symbols_scanned - rejected - watchlist`, clamped to
    `>= 0`.
- Reuse the existing `.block`, `.kv-grid`, `.label`, and `.value` CSS
  rules (`dashboard_renderer.py` style block: `.label`, `.value`,
  `.kv-grid`). No new CSS rule is added.
- Primary rejection reason: when `rejected > 0`, render one
  `PRIMARY REJECTION` row whose value is the most frequent `reason`
  string among the `sections.rejected` records, tie-broken
  deterministically by descending count then ascending reason string.
  The value is HTML-escaped via the existing `_esc` helper. When
  `rejected == 0`, no PRIMARY REJECTION row is rendered.
- Render gate: emit the block only when `symbols_scanned` is an int
  `> 0` AND lineage is coherent (`not unhealthy_lineage`, the existing
  `artifact_lineage_state in ("MIXED","STALE","MISSING")` gate). In
  every other case (missing/zero scan, or MIXED/STALE/MISSING lineage),
  render nothing — no `#opportunity-survival` element at all.

  Gating on `symbols_scanned > 0` also guarantees the qualified
  derivation is exact: a REGIME short-circuit is the only path that
  puts a non-QUALIFICATION record in `sections.rejected`, and it also
  forces `symbols_scanned == 0` (qualification is skipped, so
  `qualified_count = len(excluded) = len(watchlist) = 0`). Therefore,
  whenever the block renders, `len(sections.rejected)` equals the
  payload's `rejected_count` and `symbols_scanned - rejected -
  watchlist` equals the upstream `qualified_count` exactly — the
  derivation is the inverse of `symbols_scanned`'s own definition, not
  a proxy that can diverge (PRD-198 invariant 3). The `>= 0` clamp is
  defensive belt-and-suspenders for a state the gate already excludes.

OUT OF SCOPE
No new schema, contract field, payload key, or persisted artifact. No
change to `cuttingboard/delivery/payload.py`, `cuttingboard/contract.py`,
or any runtime / notification / pipeline file. No new rejection taxonomy
— the primary reason is the mode of the pipeline's own existing `reason`
strings, not a new categorization. No change to `#system-state`,
`_decision_title`, `_ctx_reason`, `_verdict_cls`, or the decision-state
precedence. No exposure of raw engine internals. No broader dashboard
redesign, no scoreboard / postmarket / North Star / audit work.

REQUIREMENTS

R1 — When `symbols_scanned` is an int `> 0` and lineage is coherent,
the `#opportunity-survival` block renders four counts: SURFACED =
`symbols_scanned - promoted`, QUALIFIED = `SURFACED - len(terminal
rejected) - len(watchlist)`, WATCHLIST = `len(watchlist)`, REJECTED =
`len(terminal rejected)`, where `promoted`/`terminal` are defined by R5.
For a scan with no promoted records these reduce to `symbols_scanned`,
`len(rejected)`, and `len(watchlist)` directly.
FAIL: a coherent payload with `meta.symbols_scanned = 12`, three
`sections.rejected` records (none promoted), and two `sections.watchlist`
records does not render SURFACED 12, QUALIFIED 7, WATCHLIST 2, and
REJECTED 3 in the `#opportunity-survival` block.

R2 — The `#opportunity-survival` block is entirely absent (no element
with that id anywhere in the output) when `symbols_scanned` is `0`,
missing, or non-int, OR when lineage is unhealthy
(`artifact_lineage_state in ("MIXED","STALE","MISSING")`).
FAIL: a payload with `meta.symbols_scanned = 0` renders an
`id="opportunity-survival"` element; OR an `artifact_mixed=True`
(mismatched `generation_id`s) run with `meta.symbols_scanned = 12`
renders an `id="opportunity-survival"` element.

R3 — When `rejected > 0`, exactly one PRIMARY REJECTION row renders,
its value equal to the most frequent `reason` among `sections.rejected`
(tie-break: highest count, then lexicographically smallest reason).
When `rejected == 0`, no PRIMARY REJECTION row renders.
FAIL: `sections.rejected` reasons `["CHOP","CHOP","EXTENDED_FROM_MEAN"]`
render a PRIMARY REJECTION value other than `CHOP`; OR a render with
zero `sections.rejected` records emits a PRIMARY REJECTION row.

R4 — The block reads only `payload.meta.symbols_scanned`,
`payload.sections.rejected`, and `payload.sections.watchlist`; it
introduces no new payload/contract field and emits no raw engine
internal token (`(regime=`, `confidence=`) into the output. All
rendered reason text passes through `_esc`. Engine-metadata stripping
per R7 makes the no-internals guarantee unconditional.
FAIL: the `#opportunity-survival` block references a payload field not
already produced by `cuttingboard/delivery/payload.py`; OR it emits a
`(regime=` or `confidence=` substring.

CORRECTION (Codex P2 findings on head `0a736e4`, PR #203) — three
in-scope findings, all confirmed against the code and actioned in one
consolidated correction pass. Same FILES; renderer-only; no schema,
contract, taxonomy, or CLI change.

R5 (F1) — A CONTINUATION-promoted symbol is not a terminal rejection.
PRD-260 R4 (`cuttingboard/qualification.py`) retains a promoted symbol's
DIRECT-path exclusion on the audit trail (reason rewritten to include
the marker `promoted via CONTINUATION`) AND counts it as qualified — so
it appears in both `qualified_count` and `excluded`, double-counting it
in `symbols_scanned` and seeding a non-terminal record in
`sections.rejected`. The block treats a `sections.rejected` record whose
`reason` contains the pipeline's own authoritative marker
`promoted via CONTINUATION` as `promoted` (not `terminal`): promoted
records are excluded from REJECTED and from the primary-reason tally, and
`promoted = count(promoted records)` is subtracted from SURFACED, so each
symbol is represented exactly once (the promoted one as qualified) and
QUALIFIED stays exact.
FAIL: a scan where NVDA is promoted (`symbols_scanned = 2`, one
`sections.rejected` record whose reason contains `promoted via
CONTINUATION`) does not render SURFACED 1 / QUALIFIED 1 / WATCHLIST 0 /
REJECTED 0; OR the promoted record's reason becomes the PRIMARY REJECTION.

R6 (F2) — Fail closed on malformed survival inputs. The block renders
only when lineage is coherent AND `symbols_scanned` is an `int` that is
not a `bool` and `> 0` AND `sections.rejected` and `sections.watchlist`
are both actual lists AND every `sections.rejected` record is a dict.
Any other shape suppresses the entire block — never a crash, a string's
length used as a count, `True` rendered as `1`, or a misleading partial
count. (The dashboard render path does not re-run `assert_valid_payload`,
so a corrupted/partial artifact can reach the block. No global payload
validation or CLI change is added.)
FAIL: `meta.symbols_scanned = True`, a non-list `sections.rejected`
(e.g. `"abc"`) or `sections.watchlist` (e.g. `5`), or a `sections.rejected`
list containing a non-dict element renders an `#opportunity-survival`
element (or raises).

R7 (F3) — The primary rejection text is sanitized before render by the
same policy the system-state WHY line already uses (`re.sub` stripping
`regime=` / `confidence=` suffixes, then dropping `None`/`NULL`
sentinels), then HTML-escaped via `_esc`. No second sanitization
taxonomy is introduced.
FAIL: a terminal rejection reason `bad (regime=RISK_ON, confidence=0.8)`
renders a PRIMARY REJECTION containing `regime=` or `confidence=`; OR the
sanitized text is not HTML-escaped.

DATA FLOW
`contract.audit_summary.{qualified_count, rejected_count}` +
`contract.rejections` -> `payload.py` collapses to
`meta.symbols_scanned` and splits `sections.rejected` /
`sections.watchlist` (unchanged) -> renderer reads
`meta.symbols_scanned`, `len(sections.rejected)`,
`len(sections.watchlist)` (all already at the renderer) -> new
`#opportunity-survival` block: four counts (R1) under the
symbols_scanned>0 + coherent-lineage gate (R2), plus the modal
`sections.rejected[].reason` as PRIMARY REJECTION when rejected>0 (R3).

FAIL CONDITIONS

condition for that requirement.
