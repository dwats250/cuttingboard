GOAL
Suppress the standalone RED FOLDER block only when the resolved red-folder view
is healthy, has zero events in the next 48h, and is not expiring — a display-only
change reading the existing resolved view.

- Guard the existing `id="red-folder"` block emission in `dashboard_renderer.py`
  with a pure predicate over the resolved-view keys `ok`/`events`/`expiring`;
  update only the tests whose current inputs render the now-suppressed state.

REQUIREMENTS
R1 — Suppress healthy-empty-non-expiring resolved view: when `red_folder` is a
dict with truthy `ok`, empty `events`, falsy `expiring`, `render_dashboard_html`
emits no red-folder block.
FAIL: a render with `{"ok":True,"error":None,"events":[],"expiring":False}`
contains `id="red-folder"`.
R2 — Preserve when events exist.
FAIL: a render with `ok` true and one event omits `id="red-folder"` or that
event's name.
R3 — Preserve on unhealthy/error view.
FAIL: a render with `{"ok":False,"error":"schedule file not found",...}` omits
`id="red-folder"` or `RED FOLDER UNAVAILABLE`.
R4 — Preserve on expiring, including empty-but-expiring.
FAIL: a render with `{"ok":True,"events":[],"expiring":True}` omits
`id="red-folder"` or `nearing expiry`.
R5 — Preserve the None/default path unchanged.
FAIL: a render with no `red_folder` argument omits `id="red-folder"` or `No
red-folder events in the next 48 hours.`, OR `test_gex_absent_baseline_identical`
is no longer byte-identical to the golden.
R6 — EVENT RISK and block order unaffected under suppression.
FAIL: for the R1 case, the MARKET STATE panel omits `no events in 48h`, OR
`html.index('id="trend-structure"')` is not greater than
`html.index('id="macro-tape"')`.
R7 — Coverage catalog reflects the removed rendered state.
FAIL: `red_folder_empty` remains in `SECTION_STATE_CASES` or
`_EXPECTED_CASE_NAMES`, or `test_catalog_covers_every_reachable_state` fails.
