PRD-278 — Hourly kill-switch bypass: evaluate before qualification, carry terminal HALT through hourly outputs

Status: IN PROGRESS

LANE
HIGH-RISK

CLASS
EXECUTION

WHY NOW
CB-01 (Critical, `audits/current-state-reconciliation-2026-07-30/FINDING_STATUS_MATRIX.md`): the hourly alert path never evaluates the existing kill switch and hardcodes `kill_switch: false`; DR-001 requires this fixed before CB-02 reaches Gate A. Design authorized by Dustin's 2026-08-03 ruling on the review-clean GOV-2 MATERIAL packet (`audits/current-state-reconciliation-2026-07-30/CB_01_HOURLY_KILL_SWITCH_MATERIAL_PACKET_2026-08-03.md`, merged PR #194). Translates that design into requirements; does not redesign.

MAX EXPECTED DELTA
~75 production lines in `cuttingboard/runtime/__init__.py`; ~100 test lines in `tests/test_hourly_alert.py`. No other file's logic changes.

GOAL
On a kill-switch trip, the hourly alert path halts before qualification, skips all downstream artifact work that could clobber that state, and reports `kill_switch`/`status`/`outcome`/`system_halted` consistently with the daily path's terminal HALT — instead of hardcoding `kill_switch: false` and `SUCCESS`/`NO_TRADE`.

SCOPE
- `_execute_notify_run`'s kill-switch trip flag, control-flow gating, escalation, and HALT-consistent output carriers, per R1–R7.

OUT OF SCOPE
- The daily pipeline (`_run_pipeline`, `_build_run_summary`, `execute_run`, `_failure_summary`) — unchanged.
- `_QUALIFY_ONLY_MODES` (`post_orb`, `power_hour`, `market_close`) — deferred by Dustin's ruling (Q2).
- Any dashboard, notification-formatter, or persisted-schema change.
- Any new kill-switch evaluator, threshold, or tri-state model — `_kill_switch`, `KILL_SWITCH_HALT_REASON`, `HaltCause.MARKET_STRESS` reused verbatim.
- The pre-existing data-validation-halt case's identical post-write-helper exposure (R7 scopes strictly to the kill-switch trip flag, not to `validation_summary.system_halted` generally — that broader robustness question is not CB-01's).

REQUIREMENTS

R1 — Trip flag always defined
`hourly_kill_switch = False` is initialized before the `try:` block in
`_execute_notify_run` (alongside `now_et`), not only inside the
`if not validation_summary.system_halted:` branch — so it is always defined
at both the success and failure `_build_hourly_run_summary`/
`_build_hourly_contract` call sites, including when `validation_summary`
is already halted on entry (regime is never computed in that case).

FAIL: `tests/test_hourly_alert.py::test_hourly_sends_exactly_once_system_halted`
raises `UnboundLocalError` or otherwise fails.

R2 — Kill-switch evaluation gates candidate generation and downstream work
When `notify_mode in _HOURLY_MODES` and `validation_summary.system_halted` is
false on entry, evaluate `_kill_switch(regime, normalized_quotes)`
immediately after computing `regime`. When true: neither
`_QUALIFY_ONLY_MODES` nor `_HOURLY_MODES` candidate branch executes, and none
of `compute_all_derived`, `resolve_sector_router`, `_load_flow()` is called.

FAIL: on a fixture with sustained VIX level > 35 (no matching single-interval
VIX-%-change spike > 0.15) and `regime.posture != "STAY_FLAT"` (pin
confidence >= `MIN_REGIME_CONFIDENCE`; a low-confidence fixture would already
be suppressed by the pre-existing `:426` posture gate regardless of this fix
and would not discriminate it), OR an `|SPY %change| > 0.03` fixture with the
same posture pin: `generate_candidates`/`qualify_all` is invoked, or any of
`compute_all_derived`/`resolve_sector_router`/`_load_flow` is called (proven
by monkeypatching each to raise and observing the run still succeeds).

R3 — Trip escalates validation state exactly as the daily path does
On a hourly trip, `validation_summary` is replaced via `replace()` (from
`dataclasses import replace`, `runtime/__init__.py:21`) with
`system_halted=True`, `halt_reason=KILL_SWITCH_HALT_REASON`,
`halt_cause=HaltCause.MARKET_STRESS`, reusing the daily path's constants.

FAIL: on the R2 fixture, `latest_hourly_run.json`'s `halt_reason` is not
exactly `KILL_SWITCH_HALT_REASON`, or `system_halted` is not `true`.

R4 — Terminal HALT carried through the hourly run summary
`_build_hourly_run_summary` reports `kill_switch=true`,
`status=SUMMARY_STATUS_FAIL`, `outcome=OUTCOME_HALT`,
`candidates_qualified=0`, `candidate_lines=[]` on a tripped run; on a clear
run it reports the real evaluated `kill_switch` (false) with
`status`/`outcome` unchanged from today.

FAIL: on the R2 fixture, `latest_hourly_run.json` has `kill_switch: false`,
`status` != `"FAIL"`, `outcome` != `"HALT"`, `candidates_qualified != 0`, or
non-empty `candidate_lines`.

R5 — Terminal HALT carried through the hourly contract, both hardcode sites
`_build_hourly_contract` passes the trip signal into BOTH its current
`OUTCOME_NO_TRADE` hardcodes: the `derive_run_status(...)` call's outcome
argument, and the `contract["outcome"] = ...` assignment. Note
`derive_run_status` returns `STATUS_STAY_FLAT` for any `system_halted=True`
input regardless of its outcome argument (`contract.py:205-206`), so the
serialized `contract["status"]` cannot reveal an unfixed `derive_run_status`
call site — a discriminating test must assert or spy the exact argument
passed into `derive_run_status`, not only the final `contract["outcome"]`.

FAIL: on the R2 fixture, `latest_hourly_contract.json`'s `outcome` != `"HALT"`,
OR a direct/spy test on `_build_hourly_contract` shows `derive_run_status`
still receiving `OUTCOME_NO_TRADE` on a tripped call.

R6 — Failure-before-evaluation reports kill_switch=true unconditionally
When `_execute_notify_run` raises before or during kill-switch evaluation,
the failure-path `_build_hourly_run_summary` call passes `kill_switch=True`
regardless of what `hourly_kill_switch` held at the point of the exception.

FAIL: on an exception raised before evaluation completes (e.g. `fetch_all`
raising), `latest_hourly_run.json`'s `kill_switch` is not `true`.

R7 — A recorded trip is not clobbered by a later downstream failure
`build_market_map`, `_load_previous_market_map`, `_write_market_map_file`,
and `_write_trend_structure_snapshot` (currently unconditional after
`_write_hourly_artifacts`, `runtime/__init__.py:537-561`) do not execute when
`hourly_kill_switch` is true — mirroring the existing
`if not validation_summary.system_halted:` skip already applied to
`_write_watchlist_snapshot` immediately below them. Without this, a raise in
any of the four (e.g. `_load_previous_market_map` on a malformed prior file)
routes to the generic exception handler, which re-invokes
`_write_hourly_artifacts` with a generic failure summary/contract and
overwrites the already-correctly-written R3/R4/R5 HALT state with a generic
`halt_reason` and a duplicate, differently-worded notification.

FAIL: on the R2 fixture with `_load_previous_market_map` monkeypatched to
raise, `send_notification` is called more than once, or the final
`latest_hourly_run.json`/`latest_hourly_contract.json` do not match R3/R4/R5
(e.g. `halt_reason` is not `KILL_SWITCH_HALT_REASON`).

DATA FLOW
`normalized_quotes` + `regime` -> `_kill_switch(...)` -> `hourly_kill_switch` (R1, R2)
`hourly_kill_switch=true` -> `validation_summary` escalation (R3) -> hourly summary/contract carriers (R4, R5) -> skip post-write helpers (R7)
`hourly_kill_switch=false` -> unchanged candidate generation -> qualification -> alert (unchanged)
exception before evaluation -> failure-path `kill_switch=True` (R6)

FAIL CONDITIONS
- `hourly_kill_switch` undefined at any call site (R1).
- Candidates/downstream helpers reached on a detected trip (R2).
- `halt_reason`/`system_halted` not escalated on a trip (R3).
- `kill_switch`/`status`/`outcome` not HALT-consistent on a tripped summary (R4).
- Either `_build_hourly_contract` hardcode site left un-derived from the trip signal (R5).
- Failure-path `kill_switch` != `true` (R6).
- A tripped run's recorded HALT state overwritten by a later helper failure (R7).
- Any named clear-state or daily-path regression test fails (below).

Clear-state/daily regression (no new test, must continue passing):
`tests/test_hourly_alert.py::test_hourly_candidate_line_uses_promoted_geometry_prd260_r7`;

`test_kill_switch_audit_record_carries_halt`.
