GOAL
When the correlation-adjusted contract quantity resolves below one in
`cuttingboard/options.py::build_option_setups`, refuse the setup with an
explicit, stably-tokened refusal record that reaches the contract, the
audit record, and the text report — never a floored one-contract position
and never a silent drop.

ROOT CAUSE
The floor originates in PRD-023 (commit 314ca46, 2026-04-26): the GLD-DXY
correlation layer applied its risk modifier with
`final_contracts = max(1, min(result.max_contracts, raw_adjusted))` under
an advisory-only "no removal" rationale ("AC4" — a label backed by no
acceptance criterion in PRD-023's text). PRD-157 preserved the floor while
migrating to equity-driven budgets; PRD-251 made the breach material by
correcting credit max loss to 70% of width ($350/contract on index ETFs);
PRD-256 R3 unified continuation into the same block. Result: a live
position-risk limit is silently exceeded (2.1875x at CONFLICT, 1.25x at
NEUTRAL, deterministically reproduced in the OPT-0 artifact section 3).
The 2026-07-24 ruling supersedes exactly the floor; PRD-023 R2's
qualification clause (correlation must not alter qualification outcomes)
is preserved by refusing at expression, not qualification.

REQUIREMENTS

R1 — Refusal replaces the floor
In `build_option_setups`, when `risk_per_contract > 0` and
`int(effective_risk // risk_per_contract) < 1`, no `OptionSetup` is
emitted for that result and the `max(1, ...)` floor no longer executes.
With live constants this refuses: index-ETF credit at CONFLICT ($350 vs
$160) and NEUTRAL ($350 vs $280), single-name credit at CONFLICT ($175 vs
$160).

FAIL: `build_option_setups` returns an `OptionSetup` with
`dollar_risk > ACCOUNT_EQUITY * MAX_RISK_PCT_PER_TRADE * risk_modifier`
for any input, or any emitted setup has `max_contracts` produced by a
floor rather than `min(result.max_contracts, raw_adjusted)`.

R2 — Explicit refusal record, never a silent drop
Every refusal appends exactly one `OptionRefusal` (symbol, strategy,
risk_per_contract, effective_risk, risk_modifier,
reason=`SMALLEST_CONTRACT_EXCEEDS_BUDGET`) to the caller-supplied
`refusals` list. The two pre-existing skip branches (missing
StructureResult, `max_contracts is None`) do NOT produce refusal records
and keep their current log-and-skip behavior.

FAIL: a refused symbol produces no `OptionRefusal`; or a missing-data skip
produces one; or the refusal reason is any string other than the exact
token `SMALLEST_CONTRACT_EXCEEDS_BUDGET`.

R3 — Contract representation
For each refusal, the pipeline contract's `rejections[]` contains an entry
`{symbol, stage: "OPTIONS_SIZING", reason:
"SMALLEST_CONTRACT_EXCEEDS_BUDGET", detail: <risk_per_contract, ceiling,
modifier, strategy>}`, and `assert_valid_contract` passes on the resulting
contract. The payload's existing WATCHLIST/rejected split places the entry
in `rejected`.

FAIL: the contract of a run with a refusal carries no `OPTIONS_SIZING`
rejection entry for the refused symbol, or contract validation raises, or
`build_report_payload` raises on the contract.

R4 — Audit representation
The audit record of a run with a refusal represents it explicitly (token +
the same economics as R3). A refused symbol does not appear as a
qualified-trades row whose `contracts`/`dollar_risk` are silently null
without the refusal being stated on the record.

FAIL: the audit record for a refusal run contains no occurrence of
`SMALLEST_CONTRACT_EXCEEDS_BUDGET`, or contains a qualified row for the
refused symbol with null sizing and no refusal statement.

R5 — Report representation
`render_report` output for a run with a refusal contains exactly one line
per refused symbol naming the symbol, the refusal, the one-contract cost,
and the adjusted ceiling. The refused symbol appears in neither the A+
TRADES nor the CHAIN UNVERIFIED block.

FAIL: the report body contains no refusal line for a refused symbol, or
renders the refused symbol as a trade card.

R6 — Direct and continuation parity
The refusal fires identically for `entry_mode` DIRECT and CONTINUATION
results with the same strategy/width/modifier inputs (the shared block is
the only sizing site; no entry_mode branch is introduced).

FAIL: two results differing only in `entry_mode` produce different
refusal/emission outcomes.

R7 — Positive sizing preserved value-for-value, one-contract boundary pinned
For every result with `raw_adjusted >= 1`:
`final_contracts = min(result.max_contracts, raw_adjusted)` and
`final_dollar_risk = round(final_contracts * risk_per_contract, 2)`,
identical to pre-change values. The one-contract boundary is pinned by
OPT-0 repro case 9: ALIGNED (1.0) index-ETF credit, $350 risk/contract vs
the $400.005 ceiling, `raw_adjusted = 1` -> emits exactly 1 contract at
$350.00. At ALIGNED, no refusal fires for a result Gate 8 qualified when
Gate 8 and options agree on max loss. The existing floor-adjacent tests in
`tests/test_phase5.py` (the :502, :521, :549, :578, :600, :942 groups)
stay green unmodified.

FAIL: any emitted setup's `max_contracts` or `dollar_risk` differs from
its pre-change value for `raw_adjusted >= 1`; or the case-9 boundary
fixture is refused (as it would be under an off-by-one `raw_adjusted <= 1`
refusal condition); or an ALIGNED-state qualified result is refused.

R8 — Outcome derivation
When every qualified candidate is refused, the run outcome is `NO_TRADE`
(no actionable decision exists) and the decision chain receives no setup
for refused symbols — `trade_decision`'s `contracts >= 1` validator is
never confronted with a refused candidate.

FAIL: a run whose sole qualified candidate is refused yields outcome
`TRADE`, or any `TradeDecision` is constructed for a refused symbol.

R9 — Token stability and distinctness
`SMALLEST_CONTRACT_EXCEEDS_BUDGET` is defined once as a module constant,
pinned by an exact-string test, and is distinct from
`size_rounds_to_zero` (which remains unimplemented and reserved for CB-03
policy-size materialization; it is not introduced by this PRD).

FAIL: the token literal appears with any variant spelling in production
code, or `size_rounds_to_zero` appears anywhere in this PRD's diff.

R10 — Postmarket representation
`build_postmarket_report` on a refusal-run contract exposes the refusal in
its rejection aggregation: `rejection_breakdown` carries the new stage and
the refused count; the key-set pin (`tests/test_postmarket_report.py:90-92`)
is updated and green.

FAIL: a refusal-run postmarket report's `rejection_breakdown` contains no
representation of the `OPTIONS_SIZING` refusal.

R11 — Notification body
When every qualified candidate is refused (zero `trade_candidates`), the
alert body produced by `build_notification_message` names the refusal (the
token or its plain-language form), not the generic `no setups` fallback.
Notification dedup state behavior is unchanged.

FAIL: an all-candidates-refused run's alert body reads `Reason: no setups`
(or any text with no trace of the refusal).

R12 — HTML delivery
`render_report_from_payload` renders the refusal from `sections.rejected`,
so `render_html` output for a refusal-run payload contains the refusal
text.

FAIL: the HTML page for a refusal-run payload contains no occurrence of
the refusal.

R13 — Mutation gate
Each of the following mutations, applied to the implemented code, turns at
least one of this PRD's tests red (run mechanically during implementation
review): (a) restore `max(1, min(result.max_contracts, raw_adjusted))`;
(b) add an `entry_mode == ENTRY_MODE_CONTINUATION` bypass around the
refusal; (c) replace the reason token with `None` or another string;
(d) refuse without appending the `OptionRefusal` (silent omission);
(e) compute the ceiling without `risk_modifier`; (f) write the refusal
condition as `raw_adjusted <= 1` (off-by-one; red via the R7 case-9
boundary); (g) render the refusal in the report but drop it from any one
of postmarket / notification body / HTML adapter (red via R10-R12).

FAIL: any of mutations (a)-(g) leaves the suite green.

DATA FLOW
config (ACCOUNT_EQUITY, MAX_RISK_PCT_PER_TRADE) x correlation
risk_modifier -> build_option_setups effective_risk -> raw_adjusted
-> [>= 1] min(result.max_contracts, raw_adjusted) -> OptionSetup ->
chain validation -> decisions -> contract/audit/report (unchanged)
-> [< 1]  OptionRefusal(SMALLEST_CONTRACT_EXCEEDS_BUDGET) -> runtime
refusals list -> contract rejections[] stage OPTIONS_SIZING + audit
record + one report line; no setup, no decision, no chain call.

FAIL CONDITIONS
- Any emitted OptionSetup whose dollar_risk exceeds the correlation-
  adjusted budget.
- Any refusal without an explicit OptionRefusal record (silent drop).
- Any refusal record without the exact token.
- Contract missing the OPTIONS_SIZING entry, or contract/payload
  validation raising on a refusal run.
- Audit record missing the refusal, or carrying a silent-null qualified
  row for a refused symbol.
- Report body missing the refusal line, or rendering a refused symbol as
  a trade.
- Postmarket rejection_breakdown missing the refusal on a refusal run.
- All-refused alert body reading generic `no setups`.
- Refusal-run HTML page missing the refusal text.
- Any entry_mode-dependent refusal asymmetry.
- Any value change in emitted setups for raw_adjusted >= 1; the case-9
  one-contract boundary refused (off-by-one); or any ALIGNED-state
  spurious refusal.
- Outcome TRADE on a run whose only candidates were refused.
- Any mutation (a)-(g) surviving the suite green.
