WHY NOW
CB-01 (Critical, `FINDING_STATUS_MATRIX.md`): hourly path never evaluates the kill switch, hardcodes `kill_switch: false`. DR-001 requires this fixed before CB-02 Gate A. Design from Dustin's 2026-08-03 ruling (`docs/DECISIONS.md`) on the review-clean CB-01 packet (`audits/current-state-reconciliation-2026-07-30/CB_01_HOURLY_KILL_SWITCH_MATERIAL_PACKET_2026-08-03.md`, PR #194); translates the ruling into requirements, does not redesign.

MAX EXPECTED DELTA
~90 production lines in `cuttingboard/runtime/__init__.py`; ~110 test lines in `tests/test_hourly_alert.py`. No other file's logic changes.

GOAL
On a kill-switch trip, the hourly path halts before qualification, publishes a coherent current-generation halted market map, survives auxiliary post-write failures without losing the recorded HALT, and reports `kill_switch`/`status`/`outcome`/`system_halted` consistently with the daily path's terminal HALT.

SCOPE
`_execute_notify_run`'s trip flag, control-flow gating, escalation, coherent halted-map publication, and post-write failure isolation — R1-R8.

OUT OF SCOPE
- Daily pipeline (`_run_pipeline`, `_build_run_summary`, `execute_run`, `_failure_summary`); `_QUALIFY_ONLY_MODES` (deferred, Dustin's ruling Q2); dashboard/notification-formatter/market-map-schema changes — none touched.
- New kill-switch evaluator/threshold/tri-state model — `_kill_switch`/`KILL_SWITCH_HALT_REASON`/`HaltCause.MARKET_STRESS` reused verbatim. No broad exception-handling refactor — R8 is two narrow, local guards only.

REQUIREMENTS

R1 — Trip flag always defined. `hourly_kill_switch = False` initialized before the `try:` block, not only inside `if not validation_summary.system_halted:`, so it is defined at every call site, including already-halted-on-entry.
FAIL: `test_hourly_sends_exactly_once_system_halted` raises or fails.

R2 — Kill-switch evaluation gates candidate generation and expensive work (the trip fixture: sustained VIX>35, no matching %-change spike, OR `|SPY %change|>0.03` — either with `regime.posture != "STAY_FLAT"` pinned via confidence >= `MIN_REGIME_CONFIDENCE`, so the pre-existing STAY_FLAT gate alone can't explain suppression). Evaluate `_kill_switch(regime, normalized_quotes)` immediately after `regime` is computed, only for `_HOURLY_MODES`. True: neither `_QUALIFY_ONLY_MODES` nor `_HOURLY_MODES` candidate branch runs; `compute_all_derived`/`resolve_sector_router`/`_load_flow()` not called.
FAIL: on the trip fixture, `generate_candidates`/`qualify_all` invoked, or any of the three helpers called.

R3 — Trip escalates validation state like the daily path: `replace(validation_summary, system_halted=True, halt_reason=KILL_SWITCH_HALT_REASON, halt_cause=HaltCause.MARKET_STRESS)`.
FAIL: on the trip fixture, `halt_reason` != `KILL_SWITCH_HALT_REASON` or `system_halted` != `true`.

R4 — Terminal HALT in the hourly run summary: `kill_switch=true`, `status=FAIL`, `outcome=HALT`, `candidates_qualified=0`, `candidate_lines=[]` on trip; unchanged on clear.
FAIL: on the trip fixture, any of the five differs.

R5 — Terminal HALT in the hourly contract, both hardcode sites. Trip signal reaches both `derive_run_status(...)`'s outcome argument and `contract["outcome"] = ...`. `derive_run_status` returns `STATUS_STAY_FLAT` for any `system_halted=True` input regardless of its outcome argument (`contract.py:205-206`), so a direct/spy test on the argument is required, not only the serialized outcome.
FAIL: on the trip fixture, contract `outcome` != `HALT`, or a spy shows `derive_run_status` still receiving `OUTCOME_NO_TRADE`.

R6 — Failure-before-evaluation reports kill_switch=true unconditionally: the failure-path `_build_hourly_run_summary` call passes `kill_switch=True` regardless of `hourly_kill_switch`'s value at the exception.
FAIL: on an exception before evaluation completes, `kill_switch` != `true`.

R7 — Coherent, current-generation halted market map. On trip, `build_market_map`/`_write_market_map_file`/`_write_trend_structure_snapshot` still run (not skipped) — they already tolerate the empty `derived`/`structure` and even `regime=None` that the existing validation-halted path exercises today; this trip's `regime` is non-`None`, strictly more complete. The existing, unconditional `hourly_market_map["generation_id"] = summary["generation_id"]` keeps market-map/run/payload generation IDs identical. `_load_previous_market_map`'s `RuntimeError` (malformed prior file) is caught locally and falls back to `previous_market_map=None` — the value `inject_lifecycle` already treats as "no previous map."
FAIL: on the trip fixture, `dashboard_renderer.validate_coherent_publish` raises `CoherentPublishError` for the written triple, or the map's `generation_id` != the run's.

R8 — A recorded HALT is not clobbered by a later auxiliary failure. The entire post-write auxiliary segment — `build_market_map` through the generation_id stamp, R7's previous-map fallback, `_write_market_map_file`, `_write_trend_structure_snapshot`, and the conditional `save_last_slot` — is wrapped in one narrow try/except (log + continue, not re-raise), so no exception in any of them (including `_write_market_map_file`'s own uncaught `write_text`/`mkdir`, not only the previous-map read) reaches the function's outer exception handler once R3-R5's HALT is already written. No second notification, no generic-failure overwrite; unaffected when the segment succeeds normally.
FAIL: on the trip fixture with any of `_load_previous_market_map`, `_write_market_map_file`, or `save_last_slot` raising, `send_notification` called more than once, or the final run/contract JSON don't match R3-R5.
