PRD-278 — Hourly kill-switch bypass: evaluate before qualification, carry terminal HALT through hourly outputs

Status: IN PROGRESS

LANE
HIGH-RISK

CLASS
EXECUTION

WHY NOW
CB-01 (Critical, `audits/current-state-reconciliation-2026-07-30/FINDING_STATUS_MATRIX.md`): the hourly alert path never evaluates the existing market-stress kill switch and hardcodes `kill_switch: false`; DR-001 requires this fixed before CB-02 reaches implementation Gate A. Design authorized by Dustin's 2026-08-03 ruling on the review-clean GOV-2 MATERIAL packet (`audits/current-state-reconciliation-2026-07-30/CB_01_HOURLY_KILL_SWITCH_MATERIAL_PACKET_2026-08-03.md`, merged PR #194). This PRD translates that already-reviewed design into requirements; it does not redesign.

MAX EXPECTED DELTA
~60 production lines in `cuttingboard/runtime/__init__.py` (one evaluation call, one early-exit restructure, one new parameter each on `_build_hourly_run_summary` and `_build_hourly_contract`, two call-site edits); ~80 test lines in `tests/test_hourly_alert.py`. No other file's logic changes.

GOAL
On a market-stress kill-switch trip, the hourly alert path halts before candidate qualification and reports `kill_switch`, `status`, `outcome`, and `system_halted` consistently with the daily path's terminal HALT, instead of hardcoding `kill_switch: false` and reporting `SUCCESS`/`NO_TRADE`.

SCOPE
- In `_execute_notify_run`, evaluate `_kill_switch(regime, normalized_quotes)` immediately after `regime = compute_regime(...)`, only when `notify_mode in _HOURLY_MODES`.
- On trip: early-exit before `compute_all_derived`, `resolve_sector_router`, and `_load_flow()` run, and before either candidate-generation branch (`_QUALIFY_ONLY_MODES` or `_HOURLY_MODES`) runs — restructure the existing `if not validation_summary.system_halted:` block so all of that sits in an `else:` keyed on the trip flag.
- On trip: escalate `validation_summary` via `replace(validation_summary, system_halted=True, halt_reason=KILL_SWITCH_HALT_REASON, halt_cause=HaltCause.MARKET_STRESS)` (the `dataclasses.replace` imported at `runtime/__init__.py:21`), reusing the existing daily-path pattern and constants verbatim.
- `_build_hourly_run_summary`'s success call site passes `status=SUMMARY_STATUS_FAIL` / `outcome=OUTCOME_HALT` on trip (currently hardcoded `status=SUMMARY_STATUS_SUCCESS, outcome=OUTCOME_NO_TRADE`).
- `_build_hourly_contract` gains the same trip signal as a new parameter, used at both its current `OUTCOME_NO_TRADE` hardcode sites (the `derive_run_status(...)` call and the `contract["outcome"] = OUTCOME_NO_TRADE` assignment).
- Add a `kill_switch: bool` parameter to `_build_hourly_run_summary`, replacing the hardcoded `"kill_switch": False` literal; success call site passes the real evaluated boolean.
- Failure/exception call site passes `kill_switch=True` unconditionally (Dustin's 2026-08-03 ruling: fail-safe, since the current Boolean schema has no UNKNOWN state and `False` on an incomplete evaluation is never contract-compliant).

OUT OF SCOPE
- The daily pipeline (`_run_pipeline`, `_build_run_summary`, `execute_run`, `_failure_summary`) — unchanged.
- `_QUALIFY_ONLY_MODES` (`post_orb`, `power_hour`, `market_close`) — deferred by Dustin's 2026-08-03 ruling (Q2), not part of this PRD.
- Any dashboard, notification-formatter, or persisted-schema change.
- Any new kill-switch evaluator, threshold, or tri-state model — `_kill_switch`, `KILL_SWITCH_HALT_REASON`, and `HaltCause.MARKET_STRESS` are reused verbatim.

REQUIREMENTS

R1 — Hourly kill-switch evaluation gates candidate generation
When `notify_mode in _HOURLY_MODES` and `validation_summary.system_halted` is
false on entry, `_execute_notify_run` evaluates `_kill_switch(regime,
normalized_quotes)` immediately after computing `regime`. When it returns
true, no candidates are generated or qualified for that run (neither the
`_QUALIFY_ONLY_MODES` nor `_HOURLY_MODES` branch executes), and none of
`compute_all_derived`, `resolve_sector_router`, or `_load_flow()` is called.

FAIL: on a fixture with sustained VIX level > 35 (no matching single-interval
VIX-%-change spike > 0.15) or `|SPY %change| > 0.03`, `generate_candidates`
or `qualify_all` is invoked, or any of `compute_all_derived`,
`resolve_sector_router`, `_load_flow` is called (proven by monkeypatching
each to raise and observing the run still succeeds without raising).

R2 — Trip escalates validation state exactly as the daily path does
On a hourly trip, `validation_summary` is replaced with `system_halted=True`,
`halt_reason=KILL_SWITCH_HALT_REASON`, `halt_cause=HaltCause.MARKET_STRESS`
via `replace()` (from `dataclasses import replace`), reusing the daily path's existing constants.

FAIL: on a tripped fixture, `latest_hourly_run.json`'s `halt_reason` is not
exactly `KILL_SWITCH_HALT_REASON`, or `system_halted` is not `true`.

R3 — Terminal HALT carried through the hourly run summary
`_build_hourly_run_summary` reports `kill_switch=true`,
`status=SUMMARY_STATUS_FAIL`, `outcome=OUTCOME_HALT`,
`candidates_qualified=0`, and `candidate_lines=[]` on a tripped run; on a
clear run it reports the real evaluated `kill_switch` value (false) with
`status=SUMMARY_STATUS_SUCCESS` / `outcome=OUTCOME_NO_TRADE` unchanged from
today.

FAIL: on a tripped fixture, `latest_hourly_run.json` has `kill_switch: false`,
or `status` is not `"FAIL"`, or `outcome` is not `"HALT"`, or
`candidates_qualified != 0`, or `candidate_lines` is non-empty.

R4 — Terminal HALT carried through the hourly contract
`_build_hourly_contract` reports `outcome=OUTCOME_HALT` at both of its
current `OUTCOME_NO_TRADE` hardcode sites (the `derive_run_status(...)` call
and the `contract["outcome"] = ...` assignment) on a tripped run; unchanged
(`OUTCOME_NO_TRADE`) on a clear run.

FAIL: on a tripped fixture, `latest_hourly_contract.json`'s `outcome` is not
`"HALT"`.

R5 — Failure-before-evaluation reports kill_switch=true unconditionally
When `_execute_notify_run` raises before or during kill-switch evaluation,
the failure-path `_build_hourly_run_summary` call passes `kill_switch=True`
regardless of what the trip flag held at the point of the exception.

FAIL: on an exception raised before kill-switch evaluation completes (e.g.
`fetch_all` raising), `latest_hourly_run.json`'s `kill_switch` is not `true`.

R6 — Clear-state and daily behavior unchanged
A non-tripped hourly run generates and qualifies candidates exactly as
before this PRD. The daily pipeline's kill-switch evaluation, escalation,
and summary reporting are untouched.

FAIL: `tests/test_hourly_alert.py::test_hourly_candidate_line_uses_promoted_geometry_prd260_r7`
fails, or any of `tests/test_runtime_decision.py::test_kill_switch_trip_forces_full_halt_escalation`,
`test_kill_switch_trip_skips_pipeline`,
`test_validation_halt_unchanged_when_kill_switch_not_tripped`,
`test_kill_switch_audit_record_carries_halt` fails.

DATA FLOW
`normalized_quotes` + `regime` -> `_kill_switch(regime, normalized_quotes)` -> trip flag
trip flag -> `validation_summary` escalation (R2) -> `_build_hourly_run_summary` / `_build_hourly_contract` (R3, R4)
trip flag=false -> unchanged candidate generation -> qualification -> Telegram alert (unchanged)
exception before evaluation -> failure-path `_build_hourly_run_summary(kill_switch=True, ...)` (R5)

FAIL CONDITIONS
- Candidates/downstream helpers reached on a detected trip (R1).
- `halt_reason`/`system_halted` not escalated on a trip (R2).
- `kill_switch`/`status`/`outcome` not HALT-consistent on a tripped summary (R3).
- Tripped contract `outcome` != `OUTCOME_HALT` (R4).
- Failure-path `kill_switch` != `true` (R5).
- Any named clear-state or daily-path test regresses (R6).
