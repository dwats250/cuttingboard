WHY NOW
`options.py::build_option_setups` sizes to one contract via
`final_contracts = max(1, min(result.max_contracts, raw_adjusted))` even when
`raw_adjusted == 0` — i.e. when a single contract's strategy max loss already
exceeds the correlation-adjusted per-trade budget
`ACCOUNT_EQUITY × MAX_RISK_PCT_PER_TRADE × risk_modifier`. The floor silently
substitutes a budget-violating position for the correct refusal, nullifying the
entire correlation risk reduction (PRD-198 invariant #1). Dustin ruled this
untradeable on 2026-07-24 (`docs/DECISIONS.md`, "Finding D RULED: the
one-contract floor may not breach the risk budget"): "A setup whose smallest
expressible position already exceeds the budget is correctly untradeable — the
right output is no trade, not a trade sized past the cap." That ruling required
"its own PRD with its own Gate A, including the downstream-consumer audit for
every reader of the sizing result." This is that PRD (the CB-02 restart).

WHY NOW — provenance
This restart supersedes the abandoned OPT-1/PRD-278 line. PR #184 (OPT-0
smallest-contract refusal seam trace + Late Connector Addendum) is the
preserved upstream MATERIAL packet and the authoritative evidence source. PR
#185 (closed/obsolete) and PR #193 (closed/superseded) do not carry authority.
PRD-278 was reused for unrelated work (hourly kill-switch bypass) and is NOT

GOAL
When the smallest expressible options contract exceeds the correlation-adjusted
per-trade risk budget, refuse the trade (emit no `OptionSetup`) and carry the
canonical refusal reason `SMALLEST_CONTRACT_EXCEEDS_BUDGET` (stage
`OPTIONS_SIZING`) through every consumer of the sizing result — contract, audit,
report body, notification, HTML delivery, postmarket, CLI, and dashboard —
without contradiction or silent replacement, while preserving all in-budget
sizing behavior value-for-value.

SCOPE
- Replace the `max(1, …)` floor in `build_option_setups` (`options.py:228–236`)
  with a refusal branch: when `risk_per_contract > 0` and
  `int(effective_risk // risk_per_contract) < 1`, emit no `OptionSetup` and
  record a refusal.
- Add a frozen `OptionRefusal` carrier dataclass in `options.py` plus module
  constants `OPTIONS_SIZING` and `SMALLEST_CONTRACT_EXCEEDS_BUDGET`; collect
  refusals via a NEW optional, list-return-preserving `refusals` out-parameter
  on `build_option_setups`.
- Thread the refusals from the single production call site
  (`runtime/__init__.py:1065`) into contract assembly and the audit record.
- Represent the refusal at every consumer that today drops it, contradicts it,
  or replaces it with a generic reason: contract `rejections[]` (new stage
  value), the audit record (new carrier field), the report body / notification
  body / HTML text adapter (`output.py`), the postmarket report
  (`reports/postmarket.py`), the CLI transport count line
  (`delivery/transport.py`), and the dashboard decision-state WHY line
  (`delivery/dashboard_renderer.py`).
- Preserve the distinction between refusal and the pre-existing missing-data
  and failed-computation branches.

OUT OF SCOPE
- Any change to `ACCOUNT_EQUITY`, `MAX_RISK_PCT_PER_TRADE`, regime multipliers,
  correlation modifier values, or any threshold.
- Any qualification-layer change: Gate 8 (`qualification.py`), the continuation
  sizer, and every rejection taxonomy are untouched (PRD-023 R2 preserved —
  the modifier still must not alter qualification gate outcomes; the candidate
  still qualifies, only expression refuses).
- CB-03 (`size_rounds_to_zero` / execution-policy `size_multiplier`
  materialization), CB-01, CB-04, and every other finding — no bundling.
- `reports/premarket.py`: a refused symbol produces no `OptionSetup` → no
  `TradeDecision` → it is provably absent from `contract["trade_candidates"]`
  (which `_build_trade_candidates` builds by iterating `trade_decisions`).
  Premarket reads only `trade_candidates[:5]`, carries no reason field, and
  therefore neither lists the refused symbol as a focus nor states a false
  reason. No contradiction and no silent replacement → retained-with-reason, no
  edit. (Reduction within the Gate-A ceiling per GOV-2 §5.)
- `delivery/payload.py`: its rejection split (`stage == "WATCHLIST"` vs the
  rest) is additive-tolerant, so an `OPTIONS_SIZING` contract rejection flows
  into `sections["rejected"]` with no code change. No edit.
- `delivery/html_renderer.py`: delegates wholesale to
  `output.py::render_report_from_payload`; fixing that adapter fixes the page.
  No edit.
- `runtime/_types.py`: avoided by threading `options_refusals` as a keyword
  argument to `build_pipeline_output_contract`, not as a
  `_PartialPipelineResult` field. If typing later forces the field in, that is a
  FILES amendment, not a silent expansion.
- The `risk_per_contract <= 0` else-branch (`options.py:234–235`): a distinct
  FAILED-COMPUTATION shape (defensively dead for all four strategies), currently
  a silent passthrough. Retained-with-reason, unchanged; a fail-loud treatment
  is a separate micro-scope.

  `build_notification_message` (generic "no setups"),

- Hidden sibling / post-write consumers: PRD-282 Opportunity Survival Summary
  auto-consumes the refusal via the additive payload split (its counts must
  still reconcile); the `trade_decision` validator (`contracts >= 1`) and
  `chain_validation` never see a refused symbol (no setup → no decision).

REQUIREMENTS

R1 — Refuse at the smallest-contract seam
`build_option_setups` must, for each qualified result, when
`risk_per_contract > 0` and `int(effective_risk // risk_per_contract) < 1`,
emit NO `OptionSetup` for that symbol and instead append an `OptionRefusal`
record to the `refusals` out-parameter list when one was supplied. The
`max(1, …)` floor is removed. For `raw_adjusted >= 1`, the emitted
`max_contracts` and `dollar_risk` are value-for-value identical to today
(`min(result.max_contracts, raw_adjusted)`), and the `risk_per_contract <= 0`
branch is unchanged.

FAIL: With live constants and a credit index-ETF result under CONFLICT
(risk_modifier 0.4, ceiling $160, risk_per_contract $350),
`build_option_setups([result], sr, dm, refusals=refs)` returns a setup for that
symbol (instead of no setup with `refs` carrying one `OptionRefusal`).

R2 — Canonical reason token and stage, distinct from missing data and CB-03
The refusal reason string is exactly `SMALLEST_CONTRACT_EXCEEDS_BUDGET` and the
stage is exactly `OPTIONS_SIZING`, defined as module constants in `options.py`.
The `OptionRefusal` carrier records at least: symbol, strategy,
`risk_per_contract`, the adjusted budget/ceiling, `risk_modifier`, stage, and
reason. The missing-data skip branches (`sr is None`;
`result.max_contracts is None or result.dollar_risk is None`) and the
`risk_per_contract <= 0` branch never emit this token.

FAIL: A refusal record carries a reason other than the exact literal
`SMALLEST_CONTRACT_EXCEEDS_BUDGET`, or a missing-data / `risk_per_contract <= 0`
skip produces an `OptionRefusal` / `OPTIONS_SIZING` entry.

R3 — Contract carries the refusal as a new rejection stage
The refusals collected at the call site are threaded into contract assembly so
`contract["rejections"]` contains one entry per refusal with
`stage == "OPTIONS_SIZING"`, `symbol == <refused symbol>`, and
`reason == "SMALLEST_CONTRACT_EXCEEDS_BUDGET"`, using the existing
`{symbol,stage,reason,detail}` dict shape (no new contract key).
`assert_valid_contract` still passes.

FAIL: A run with a refused sole candidate produces a contract whose
`rejections` list contains no entry with `stage == "OPTIONS_SIZING"`, or
`build_pipeline_output_contract` raises on the threaded refusals.

R4 — Audit record carries an explicit refusal, never a silent-None row
`write_audit_record` / `_build_record` receive the refusals and record them in a
new dedicated audit carrier field containing symbol, strategy,
`risk_per_contract`, adjusted budget, `risk_modifier`, stage, and reason. A
refused symbol must NOT be emitted as a qualified-trade row with silently-None
`strategy/dte/contracts/dollar_risk`; the refusal is affirmatively represented.
No existing audit field is repurposed with false semantics.

FAIL: An audit record for a refused-sole-candidate run either (a) contains a
`qualified_trades[]` row for the refused symbol with `contracts == None` and no
refusal representation, or (b) omits the refusal entirely.

R5 — Report body, notification, and HTML surface the refusal without contradiction
On an all-candidates-refused run: (a) `render_report` names the refusal in the
report body and does NOT emit the generic "no qualifying setups" line as the
cause; (b) the notification body (`_alert_reason` / the no-candidates branch of
`build_notification_message`) names the refusal instead of generic "no setups";
(c) `render_report_from_payload` (and therefore `render_html`) renders the
refusal from `sections["rejected"]` rather than dropping it.

FAIL: An all-refused run yields a report body containing "no qualifying setups"
(or a notification body reading "Reason: no setups") with no mention of the
sizing refusal, or an HTML render whose body omits the refusal present in
`sections["rejected"]`.

R6 — Postmarket counts and breakdown include options-sizing refusals
`build_postmarket_report` adds an `options_sizing` key to `rejection_breakdown`
counting `OPTIONS_SIZING`-stage rejections, and `trade_summary.rejected_count`
includes options-sizing refusals (it may not remain zero while the breakdown
reports a sizing refusal).

FAIL: A postmarket report built from a contract carrying one `OPTIONS_SIZING`
rejection reports `rejection_breakdown` without an `options_sizing` count of 1,
or reports `rejected_count == 0`.

R7 — CLI and dashboard do not contradict the refusal
(a) `deliver_cli` surfaces the options-sizing refusal reason (its token or a
stable plain-language form), not only a bare count. (b) The dashboard
decision-state WHY line (`dashboard_renderer.py`) does not render "no qualified
setups" when an `OPTIONS_SIZING` refusal occurred; the WHY line and the PRD-282
Opportunity Survival Summary agree, and the survival counts still reconcile.

FAIL: On an all-refused run, CLI output shows only a rejected count with no
reason token/text, OR the dashboard WHY line reads "no qualified setups" while
the survival summary counts the refusal as REJECTED.

R8 — Positive-sizing behavior preserved value-for-value
For every result with `raw_adjusted >= 1` (including the exactly-one-contract
in-budget boundary: ALIGNED credit ETF, $350 risk/contract vs $400.005 ceiling,
`raw_adjusted = 1`), the emitted `max_contracts`, `dollar_risk`, strategy, DTE,
and strikes are byte/value-identical to pre-change. Qualification outcomes,
watchlist membership, excluded counts, correlation computation, and the
advisory `correlation` contract block are unchanged.

FAIL: The one-contract in-budget boundary case is refused (proving the
predicate was written `<= 1` instead of `< 1`), or any `raw_adjusted >= 1` case
changes its emitted `max_contracts` / `dollar_risk`.

DATA FLOW
config.ACCOUNT_EQUITY, config.MAX_RISK_PCT_PER_TRADE, risk_modifier
  -> options.py:228 effective_risk = EQUITY × PCT × risk_modifier
  -> options.py:229-232 risk_per_contract, raw_adjusted
  -> [raw_adjusted < 1 & risk_per_contract > 0] REFUSE: OptionRefusal -> refusals[]
     [else] OptionSetup (unchanged sizing)
refusals[] (runtime/__init__.py:1065 call site)
  -> _build_and_finalize_contract -> build_pipeline_output_contract(..., options_refusals=refusals)
       -> contract.py::_build_rejections -> contract["rejections"] (stage OPTIONS_SIZING)
          -> delivery/payload.py split (additive) -> sections["rejected"]
             -> output.py::render_report_from_payload / render_html
             -> delivery/dashboard_renderer.py survival summary + WHY line
             -> delivery/transport.py::deliver_cli
          -> reports/postmarket.py rejection_breakdown + rejected_count
       -> output.py::render_report / _alert_reason / build_notification_message
  -> audit.py::write_audit_record -> _build_record -> audit refusal carrier field

- (R8) The one-contract in-budget boundary is refused, or any in-budget case's
