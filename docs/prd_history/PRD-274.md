WHY NOW
PRD-273's 8ca1969 removed the only assertions that ruff's RESOLVED rule set matches the DECLARED select in pyproject.toml (the two stdout checks: E402 present, line-too-long absent). test_lint_select_is_historical_set covers the declaration only. BINDING SCOPE NOTE (2026-07-31, connector review of PR #174 — verified)
Restoring the two removed probes is NOT sufficient and must not be this PRD's
requirement. Those probes only established that E402 was enabled and E501 was
disabled; they never proved the resolved set equals the declared
`['E4', 'E7', 'E9', 'F']`. A resolved configuration missing the E7, E9, or F
families entirely — or carrying unrelated extra families while E501 stays off —
satisfies both probes. Restoring them would let this PRD close while the
declaration-to-resolution agreement it exists to prove remains unproved, which
is the same declared-vs-resolved gap in a new costume (PRD-198 invariant 2).

The requirement must therefore compare the COMPLETE resolved rule set against
the expansion of the declared `select`, not spot-check representative rules.
`ruff rule --all` / `ruff check --show-settings` style output is the resolved
source; the declaration is `pyproject.toml`'s `lint.select`. A FAIL line that
passes when a whole declared family is missing is not an acceptable FAIL line.

MAX EXPECTED DELTA
`tests/test_prd273_lint_baseline.py` <= 70 net lines (one new test + two helpers). Zero production-code lines; `pyproject.toml` untouched; the ruff pin stays `0.15.22`.

GOAL
Add one deterministic test that proves the COMPLETE set of rules the pinned ruff RESOLVES for this repository equals the COMPLETE expansion of the DECLARED `[tool.ruff.lint].select = ["E4", "E7", "E9", "F"]`, so a resolved configuration missing a whole declared family, or carrying an undeclared family, turns the suite RED (PRD-198 invariant 2: assert the resolved, not the requested).

SCOPE
- New test `test_resolved_rule_set_equals_declared_expansion` in `tests/test_prd273_lint_baseline.py` using the existing `_ruff(...)` helper (the pinned interpreter's ruff, never a bare PATH ruff).
- RESOLVED source: `ruff check --show-settings <one tracked .py file>` stdout; parse the block `linter.rules.enabled = [ ... ]` and collect every `(CODE)` token (regex `\(([A-Z]+\d+)\)` inside that block). Verified 2026-09-18 on ruff 0.15.22: 59 codes.
- DECLARED source: `pyproject.toml` `[tool.ruff.lint].select` read with `tomllib`, expanded against the catalog from `ruff rule --all --output-format json` using ruff's own selector semantics: a selector `E4`/`E7`/`E9` matches catalog entries with `linter == "pycodestyle"` whose `code` starts with the selector; `F` matches entries with `linter == "Pyflakes"`; only entries whose `status` object carries the key `Stable` count (preview is off; `Removed` codes such as E999 are excluded). Verified 2026-09-18: 59 codes, set-equal to RESOLVED. The linter-name mapping is read from `ruff linter --output-format json` (pycodestyle categories E/W; Pyflakes prefix F), not hard-coded, so an unrelated linter whose codes merely start with "F" (FA, FAST, FBT, FIX) is never counted.
- Assertion: `resolved == declared` with the symmetric difference in the failure message.
- Bookkeeping per convention (registry row stays IN PROGRESS until the implementation PR; same-PR closeout).

OUT OF SCOPE
- Changing `select`, the ruff pin, or any lint rule; fixing lint findings; the existing PRD-273 tests (`test_exactly_one_exact_ruff_pin`, `test_lint_select_is_historical_set`, `test_ruff_resolves_root_config`, `test_ruff_check_passes`) stay unmodified.

REQUIREMENTS

R1 — Complete resolved set equals complete declared expansion.
The test computes RESOLVED and DECLARED exactly as defined in SCOPE and asserts set equality.
FAIL: the assertion is absent, compares subsets or representative codes only, or passes when RESOLVED != DECLARED.

R2 — Missing declared family turns RED.
Removing the entire E7 (or E9, or F) family from RESOLVED (simulated by monkeypatching the parsed RESOLVED set, or by a temporary `select` without that family in a copied config) makes the test fail with the missing codes named.
FAIL: the test stays GREEN with a whole declared family absent from RESOLVED. (Verified discriminating 2026-09-18: dropping E7 yields a 15-code difference.)

R3 — Undeclared extra family turns RED.
Adding the stable pycodestyle `W` family to RESOLVED makes the test fail with the extra codes named.
FAIL: the test stays GREEN with an undeclared family present in RESOLVED.

R4 — Resolved source is ruff's own output, not a re-implementation.
RESOLVED is parsed from `ruff check --show-settings` stdout of the pinned ruff; DECLARED expansion uses `ruff rule --all --output-format json` and `ruff linter --output-format json` from the same binary; no hand-maintained code list exists in the test.
FAIL: the test contains a literal list of rule codes, or invokes a ruff other than the one `_ruff()` resolves.

R5 — Version-format coupling bounded.
The parser depends only on the `linter.rules.enabled = [` header, the `(CODE)` suffix per entry, the JSON fields `code`, `linter`, `status`, and the `Stable` status key. If ruff's pin ever moves and any of these change, the test must fail loud (parse yields an empty RESOLVED or DECLARED set -> assertion error naming the empty side), never pass vacuously.
FAIL: an empty RESOLVED or DECLARED set does not fail the test.

DATA FLOW
pyproject.toml lint.select -> tomllib -> selectors -> [ruff rule --all json + ruff linter json] -> DECLARED code set; one tracked .py -> ruff check --show-settings -> linter.rules.enabled block -> RESOLVED code set; assert RESOLVED == DECLARED.

FAIL CONDITIONS
- Any R1-R5 FAIL line; any production-code line changed; ruff pin changed; existing PRD-273 tests edited.
