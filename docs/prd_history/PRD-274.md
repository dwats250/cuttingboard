Restoring the two removed probes is NOT sufficient and must not be this PRD's
requirement. Those probes only established that E402 was enabled and E501 was
disabled; they never proved the resolved set equals the declared
`['E4', 'E7', 'E9', 'F']`. A resolved configuration missing the E7, E9, or F
families entirely — or carrying unrelated extra families while E501 stays off —
satisfies both probes. Restoring them would let this PRD close while the
declaration-to-resolution agreement it exists to prove remains unproved, which
is the same declared-vs-resolved gap in a new costume (PRD-198 invariant 2).

The requirement must therefore compare the COMPLETE resolved rule set against
the expansion of the declared `select`, not spot-check representative rules.
`ruff rule --all` / `ruff check --show-settings` style output is the resolved
source; the declaration is `pyproject.toml`'s `lint.select`. A FAIL line that
passes when a whole declared family is missing is not an acceptable FAIL line.

REQUIREMENTS

R1 — Complete resolved set equals complete declared expansion.
The test computes RESOLVED and DECLARED exactly as defined in SCOPE and asserts set equality.
FAIL: the assertion is absent, compares subsets or representative codes only, or passes when RESOLVED != DECLARED.

R2 — Missing declared family turns RED.
Removing the entire E7 (or E9, or F) family from RESOLVED (simulated by monkeypatching the parsed RESOLVED set, or by a temporary `select` without that family in a copied config) makes the test fail with the missing codes named.
FAIL: the test stays GREEN with a whole declared family absent from RESOLVED. (Verified discriminating 2026-09-18 on ruff 0.15.22: dropping E7 yields a 13-code difference; the stable expansion is E4=2, E7=13, E9=1, F=43.)

R3 — Undeclared extra family turns RED.
Adding the stable pycodestyle `W` family to RESOLVED makes the test fail with the extra codes named.
FAIL: the test stays GREEN with an undeclared family present in RESOLVED.

R4 — Resolved source is ruff's own output, not a re-implementation.
RESOLVED is parsed from `ruff check --show-settings` stdout of the pinned ruff; DECLARED expansion uses `ruff rule --all --output-format json` and `ruff linter --output-format json` from the same binary; no hand-maintained code list exists in the test.
FAIL: the test contains a literal list of rule codes, or invokes a ruff other than the one `_ruff()` resolves.

R5 — Version-format coupling bounded.
The parser depends only on: the `linter.rules.enabled = [` header and its closing `]` delimiter with one `(CODE)` suffix per entry in `--show-settings` output; the rule-catalog JSON fields `code`, `linter`, and `status` (a dict whose key `Stable` marks a stable rule; `Removed` codes such as E999 are excluded); and the linter-catalog JSON fields `name`, `prefix`, and nested `categories[].prefix` (pycodestyle exposes E and W as categories; Pyflakes exposes top-level prefix F). A missing or malformed mapping (a selector whose linter cannot be resolved, or an empty catalog) must fail loud. If ruff's pin ever moves and any of these change, the test must fail loud (parse yields an empty RESOLVED or DECLARED set -> assertion error naming the empty side), never pass vacuously.
FAIL: an empty RESOLVED or DECLARED set does not fail the test.
