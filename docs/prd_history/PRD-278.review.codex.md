FINDINGS (verbatim from the connector's PR review comments):

1. **P1 — Publish the halted map before saving the slot**
   (`cuttingboard/runtime/__init__.py:560`)
   "When a tripped live hourly run has `slot_utc` and `save_last_slot`
   raises, control jumps directly to this block's catch before
   `build_market_map` runs. The new run and payload have already been
   published with the current generation ID, but the hourly market map
   remains stale or absent, so `validate_coherent_publish` cannot
   accept the required current-generation triple. Move slot
   persistence after the market-map publication or isolate it
   separately; the added slot-failure test currently misses this
   because it only checks the run and contract."

2. **P1 — Keep trend snapshot work inside the post-write guard**
   (`cuttingboard/runtime/__init__.py:601`)
   "On a kill-switch HALT, `_collect_trend_structure_history(ohlcv)` is
   evaluated outside the new auxiliary `try`, so any `fetch_ohlcv`
   failure propagates to the outer handler; `_write_trend_structure_
   snapshot` can likewise propagate if its `LOGS_DIR.mkdir` fails
   before its internal `try`. Either post-write failure occurs after
   the terminal artifacts and first notification, causing a second
   failure notification and overwriting the recorded HALT with a
   generic failure, contrary to R8. Include both history collection
   and the snapshot call in the post-write isolation."

DISPOSITION (PRD-228 triage; one correction pass, per Dustin's Gate A
authorization "request one bounded Codex review ... one correction
pass maximum"):

- Finding 1 — ACTIONED. Reordered the auxiliary block in
  `_execute_notify_run` so `build_market_map` /
  `_write_market_map_file` run before slot persistence is attempted;
  `save_last_slot` is now the last statement inside the same try, so a
  failure there can no longer prevent the coherent current-generation
  map from publishing, and is still swallowed by the existing except
  (no second notification, no HALT overwrite). Verified with a
  strengthened `test_prd278_slot_persistence_failure_preserves_halt`
  asserting `market_map["generation_id"] == hourly_run["generation_id"]`
  under a `save_last_slot` `OSError`; mutation-confirmed red against
  the pre-correction ordering, green after.

- Finding 2 — ACTIONED, adapted to two static-source constraints the
  connector could not see, both outside PRD-278's FILES and not
  touched: `tests/test_watchlist_sidecar.py::
  test_runtime_call_site_has_explicit_halt_guard` requires the line
  immediately after `_write_trend_structure_snapshot(...)`'s closing
  `)` to be exactly `if not validation_summary.system_halted:` (so
  that call cannot sit inside a `try` whose `except` would land
  between it and the guard), and
  `tests/test_runtime_trend_structure_refresh.py::
  test_prd174_execute_notify_run_wires_trend_history_helper` requires
  the literal source substring
  `history_by_symbol=_collect_trend_structure_history(ohlcv)` inside
  `_execute_notify_run` (so the call site's argument cannot be
  pre-computed into a variable either). Given both, the call site is
  left exactly as it was; instead `_collect_trend_structure_history`
  itself (within PRD-278's FILES) was made self-protecting, per-symbol,
  consistent with its own already-documented contract ("a symbol whose

  caught and treated identically to a `None` return, logged, and
  skipped, rather than propagated. `LOGS_DIR.mkdir(...)` inside
  `_write_trend_structure_snapshot` itself was moved inside that
  function's own existing try/except. Both are narrow, local guards
  consistent with R8's intent (no post-write auxiliary exception may
  reach the outer handler), not a broadened exception-handling
  refactor. Verified with a new
  `test_prd278_trend_history_collection_failure_preserves_halt`

  pre-correction code (asserted `result["status"] == "FAIL"` where the
