## REQUIRED findings

**REQ-1. The `+N in ladder` overflow marker overprints the outermost surviving rail label (R10 invariant (a); D-3 "honest placement").**
Claim: `_place_rail` clamps survivors to the frame edge (`edge_lim = top | bottom`, `cuttingboard/delivery/setup_chart.py:451`) and re-stacks inward, but reserves no pitch for the marker; `_render_levels_layer` then draws the marker at that same edge (`ey = 2.0 + half` / `height - 14 - half`, `setup_chart.py:489`). Whenever a side overflows, the marker and the outermost survivor share the edge slot.
Evidence (adversarial script, height 232, default SPY inputs): `forced_overflow_above` (the PRD's own T8 case): marker at y=8.0 vs `VWAP 104.5` at y=16.3, gap 8.3 (< 12 pitch); `forced_overflow_below`: `EMA21 99.4` at 202.1 vs marker at 212.0, gap 9.9; sixteen-level cluster: marker at 8.0 vs `0.618 102.5` at 8.7, gap 0.7 (drawn on top of each other). The committed T8 test (`tests/test_setup_chart.py:500-545`) cannot see this because `_rail_items` matches `class="lvl-label" x="286"` and the marker's class is `lvl-label lvl-more`, so the marker is excluded from the overlap, frame and NOW checks.
Smallest fix (net 0 production LOC, stays under 185): compute `edge_lim` inside the `while True:` loop as `(top if side == "above" else bottom) + sign * (_LEVELS_PITCH if dropped[side] else 0)` and delete the pre-loop assignment at :451, so a side that will carry a marker stacks its survivors one pitch inside the edge. Test side (net 0 test LOC, stays under 520): include marker y values in the `ys` list used for the (a)/(b)/(d) assertions (a second `re.findall` on `lvl-more" x="286" y="..."` folded into the existing `ys = sorted(...)` line), leaving the `<= 11` chars / price-suffix assertion on plain labels only.

**REQ-2. R12's "patched control map yields a second independent control whose selector shape targets only the probe segments" is not implemented or tested; Helm disposition needed.**
Claim: R12 requires the probe test to monkeypatch BOTH maps and assert a second control appears from the patched `_LAYER_CONTROLS`. The shipped test (`tests/test_setup_chart.py:547`) patches only `_LAYER_RENDERERS`; the renderer reads the control map by literal key (`_LAYER_CONTROLS["levels"]`, `dashboard_renderer.py:2521`), passes the literal `layers=("levels",)` (`:2517`), and the display selector is a literal (`#spy-levels:checked~.spy-chart .chart-layer[data-layer="levels"]`, `:1137`). A patched control map therefore yields nothing; the renderer-side seam is inert. This cannot be fixed by iterating the map without breaking R3's own AST pin (`test_prd329_spy_session_source_cone`, `tests/test_dashboard_renderer.py:5686-5704`, requires the literal tuple) and without LOC headroom (184/185).
Shipped behaviour is otherwise correct (exactly one control, no dead UI, no astrology string; verified). Smallest fix: a Helm ruling either (a) waiving the second-control clause by recording in PRD-330 R12 that the renderer keys the control by the literal `levels` entry under R3's AST pin (one-row PRD amendment, no code), or (b) authorizing the seam (map iteration plus a selector per control, roughly +4 net LOC and an R3 pin rewrite), which would require re-entering GOV-2 sec5 on the ceiling. I recommend (a).
