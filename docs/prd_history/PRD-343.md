WHY NOW
On 2026-09-15 nine hourly dispatches delivered normal Telegram alerts and then
had their publication refused by the R5 authority guard, so the operational
channel looked alive while the served board was frozen all day; the ordinary
send sits two steps before the carrier whose admissibility decides publication.

MAX EXPECTED DELTA
Production: <= 45 net LOC in `cuttingboard/runtime/__init__.py` and <= 6 LOC in
`.github/workflows/hourly_alert.yml` (ESTIMATED SURFACE -- NOT YET APPROVED;
Gate A sets the binding ceiling). Tests: <= 300 net LOC across the four test
files in FILES. Exceeding either bound STOPS implementation and reopens the
PRD for amendment and re-review per the CLASS matrix.

GOAL
Make the user-facing ordinary hourly alert and successful hourly publication
agree on authority admissibility, by evaluating the same canonical admission
rules read-only before the ordinary send and routing an inadmissible run into
the existing hourly failure path instead.

ROOT CAUSE
`_execute_notify_run` sends the ordinary Telegram at runtime/__init__.py:711
and only computes the EffectivePermission carrier at :755-761 (via
`_load_accepted_authority`, :1241-1257). On 2026-09-15 no same-day daily
carrier existed on `publish`, so `admit_persisted` rejected the restored
09-14 envelope as prior-session (effective_permission.py:224-225), the carrier
became the UNAVAILABLE sentinel (:91-98), and the publisher's
`publication_admits` refused it (`_valid_canonical`, :189-215) after the
alert had already been delivered. Admissibility was tested only in
`tools/ci_push_artifacts.sh::authority_guard` (:70-110).

REQUIREMENTS

R1 — Frozen workflow session
`hourly_alert.yml` exports `CB_WORKFLOW_SESSION` (UTC `%F`) once, in a step
that runs before "Run hourly alert" and is visible to every later step. The
runner pre-flight reads it as `admit_session`; `tools/ci_push_artifacts.sh`
consumes it unchanged via its existing `PUBLISH_SESSION` override (:40).
When the variable is absent (direct in-process callers, tests) the pre-flight
falls back to `run_date.isoformat()`.

FAIL: `tests/test_ci_artifact_hygiene.py` finds no `CB_WORKFLOW_SESSION`
export in `hourly_alert.yml` positioned before the "Run hourly alert" step;

from `CB_WORKFLOW_SESSION`.

R2 — Accepted-tip restore
The hourly restore list (`hourly_alert.yml:127`) includes
`logs/latest_hourly_contract.json`. It remains in the hourly commit

FAIL: the hygiene test that enumerates the hourly `ci_restore_publish_state.sh`

R3 — Read-only pre-flight carrier
Immediately before the ordinary send, and only when `mode == MODE_LIVE and
notify_mode in _HOURLY_MODES`, `_execute_notify_run` computes
`_preflight_now = datetime.now(timezone.utc)`,
`_pf_acc = _load_accepted_authority(date_str, _preflight_now)`, and
`_pf_ep = ep_authority.carry_forward(...)` with the same observed flags the
persisted block uses, else `ep_authority.unavailable(date_str)`. Nothing is
persisted, written, or mutated by this computation. The persisted carrier
block (:754-764) and the artifact clock (:715) are byte-for-byte unchanged.

FAIL: `git diff` of the implementation touches any line in the :714-764
range of the pre-PRD file, or moves `run_at_utc`; or test H (R8) shows the
persisted envelope differing from the pre-PRD runtime's at the same clocks;
or M6/M7 stay GREEN.

R4 — Canonical admission, no fork
Admissibility is exactly
`ep_authority.publication_admits(accepted, incoming) and
ep_authority.admit_persisted(incoming, current_session_date=admit_session,
now=None) is not None`, where `accepted =
ep_authority._read_authority(str(LATEST_HOURLY_CONTRACT_PATH))` and
`incoming = _pf_ep.to_envelope()`. No other predicate, reimplementation,
wrapper with altered semantics, or additional authority module is
introduced. `now=None` mirrors the Slice-2 CLI (`authority_projection._cli`,
:267-271).

FAIL: the implementation calls any admission predicate other than these two
functions, passes a `now` other than `None` to `admit_persisted`, or defines
a new function that compares `authority_version` fields.

R5 — Refusal enters the existing failure path before any ordinary send
If not admissible, `_execute_notify_run` raises
`HourlyPublicationInadmissible` (a module-level `Exception` subclass) BEFORE
`send_notification` is called. The existing except branch (:919-972) handles
it unchanged: `format_failure_notification(notify_mode, date_str,
str(exc)[:120])` (:924), one `send_notification` attempt, `traceback.txt`,
`build_error_contract` with `OUTCOME_HALT`, FAIL summary via
`_write_hourly_artifacts`, return `{"status": SUMMARY_STATUS_FAIL}`;
`alert_runner` exits 1; `save_last_slot` never runs.

FAIL: test B (R7) observes `send_notification` called with the ordinary
hourly title, or called more than once, or observes status SUCCESS, or finds
`logs/last_hourly_slot.json` written; or M1/M2 stay GREEN.

R6 — Refusal reason preserves HALT context and states non-publication
The exception message is composed BEFORE the 120-char truncation as
`"<validation_summary.halt_reason> | Hourly board update REFUSED, not
published (R5)"` when `hourly_kill_switch` is true, else `"Hourly board
update REFUSED, not published (R5): authority carrier inadmissible"`. With
`KILL_SWITCH_HALT_REASON` (runtime :3087, 56 chars) the composed text is
106 chars, <= 120.

FAIL: test B2 (R7) finds a failure body without the exact
`validation_summary.halt_reason` text on a kill-switch run, or any failure
body without the words `REFUSED` and `not published`; or M3 stays GREEN.
