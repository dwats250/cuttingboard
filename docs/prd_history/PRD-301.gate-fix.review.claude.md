## Correctness
The gate is the FIRST branch of every loop iteration and short-circuits with a no-op (`:`) whenever
RECLAIM_LOCK exists. The only acquisition path (`elif link ... then break`) is unreachable while the
gate is true, so acquisition, legacy-dir handling, and reclaim entry are all skipped — INCLUDING the
finding's `$LOCKFILE`-absent orphan case (where `[ -d "$LOCKFILE" ]` is false and, pre-fix, `link`
would have succeeded). The mutex is never removed by a contender: the only removals are inside
`_reclaim_lock` (self-created) and `_on_exit` (guarded by stored-pid == `$$`), so a foreign/orphaned
mutex is never auto-stolen. At the bound, control reaches the `[ -e "$RECLAIM_LOCK" ]` timeout branch:
exit 2 with the stale-reclaim diagnostic, mutex retained. No interleaving allows work while the mutex
exists.

## No regression
When RECLAIM_LOCK is absent the gate is false and normal reclamation is unchanged — a reclaimer takes
the `else` branch; `_reclaim_lock` creates the mutex, removes the dead canonical lock, and removes the
mutex within one function call. The mutex is held only transiently inside `_reclaim_lock`, never
across the caller's own loop iterations, so the gate cannot self-block or deadlock. The 32 prior proofs
still pass (34/34 total).

## Proofs + mutation
Both new tests are real-process (bash subprocess of the actual script) and deterministic:
test_orphaned_reclaim_lock_blocks_acquisition_and_fails_loud (dead pid + bounded loop) and
test_sigkilled_reclaimer_after_dead_lock_removal_blocks_contender (FAKE_RM_PAUSE rm-barrier scoped by
the `*.dev_bootstrap.lock` suffix, correctly excluding `.reclaim`/`.new.*`/`.stale.*`, pinning the
SIGKILL precisely after dead-lock removal and before mutex release). Both assert the full required
outcome set: bounded exit 2, `stale reclaim lock` diagnostic, `rm -f ... .reclaim` (no `rm -rf`),
canonical lock never acquired, mutex retained, no `ready`/`bootstrapped`, no env publication.
MUTATION (independently reproduced on a copy): collapsing the gate reddens BOTH new tests — each then
returns 0 with `dev_bootstrap: ready`, i.e. the bypass; assertions are load-bearing.
