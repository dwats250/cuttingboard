Status: IN PROGRESS

WHY NOW
The owner-ruled intraday session-candle card (A1) is split, per doctrine
G3/G4/G8 and Helm's 2026-08-30 ruling, into a producer then a consumer. This
PRD is the producer half only: it must persist validated current-session
1-minute source bars before any consumer can render them. The hourly run pays
for no guaranteed intraday session frame today, so the data must be acquired
here, run-local, with no reader yet.

GOAL
Co-produce, in the existing hourly run, a run-local additive sidecar
`logs/intraday_bars_snapshot.json` holding strictly-validated current-session

(deduped) and the recorded `primary_symbol`, with no reader, no dashboard
change, and no decision effect.

REQUIREMENTS

R1 — Canonical-primary shared leaf
`cuttingboard/delivery/primary_selection.py` exposes
`select_primary_card_symbol(market_map, price_bars_by_symbol, integrator_skips)`
returning the first symbol, in `_TIER_DEFS`-then-`_GRADE_ORDER`-then-symbol
order, that is (1) not integrator-skipped, (2) has a valid `current_price`
(finite positive non-bool), (3) has `fib_levels` OR `watch_zones`, (4) has
age-admitted daily bars, (5) yields a non-empty
`setup_chart.render_setup_chart_svg`. It is a pure leaf.
FAIL: `primary_selection` imports `cuttingboard.delivery.dashboard_renderer`, OR
its selection differs from the renderer's inline chart-slot winner on the
cross-check fixtures in `tests/test_primary_selection.py`.

R2 — Seam selection and bounded acquisition
At runtime:780-802, the producer computes `primary_symbol` via R1 (from the
`build_market_map` result already bound at runtime:738 and `trend_history` at
runtime:782), then fetches 1m bars for exactly `[primary_symbol, "SPY"]` deduped
via `fetch_intraday_session_bars`.
FAIL: the producer fetches any symbol other than the R1 primary and SPY, OR the
written artifact omits the `primary_symbol` field.

R3 — Injectable, guard-respecting fetch
The intraday acquisition is injectable and honors the existing live-data guard,
so a seam-driving test that does not stub intraday degrades to omission
(network-free), not a live call.
FAIL: any seam-driving test without an intraday stub performs a live network
fetch.

R4 — Strict whole-symbol validation
A symbol is written only if: timestamps are timezone-aware and strictly
ascending; columns are exactly `["ts","Open","High","Low","Close","Volume"]`;
every row has six cells with finite, coherent OHLCV (High>=max(Open,Close),
Low<=min(Open,Close), positive prices, Volume>=0); `through` == last bar ts;
`row_count` == len(bars). Any violation omits the WHOLE symbol.
FAIL: a symbol entry appears with a naive/unordered timestamp, wrong column set,
a malformed/partial row, incoherent OHLCV, or a `through`/`row_count` mismatch.

R5 — Current-session-only (prior-session rejection)
`session_date` is the current ET regular-session date computed independently of
the frame; a symbol whose bars are not that session is omitted.
`fetch_intraday_session_bars` filters to the latest date present in the frame
(`ingestion.py:240-241`), never checked against today, so a stale/pre-open
response can return a prior session.
FAIL: a symbol whose bar session date differs from the current ET regular-session
date is written to the artifact.

R6 — Versioned schema, honest provenance
The artifact matches: `schema_version:1`; `generated_at` timezone-aware UTC and
never in the future; `session_date` the ET date; `primary_symbol` a symbol or
null when no chartable primary exists;
`source:{producer:"hourly",provider:"yfinance",interval:"1m",adjusted:false}`;
`columns:["ts","Open","High","Low","Close","Volume"]`; `symbols` a map of
`{through,row_count,bars}`. `INTRADAY_BARS_PATH` is defined in
`cuttingboard/runtime/_constants.py`.
FAIL: the artifact has a non-1 or non-integer `schema_version`, a future
`generated_at`, a missing `ts` column, or a missing `primary_symbol`/`source`
field.

R7 — One isolation boundary; exactly-once notification
The entire new acquisition/selection/validation/serialization block is wrapped
in one catch-and-log boundary (mirroring the runtime:737 try / :772-779 except),
so no raise reaches the outer handler at runtime:806 or fires the second
(failure) notification at runtime:815 (the primary notification is already sent
at runtime:693).
FAIL: a raised fetch, validator, or serializer changes hourly status/artifacts
or produces a second (failure) notification.

R8 — Conditional, run-local staging
`logs/intraday_bars_snapshot.json` is conditionally force-added in
`hourly_alert.yml` (present => staged; MISSING => no-op, since the artifact is
gitignored/untracked) and is absent from the `ci_restore_publish_state.sh`
restore list, so it is never revived across runs.
FAIL: the publish step fails when the artifact is absent, OR the artifact name
appears in the restore-list invocation (104-105).

R9 — Safe to merge alone (baseline-neutral)
No reader exists (A1-C is a later PRD); `dashboard_renderer.py` is not in FILES;
the rendered dashboard is byte-identical to a pre-A1-P golden whether the artifact
is present, absent, or malformed.
FAIL: the dashboard output differs from a pre-A1-P golden, OR
`dashboard_renderer.py` appears in the change set.

R10 — No decision effect (G2)
No decision, regime, qualification, setup grade, position size, contract
selection, notification eligibility, or existing pipeline-owned artifact changes
as a function of this producer.
FAIL: any decision-pipeline output or existing artifact differs when the intraday
producer runs vs when it is disabled.

R11 — Bounded acquisition latency
The intraday fetch uses the existing bounded retry/timeout
(`FETCH_TIMEOUT_SECONDS*3` per attempt x `FETCH_RETRIES`, plus
`FETCH_BACKOFF_SECONDS`), so worst-case added wall-clock is ~94s/symbol (~188s
for two). The producer never waits unbounded. Accepted budget; a tighter
intraday timeout/retry is a Gate-A option.
FAIL: the producer performs an unbounded (no-timeout) intraday wait.

DATA FLOW
build_market_map (runtime:738) + trend_history (runtime:782) → select_primary_card_symbol (leaf) → primary_symbol
[primary_symbol, SPY] deduped → fetch_intraday_session_bars (injectable, guarded) → per-symbol 1m frames
per-symbol 1m frames → whole-symbol validation (R4/R5) → symbols map
{schema_version, generated_at, session_date, primary_symbol, source, columns, symbols} → _write_intraday_bars_snapshot (atomic replace) → logs/intraday_bars_snapshot.json
hourly_alert.yml: if present → git add -f (conditional); restore list unchanged (run-local)

FAIL CONDITIONS
- primary_selection imports dashboard_renderer, or diverges from the renderer's inline winner on the cross-check fixtures (R1).
- A fetched symbol is not the R1 primary or SPY, or primary_symbol is absent (R2).
- A seam test without an intraday stub hits the network (R3).
- A symbol with a validation defect (naive/unordered ts, wrong columns, malformed row, incoherent OHLCV, through/row_count mismatch) is written (R4).
- A prior-session frame is written (R5).
- schema_version non-1/non-integer, future generated_at, missing ts column, or missing primary_symbol/source (R6).
- A raised fetch/validator/serializer yields a second failure notification or mutates hourly status/artifacts (R7).
- Publish fails on a missing artifact, or the artifact is in the restore list (R8).
- Dashboard output differs from a pre-A1-P golden, or dashboard_renderer.py is edited (R9).
- Any decision-pipeline output changes with the producer enabled vs disabled (R10).
- The producer performs an unbounded intraday wait (R11).
