## RECOMMENDED EDITS

1. **Pin the return-carrier shape to a post-persistence key on the returned
   summary dict, and say so (PRD line 21, 50).** RC2 offers "a separate return
   value / typed result" as one option. If Stage-0 takes that literally and
   changes execute_run to return a tuple/object, it breaks every existing
   caller that indexes the return as a dict -- `test_notification_ownership.py`
   (`summary["status"]`, multiple), `test_sunday_mode.py`,
   `test_gap_down_permission_integration.py`, `test_runtime_decision.py`,
   and `test_operationalization.py`'s fixture test -- none of which are in
   FILES. The only carrier that preserves the PRD's "no existing test edited
   except the cli_main mocks" posture is a key set on the returned
   `pipeline.summary` dict strictly AFTER the :303 persistence rewrites (so it
   is returned but never persisted, satisfying R3/I4). Stating this removes the
   ambiguity that drives both REQUIRED 1 and this hazard.

2. **Add FIXTURE and SUNDAY market-stress rows to the VALIDATION exit table
   (PRD line 80).** The packet review (finding G) flagged that a FIXTURE
   market-stress halt exits 0 by predicate but never sends
   (`not fixture_backed`, runtime:904) and never publishes, and a SUNDAY
   market-stress halt IS reachable and must be covered by the daily always-send.
   Both are benign but currently implicit; naming them closes the outcome-class
   matrix the PRD promises.

3. **Ground the postmarket-EVR "benign" claim on the directional-next-run MISS
   path (PRD line 71, I6).** The packet's own review noted EVR classifies a
   directional run against a NEUTRAL halt prior as an explicit MISS, not only
   the both-NEUTRAL branch. The PRD's behavioral coverage should assert that
   MISS path (or exclude MARKET_STRESS-halt priors), and state that "benign" is
   grounded in EVR being a display-only, non-decision sidecar. This is already
   implied by I6 but the test scope should name the MISS case.
