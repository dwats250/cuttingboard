## Findings and disposition

### F1 (P2) — Promoted symbols are non-terminal rejections — ACTIONED
Claim: in EXPANSION, a symbol failing the DIRECT path and later promoted through
CONTINUATION keeps its DIRECT exclusion in `excluded` (audit history) while also
counting as qualified, so counting every `sections.rejected` record double-counts
it (e.g. one promoted NVDA → SURFACED 2 / QUALIFIED 1 / REJECTED 1) and may show
its `promoted via CONTINUATION` audit entry as the primary rejection.

Verified: `qualification.py` line ~283-287 rewrites `excluded[symbol]` to
`"DIRECT rejected (...); promoted via CONTINUATION"` while appending the promoted
candidate to `qualified` (line ~257) and setting `symbols_qualified=len(qualified)`
(line ~331) with `excluded` retained (line ~329). `contract.py` `_build_audit_summary`
sets `qualified_count = qual.symbols_qualified` and `rejected_count = len(qual.excluded)`;
`payload.py` computes `symbols_scanned = qualified_count + rejected_count +
watchlist_count`, so a promoted symbol is counted twice and its record reaches
`sections.rejected`. CONFIRMED.

Correction: the block treats a `sections.rejected` record whose `reason` contains
the pipeline's own authoritative marker `promoted via CONTINUATION` as non-terminal
— excluded from REJECTED and from the primary-reason tally, and subtracted from
SURFACED — so each symbol is represented once (the promoted one as qualified) and
QUALIFIED stays exact. No new schema or heuristic; the marker is the existing
PRD-260 R4 signal. (PRD-282 R5.)

### F2 (P2) — Validate survival inputs / fail closed — ACTIONED
Claim: the gate does not fail closed — `symbols_scanned: true` passes because
`bool` is an `int`, `rejected: "abc"` renders REJECTED 3, and a numeric `rejected`
raises `TypeError` at `len()`; the dashboard render path loads the payload without
`assert_valid_payload`.

Verified: `assert_valid_payload` is called only on the write path
(`runtime/__init__.py`, `transport.py`), not in `dashboard_renderer.py`'s load/render
path. CONFIRMED.

Correction: render only when lineage is coherent AND `symbols_scanned` is an `int`
that is not a `bool` and `> 0` AND `sections.rejected`/`sections.watchlist` are both
lists AND every rejected record is a dict; any other shape suppresses the whole
block. No global validation or CLI change (per instruction). (PRD-282 R6.)

### F3 (P2) — Strip engine metadata from the primary rejection — ACTIONED
Claim: a reason like `bad (regime=RISK_ON, confidence=0.8)` is only HTML-escaped,
so raw `(regime=`/`confidence=` tokens remain visible, contradicting the block's
no-engine-internals requirement.

Verified: the pre-correction primary reason applied only `_esc`. The system-state
WHY line already strips these tokens (`dashboard_renderer.py` ~line 2352-2353).
CONFIRMED.

Correction: the primary reason is sanitized with the same `re.sub` policy
(`regime=` / `confidence=` suffixes, then `None`/`NULL` sentinels) before `_esc`.
No second sanitization taxonomy. (PRD-282 R7.)
