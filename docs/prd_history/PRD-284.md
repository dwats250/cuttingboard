WHY NOW
`execution_policy.py` computes a per-decision `size_multiplier` (confidence
tier × macro-pressure factor) and records it on the `TradeDecision`, but it
never applies it to the position. `apply_execution_policy` sets
`size_multiplier=result.size_multiplier` (`execution_policy.py:184`) and never
touches `contracts` or `dollar_risk`; the trader-facing surfaces read sizing
straight from the pre-policy `OptionSetup`, so a policy decision to cut size in
half is displayed and exported at full size. The contract can carry the
inconsistent triple `{size_multiplier: 0.5, position_size: 2, dollar_risk: 300}`
(reconciliation CB-03). Only a multiplier of exactly `0` has any effect today,
and only because `is_actionable_trade` reads `size_multiplier > 0` as a boolean
gate — the fractional cut is silently discarded, violating the description-not-
prediction / the-system-serves-the-trader principles (the sizing shown is not
the sizing the policy decided). This is A2 in `audits/BUILD_PLAN.md`
(reconciliation finding CB-03), the settled "size multiplier materializes into
contracts/dollar_risk" work that was planned as "PRD-254" but never shipped
(that number landed hook/settings hardening instead).

GOAL
Apply the finalized execution-policy `size_multiplier` to the actual position so
every trader-facing surface reads the materialized sizing: for an allowed
decision, replace `contracts` with `floor(contracts × size_multiplier)` and
recompute `dollar_risk` proportionally; when that floors to zero, downgrade the
decision to a `BLOCK_TRADE` at stage `EXECUTION_POLICY` with the canonical
reason `size_rounds_to_zero`, non-actionable, carrying the truthful reason
through the existing execution-policy block-reason consumers — while preserving
all `size_multiplier == 1` behavior value-for-value.

SCOPE
- Materialize in `execution_policy.py::apply_execution_policy`, using the
  finalized multiplier from `evaluate_execution_policy` (already macro-pressure-
  adjusted). Add module constant `POLICY_SIZE_ROUNDS_TO_ZERO = "size_rounds_to_zero"`.
- Unity short-circuit (allowed, `result.size_multiplier == 1.0`, equivalently
  `materialized_contracts == decision.contracts`): leave `contracts` and
  `dollar_risk` UNTOUCHED; change only the policy fields
  (`size_multiplier = 1.0`, `policy_allowed = True`, `policy_reason =
  result.reason`), exactly as `execution_policy.py:179–185` does today. This
  structurally guarantees the R3 value-for-value invariant rather than relying
  on `(d/c)×c == d` holding in float arithmetic (PRD-198 invariant 6).
- Positive path (allowed, `materialized_contracts >= 1` and
  `materialized_contracts != decision.contracts`): replace `contracts` with
  `materialized_contracts` and `dollar_risk` with
  `round(dollar_risk_per_contract × materialized_contracts, 2)`, where
  `dollar_risk_per_contract = decision.dollar_risk / decision.contracts` (the
  `round(..., 2)` matches the cents convention every `dollar_risk` already
  carries, `options.py:299`); keep `size_multiplier = result.size_multiplier`,
  `policy_allowed = True`, `policy_reason = result.reason`.
- Zero path (allowed, `materialized_contracts == 0`): downgrade to
  `BLOCK_TRADE`; `block_reason = size_rounds_to_zero`;
  `decision_trace = {stage: EXECUTION_POLICY, source: execution_policy, reason:
  size_rounds_to_zero}`; `policy_allowed = False`;
  `policy_reason = size_rounds_to_zero`; `size_multiplier = 0.0`; `contracts`
  and `dollar_risk` left at their pre-materialization values (the
  `TradeDecision.contracts >= 1` invariant forbids `contracts = 0`, and the
  block makes the position moot).
- Re-point the three sizing consumers that today read the pre-policy
  `OptionSetup` to read the materialized `TradeDecision` instead, killing the
  inconsistent triple:
  1. `contract.py::_build_trade_candidates` — `position_size` / `dollar_risk`

     `size_multiplier` from the decision).

     materialized decision when a decision exists for the symbol (it already
     records `size_multiplier` from the decision; the `trade_decisions[]` block
     already reads `decision.contracts` / `decision.dollar_risk`).
  3. `output.py::render_report` / `_setup_detail` — render materialized sizing
     for actionable decisions and exclude execution-policy-blocked decisions
     from the A+ TRADES section, via a new optional keyword argument carrying a
     per-symbol materialized-sizing map derived from the decisions (absent →
     unchanged legacy behavior, preserving every existing caller).
- Thread the materialized-sizing map into `render_report` from the only call

REQUIREMENTS

R1 — Materialize contracts on the positive path
For an allowed decision, `apply_execution_policy` sets
`contracts = floor(decision.contracts × result.size_multiplier)` whenever that
value is `>= 1`, using `math.floor`, and returns a decision whose `contracts`
equals that value.

FAIL: An allowed decision with `contracts = 3` and a finalized multiplier of
`0.75` (`floor(2.25) = 2`) returns `contracts != 2`.

R2 — Recompute dollar_risk proportionally on the positive path
On the positive path (`materialized_contracts != decision.contracts`),
`dollar_risk` is recomputed as
`round((decision.dollar_risk / decision.contracts) × materialized_contracts, 2)`
— cents-rounded to match the convention every `dollar_risk` already carries
(`options.py:299`). No fractional-contract or full-size dollar figure is
emitted.

FAIL: A `contracts = 2`, `dollar_risk = 300.0`, multiplier `0.5`
(`materialized_contracts = 1`) decision returns `dollar_risk != 150.0`, or a
`contracts = 3`, `dollar_risk = 100.0`, multiplier `0.75`
(`materialized_contracts = 2`) decision returns a `dollar_risk` not equal to
`66.67` (an unrounded `66.666…`).

R3 — Preserve size_multiplier == 1 value-for-value (structural)
When the finalized multiplier is exactly `1.0`, the unity short-circuit
(SCOPE) leaves `contracts` and `dollar_risk` untouched, so the returned
decision's `contracts`, `dollar_risk`, `status`, `entry`, `stop`, `target`,
`direction`, `r_r`, `block_reason`, `decision_trace`, `policy_allowed`, and all
other non-policy fields are byte-for-byte identical to the pre-change
(multiplier-not-applied) decision. R3 is guaranteed structurally by the
short-circuit, NOT by float algebra on the R2 formula.

FAIL: A `contracts = 4`, `dollar_risk = 800.0`, multiplier `1.0` allowed
decision returns any field differing from the current (pre-PRD-284) output —
e.g. `contracts != 4` or `dollar_risk != 800.0`.

R4 — Block at EXECUTION_POLICY when the position rounds to zero
When an allowed decision's `floor(contracts × multiplier) == 0`, the returned
decision has `status == BLOCK_TRADE`, `block_reason == "size_rounds_to_zero"`,
`decision_trace == {"stage": "EXECUTION_POLICY", "source": "execution_policy",
"reason": "size_rounds_to_zero"}`, `policy_allowed is False`,
`policy_reason == "size_rounds_to_zero"`, and `size_multiplier == 0.0`;
`contracts` remains at its pre-materialization value (`>= 1`).

FAIL: A `contracts = 1`, multiplier `0.5` allowed decision returns
`status == ALLOW_TRADE`, `contracts == 0`, a `block_reason` other than the exact
literal `size_rounds_to_zero`, a `decision_trace.stage` other than
`EXECUTION_POLICY`, or `size_multiplier != 0.0`.

R5 — The zero-rounding block is non-actionable and reason-carried
A `size_rounds_to_zero` decision is excluded by `decision_is_actionable` and
`candidate_is_actionable` (so it is absent from the run TRADE outcome and from
`top_trades`), and its reason reaches the block-reason consumers via the
existing `EXECUTION_POLICY` block path (contract `trade_candidates`
`block_reason` / `decision_trace`, audit record, and any downstream reader of
those) without contradiction or generic substitution.

FAIL: A run whose sole candidate rounds to zero yields a TRADE outcome, lists
the symbol in `top_trades`, or produces a contract `trade_candidate` whose
`block_reason` is empty or a reason other than `size_rounds_to_zero` for that
symbol.

R6 — Contract trade_candidates read materialized sizing (no inconsistent triple)
`contract.py::_build_trade_candidates` emits `position_size` and `dollar_risk`
from `decision.contracts` and `decision.dollar_risk`, so the candidate's
`{size_multiplier, position_size, dollar_risk}` are mutually consistent for
every decision. `assert_valid_contract` still passes.

FAIL: A candidate for an allowed, materialized decision carries
`size_multiplier = 0.5` with `position_size = 2` / `dollar_risk = 300.0`
(the pre-policy triple) instead of `position_size = 1` / `dollar_risk = 150.0`.

R7 — Audit reads materialized sizing
The audit `qualified_list` entry for a symbol with a materialized decision emits
`contracts` / `dollar_risk` from the decision, consistent with the entry's
`size_multiplier`; the `trade_decisions[]` block continues to emit
`decision.contracts` / `decision.dollar_risk`.

FAIL: An audit `qualified_list` entry carries `size_multiplier = 0.5` alongside
`contracts` / `dollar_risk` equal to the pre-policy setup values.

R8 — Report renders materialized sizing and excludes policy-blocked trades
When `render_report` is supplied the materialized-sizing argument (as at the
production call site), the A+ TRADES section renders `contracts` / `max risk`
from the materialized decision and does NOT render a decision blocked by
execution policy (including `size_rounds_to_zero`) as an A+ trade. With the
argument absent, rendering is byte-identical to pre-change (legacy callers
preserved).

FAIL: A production run in which a candidate materializes to 1 contract renders
"2 contracts" in the report body, OR a `size_rounds_to_zero` candidate is
rendered in the A+ TRADES section; OR an existing `render_report` caller that
omits the new argument produces different output than pre-change.

DISTINCTION FROM PRD-283
PRD-283 (CB-02) refuses at `OPTIONS_SIZING` with reason
`SMALLEST_CONTRACT_EXCEEDS_BUDGET` when the smallest expressible contract
already breaches the correlation-adjusted budget — BEFORE any `TradeDecision`
exists (no `OptionSetup` is emitted). PRD-284 (CB-03) blocks at
`EXECUTION_POLICY` with reason `size_rounds_to_zero` when an already-affordable
decision's policy-scaled position floors to zero — AFTER a `TradeDecision`
exists. Different producer (`options.py::build_option_setups` vs
`execution_policy.py::apply_execution_policy`), predicate (budget-vs-smallest-
contract vs `floor(contracts × multiplier)`), stage, and reason literal. The two
reasons must never be conflated (cf. the `options.py:63–68` sibling comment).

consistent (`size_multiplier`, `contracts`/`position_size`, `dollar_risk` agree)
across: contract `trade_candidates`, audit `qualified_list` and

block is uniformly non-actionable. The block reason is carried, un-substituted,

readers.
