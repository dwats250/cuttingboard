# PRD-345 — prd_close.sh --next matches the canonical bulleted Next-step line

Status: IN PROGRESS

LANE
MICRO

CLASS
INFRA + PATCH

(Patch against PRD-164 R5 / PRD-183: the closeout helper's Next-step rewrite.)

ROOT CAUSE
ambiguous requirement — PRD-164 R5 specified "the PROJECT_STATE Next step line" without pinning its markup. PRD-183 later moved PROJECT_STATE to the bulleted "Current state" form, so the live file carries `- **Next step:** ...` (docs/PROJECT_STATE.md:245) while `scripts/prd_close.sh:262-269` still searches `^\*\*Next step.*$` and writes an unbulleted `**Next step:** ...`. The test fixture in tests/test_prd_close.py:58 kept the OLD unbulleted form, so the suite stayed green while every real `--next` invocation failed loud ("'**Next step**' line not found"). Recorded as known debt in PROJECT_STATE since July.

GOAL
Make `--next` match the canonical bulleted Next-step line and rewrite it in place, preserving the leading `- ` bullet, while keeping every other contract of the helper unchanged: exactly one line updated, fail-loud when `--next` is supplied and no Next-step line exists, no partial closeout files written on that failure, and no Next-step change when `--next` is omitted.

SCOPE
- `scripts/prd_close.sh` step (d): pattern `^(- )?\*\*Next step.*$` with a replacement that re-emits the captured prefix (`- ` or empty) followed by `**Next step:** <text>`; unchanged error text when the line is absent.
- `tests/test_prd_close.py`: the fixture PROJECT_STATE adopts the live bulleted form `- **Next step:** ...`; add regressions for R1-R3 below; existing `startswith("**Next step")` assertion adjusted to the bulleted form.
- Bookkeeping per convention: registry row, index entry, PROJECT_STATE active-PRD pointer (pointer touch only; obliges a fresh-context review per the MICRO row).

OUT OF SCOPE
- Any other prd_close.sh behaviour (registry flip, status markers, Active PRD reset, test baseline, Recent ships, index); prd_open.sh; the PROJECT_STATE content itself.

REQUIREMENTS

R1 — Bulleted Next-step line is rewritten in place, bullet preserved.
With a PROJECT_STATE containing exactly one `- **Next step:** old text` line and `--next "new text"` supplied, the output contains exactly one line matching `^- \*\*Next step:\*\* new text$` and no line containing "old text".
FAIL: the helper exits non-zero, or the output has zero or more than one Next-step line, or the line lost its `- ` prefix, or "old text" survives. Mutation M1 (revert the pattern to `^\*\*Next step.*$`) must turn this test RED.

R2 — Absent line with --next fails loud and writes nothing.
With no Next-step line in PROJECT_STATE and `--next` supplied, the helper exits non-zero, stderr names "Next step", and all four closeout artifacts (PROJECT_STATE, registry, PRD doc, index) are byte-identical to their pre-run content.
FAIL: exit code 0, or stderr lacks "Next step", or any artifact differs after the run.

R3 — Omitted --next leaves the bulleted line untouched.
Without `--next`, the bulleted `- **Next step:** old text` line is byte-identical after a successful closeout.
FAIL: the line changed or disappeared.

R4 — Unbulleted legacy form still accepted.
A PROJECT_STATE carrying the legacy `**Next step:** old text` (no bullet) is still rewritten in place as `**Next step:** new text` (prefix preserved as empty).
FAIL: exit non-zero or the legacy line is not rewritten.
