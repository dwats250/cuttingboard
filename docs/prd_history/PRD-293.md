WHY NOW
Remote/mobile sessions (e.g. an Asher checkout) frequently start with the
`cuttingboard` package NOT installed into a usable environment, so
`import cuttingboard`, `pytest`, and `ruff` fail on first use (reconciliation
F-5, "remote-session env unbootstrapped … a known trap"). QW-5 removes the trap
with an idempotent bootstrap that OWNS a repo-local `.venv`, invoked by a thin
SessionStart hook — without an unconditional install-on-every-session anti-
pattern.

with every existing setting and permission byte-unchanged except the minimal
SessionStart addition.

CHANGE SURFACE
`.claude/settings.json` is touched but is NOT a GOVERNANCE_PAYLOAD_FILE and no
permission entry changes — only a SessionStart hook is added. The new automated
execution is the material surface; it is guarded by the environment/probe/fail-
loud contract below and mutation-discriminating red tests (PRD-198 #4).

ENVIRONMENT CONTRACT (owns the repo-local `.venv`)
- Resolve the physical repository root from the script's own location, never
  from caller cwd/`PYTHONPATH`/activated env.
- Target ONLY `<repo>/.venv`. Reject (fail-loud, do NOT auto-delete): a
  symlinked `.venv`, an externally-located env, `include-system-site-packages =
  true`, Python < 3.11, or an invalid/broken `.venv`.
- When `.venv` is absent: pick the first usable base interpreter in order
  `python3` then `python`, requiring Python >= 3.11 with `venv` support, and run
  `<base-python> -m venv .venv`. The base interpreter MAY create the venv but
  MUST NEVER run pip.
- Every install: `"$REPO_ROOT/.venv/bin/python" -m pip install -e ".[dev]"` from
  the repo root. Never system/active/global pip (so PEP 668 is irrelevant).

READINESS PROBE CONTRACT ("ready" == zero pip invocations)
Ready requires ALL of, evaluated in isolation (`.venv/bin/python -I`, ignoring
cwd/`PYTHONPATH`/user-site/activated env):
- `.venv/bin/python` is the validated owned interpreter, Python >= 3.11.
- `cuttingboard` imports from THIS checkout, and its distribution metadata is
  EDITABLE with `direct_url.json` resolving to the current physical repo root.
- Every active `[project.dependencies]` and `[project.optional-dependencies].dev`
  requirement is installed at a satisfying version — INCLUDING `PyYAML>=6.0`
  (a third dev dep beyond pytest and ruff).
- Ruff distribution metadata AND `.venv/bin/ruff --version` both resolve exactly
  `0.15.22` (PRD-273 pin).
- `.venv/bin/python -I -m pytest --version` AND `.venv/bin/pytest --version`
  both succeed.
Not-ready => at most ONE `.venv/bin/python -m pip install -e ".[dev]"`, then the
IDENTICAL full probe; if it still fails, bootstrap fails. `import ruff` is NOT
the lint readiness contract — the executable and exact version are.

SESSION-ENV BINDING (activate the parent session)
After readiness succeeds, and ONLY when `CLAUDE_ENV_FILE` is supplied, the
script idempotently appends safely-quoted `VIRTUAL_ENV=<repo>/.venv` and a
`<repo>/.venv/bin`-first `PATH` to `CLAUDE_ENV_FILE` (no duplicate entries; never
written on failure). Standalone human execution instead prints the explicit
`.venv/bin/...` paths / activation command. This narrow session-env write is
permitted by R1 and is neither a global install nor persistent system mutation.

SESSIONSTART HOOK (exact, cwd-safe, delegating)
```json
"SessionStart": [
  {
    "matcher": "startup|resume|clear",
    "hooks": [
      {
        "type": "command",
        "command": "cd \"${CLAUDE_PROJECT_DIR:-.}\" && bash scripts/dev_bootstrap.sh",
        "timeout": 300,
        "statusMessage": "Preparing CuttingBoard developer environment..."
      }
    ]
  }
]
```
`compact` is deliberately EXCLUDED (a no-network failure would recur
automatically). The hook only delegates; no bootstrap logic embedded.

FAILURE SEMANTICS
Every failure => a concise stderr diagnostic naming the failed step and
`.venv`, and exit 2 (surfaced by Claude Code as a non-blocking hook error; the
session continues and stays usable). Never `continue:false`; never a success
message on failure; never a session-env write on failure. At most one venv
creation + one pip invocation per event; NO internal retry. A failed session
may retry via a later user-driven resume/clear or `bash scripts/dev_bootstrap.sh`.

IDEMPOTENCY STATE MATRIX (frozen)
- Fully ready: session-env binding + one status line; ZERO pip.
- Missing `.venv`: create, install once, post-probe.
- Missing/incomplete deps, absent editable metadata, wrong checkout provenance,
  or wrong ruff: install once, post-probe.
- Repo moved / `.venv` reused from another checkout: provenance fails, install
  retargets it (provided the venv itself is valid).
- Broken/non-isolated/symlinked/unsupported `.venv`: fail visibly, NO deletion/
  recreation/system fallback.
- Pip or post-probe failure: exit 2, no success message, no env binding.

REQUIREMENTS

R1 — Confined, idempotent, non-destructive; narrow session-env write permitted
The bootstrap operates ONLY within `<repo>/.venv`; a ready env causes zero pip;
no global/system mutation; the only environment write outside `.venv` is the
idempotent `CLAUDE_ENV_FILE` binding after readiness.
FAIL: pip runs when the probe already passes; any global/system mutation; a
`CLAUDE_ENV_FILE` write on failure or with duplicates.

R2 — Fail-loud, no loop
Any un-completable bootstrap exits 2 with a clear stderr message; never exits 0
on failure; never retries internally; never runs on `compact`.
FAIL: a failed bootstrap exits 0/loops, or SessionStart fires on `compact`.

R3 — Version-true readiness
"Ready" enforces the full isolated dependency + editable-provenance + pytest
resolution + exact ruff-0.15.22 probe above; a global/stale/wrong-version
install cannot produce a false READY.
FAIL: `import`-only or version-blind readiness; a wrong ruff version reads ready.

R4 — Thin delegating hook, zero permission/hook drift
`.claude/settings.json` gains exactly the SessionStart entry above; JSON stays
valid; `permissions.allow`/`deny` and the existing PreToolUse/UserPromptSubmit
hooks are byte-unchanged.
FAIL: embedded logic, any permission/hook change, or invalid JSON.

FROZEN IMPLEMENTATION INVARIANTS (Gate-A binding; Sol E)
1. Physical root from the script location, never accidental cwd.
2. `.venv` repo-local, non-symlinked, isolated from system site-packages,
   Python >= 3.11.
3. Base interpreter order `python3` then `python`; base MAY create the venv,
   MAY NEVER run pip.
4. All pip via `.venv/bin/python` only.
5. Probe isolated from cwd/`PYTHONPATH`/user-site/activated env.
6. Editable provenance names the current physical checkout.
7. All declared runtime + dev requirements satisfy versions (incl. PyYAML).
8. Ruff executable AND metadata both == 0.15.22.
9. Pytest module AND `.venv/bin/pytest` both resolve.
10. Ready => zero pip.
11. Not-ready => at most one install + identical post-probe.
12. Wrong-version / incomplete-extra / absent-editable / moved-repo / wrong-
    checkout are NOT ready.
13. Broken/unsafe `.venv` fails without deletion/recreation/external fallback.
14. Session PATH/VIRTUAL_ENV binding only after readiness, idempotent.
15. Failure => stderr + exit 2; success => one concise line + exit 0.
16. SessionStart excludes `compact`; exact cwd-safe delegation above.
17. `permissions.allow`/`deny`, PreToolUse, UserPromptSubmit unchanged.
18. No CI workflow/helper, Cloudflare, Options, global install, or unrelated
    file change.
19. Tests prove call counts + targets in temporary fixtures (fake executables /
    logging, no network) and include mutation-discriminating failures for
    readiness, confinement, and fail-loud behavior.
20. Payload expansion or >90 net-production LOC => stop-and-renew.
