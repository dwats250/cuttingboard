REQUIREMENTS

R1 — Presentation-only; upstream untouched
No file outside FILES is edited; no compute module changes; selection changes no
datum. Default-selected setup = select_primary_card_symbol(...); the primary
chart-slot rule (chart_slot_available = sym == primary) is byte-unchanged.
FAIL: any diff to an out-of-scope compute module, or the rendered setup-chart
count differs from today's for the same fixture, or the default-checked radio is
not the canonical primary when the primary is a workspace symbol.

R2 — Native, no JavaScript
The setup selector is a radio group toggled by CSS :checked~ rules (the PRD-330
pattern). No <script> is added and no inline handler is used.
FAIL: html.count("<script") != 1 (the pre-existing staleness banner), or any
onclick/onchange/role="tab"/role="tablist" appears in the rendered HTML.

R3 — MANUAL CHECK impossible to miss; PRD-331 preserved
#alert-watchlist is emitted BEFORE #candidate-board inside #watching-zone and is
never inside any tab panel. The PRD-331 flag row (class "candidate-state
manual-check", data-raw-state="NEEDS_MANUAL_CHECK", span "manual-check-flag" with
literal text "MANUAL CHECK") is byte-unchanged; the literal "MANUAL CHECK" count
and "flag only inside #alert-watchlist" hold. Any per-setup mirror on a tab uses
the token "CHECK", not the literal.
FAIL: #alert-watchlist renders after #candidate-board; or the "MANUAL CHECK"
literal count changes; or the literal appears outside #alert-watchlist; or a
manual-check candidate becomes discoverable only by selecting a tab.

R4 — Selection hides no critical state (guardrail)
Without changing selection the operator can read: how many setups exist (screen
line + tab count), which is active, and each other qualified setup's
symbol+grade (every tab shows both, always). Static _CSS never hides a
.setup-panel or .tier-group; only the inline per-symbol rules (each beginning
"#setup-") toggle visibility, so a selector failure shows more, never less
(fail-open to the stacked list).
FAIL: a qualified setup's identity/grade is not visible until selected; or static
_CSS contains a display:none targeting .setup-panel/.tier-group outside the
inline per-symbol block.

R5 — Upper surface identity preserved
All upper-surface markup (#system-state, #tape-zone, #spy-session, #today-zone)
is byte-unchanged; upper refinements are CSS appended to the _CSS tail with no
existing rule string edited and new phone rules in a separate
@media(max-width:430px) block.
FAIL: test_dashboard_d2_seam.py R1/R2/R5/R8 change; or any pre-existing _CSS rule
string is modified rather than appended-after.

R6 — Oracle re-baseline is deliberate and reviewed
The below-seam seam hashes and the whole-document goldens are re-baselined to the
new WATCHING bytes in dedicated, reviewed commits; goldens are regenerated by the
renderer, never hand-edited.
FAIL: a golden is hand-edited; or a seam/golden oracle is deleted/weakened rather
than re-baselined; or the re-baseline rides an unrelated commit.

R7 — No horizontal overflow at operator viewports
At 390x844, 360x780, and 1280x960, document.documentElement.scrollWidth <=
window.innerWidth by default, with every disclosure open, and with each setup tab
selected in turn; measured via DevTools device metrics asserting innerWidth.
FAIL: page horizontal overflow in any of those states, or overflow suppressed
with overflow:hidden rather than a min-width:0 / minmax(0,1fr) containment fix.
