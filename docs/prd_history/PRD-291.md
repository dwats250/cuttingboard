WHY NOW
Agents prepare a branch, run proof and validation, drive the fresh-context
review, and complete same-PR closeout, but cannot transition a completed
DRAFT PR to "Ready for review" — so a fully prepared PR cannot reach the
owner's merge button without a manual owner UI action. This recurred on PR
#232 and PR #233 and tripped the campaign's recurring-friction rule.

Current boundary (record 1 — deny/allow interaction). The effective
permission set is `.claude/settings.json` UNION `.claude/settings.local.json`.
`.claude/settings.json` `permissions.deny` contains `Bash(gh pr ready*)`;

`gh pr ready` and the pre-existing broad allow does nothing for this one
command. The merge deny (`Bash(gh pr merge:*)`) and the gh-api mutation denies
are separate deny entries, unrelated to this line.

GOAL
Permit an agent to transition an already-prepared PR between DRAFT and Ready
for review (both directions), so a completed PR reaches the owner's merge
button without an owner UI action — while every consequential landing/state
authority (merge, api mutation, destructive git) stays exactly as denied.

SCOPE
- Exact one-line permission delta (record 2): delete exactly the entry
  `Bash(gh pr ready*)` from `.claude/settings.json` `permissions.deny`. One
  deleted line; `deny` count 80 -> 79; JSON remains valid. Nothing else
  changes. (This change is already staged on the branch at commit `66c2b27`
  as part of the MATERIAL packet path; branch `deny` count is verified 79 with
  the merge and gh-api denies intact.)
- Intended use (record 3): after merge + config reload the agent may run
  `gh pr ready <n>` to mark an already-prepared DRAFT PR Ready for review.
- Bidirectional capability (record 4): `gh pr ready` is two-way —
  `gh pr ready [target]` marks Ready; `gh pr ready --undo [target]` reverts
  Ready back to DRAFT. Both directions are within the granted authority. Under
  the reviewed `gh` 2.46.0 there is no merge, close, or base-changing operation
  on `gh pr ready`.
- Wildcard/suffix semantics (record 5): the permitted shape is the glob
  `Bash(gh pr ready*)` (an arbitrary-suffix matcher). It matches any command
  string beginning `gh pr ready`, which under `gh` 2.46.0 is only
  `gh pr ready [--undo] [<target>]`, where `<target>` may be omitted (the
  current branch's PR) or given as a `<number>`, `<url>`, or `<branch>`. No
  other `gh` subcommand begins with the token `gh pr ready`. Two independent
  denies bound the target regardless of grammar: URL forms are blocked by
  `Bash(gh pr *http*)`, and cross-repository forms by `Bash(gh -R*)` /
  `Bash(gh --repo*)` (and their `gh * -R*` / `gh * --repo*` variants). The
  wildcard therefore does not widen authority beyond the DRAFT<->Ready
  transition on a current-repository PR.

OUT OF SCOPE
- Merge authority — `Bash(gh pr merge:*)` deny REMAINS; merge stays owner-only
  (GOV-1). (record 6)
- All gh-api mutation denies REMAIN (`-X`, `--method`, `-f`, `-F`,
  `--raw-field`, `--field`, and their `* -X*` etc. variants), so PR title/body
  editing via `gh api` PATCH stays denied. (record 7)
- All git/worktree destructive denies REMAIN: checkout, switch -f/-C/...,
  restore, reset, rebase, branch -d/-D/-m/..., worktree
  add/remove/move/prune/lock/repair, push --force/-f/--delete/--mirror/--prune.
  (record 8)
- Tightening the pre-existing `Bash(gh pr *)` local allow (which already
  permits `gh pr edit`/`close`/`reopen`) is NOT in this PRD; it is a separate
  permission-boundary finding handled by a separate read-only permission-
  surface audit, per Dustin's design-direction ruling.

REQUIREMENTS

R1 — Exact one-line deletion, nothing else
The change is exactly the removal of the single `permissions.deny` entry
`Bash(gh pr ready*)` from `.claude/settings.json`. Every other deny entry, the
whole allow array, and the hooks block are byte-unchanged; the file parses as
valid JSON.
FAIL: any deny entry other than `Bash(gh pr ready*)` is added, removed, or
altered; or the allow array or hooks block changes; or the file is not valid
JSON.

R2 — Merge and mutation protection preserved
After the change, `Bash(gh pr merge:*)` and every gh-api mutation deny remain
present, so merge and `gh api` PATCH title/body editing stay denied.
FAIL: `gh pr merge` or any denied `gh api` mutation becomes permitted.

R3 — Authority bounded to the draft<->ready transition
The only new capability is `gh pr ready [--undo] [<target>]` (both directions),
where `<target>` is omitted (current branch's PR), a `<number>`, a `<url>`, or
a `<branch>`. URL and `-R`/`--repo` cross-repo forms remain independently
denied, so no merge, close, base-change, or cross-repository authority is
exposed. No other command becomes permitted by removing the glob.
FAIL: removing `Bash(gh pr ready*)` enables any command other than
`gh pr ready [--undo] [<target>]`.
