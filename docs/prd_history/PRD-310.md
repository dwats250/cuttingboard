REQUIREMENTS

R1 — Insertion point and gating
hourly_alert.yml gains exactly one new step, named
"Refresh GEX snapshot (best-effort)", placed after the
"Aggregate regime history" step and before the
"Render and stage hourly artifacts" step, gated
`if: ${{ success() && steps.freshcheck.outputs.fresh == 'true' }}` — the
same fresh-hourly-payload gate the render step uses.

FAIL: The step is absent, appears after the render step, or lacks the
fresh == 'true' gate (i.e., can run on a suppressed/non-fresh slot).

R2 — Pre-refresh scrub (no inherited artifact)
The step's first command removes logs/gex_snapshot.json
(`rm -f logs/gex_snapshot.json`) before invoking the producer, so no
checked-out, restored, or otherwise pre-existing copy can survive into the
render without a successful fresh producer write in THIS run.

FAIL: The producer invocation is reachable while a pre-existing
logs/gex_snapshot.json has not been removed first.

R3 — Best-effort semantics: failure degrades to absence, step succeeds
The step invokes the existing producer (`python3 tools/gex_snapshot.py`,
default artifact path and URL). On nonzero producer exit the step removes
logs/gex_snapshot.json again and the step itself exits 0. Both outcomes —
producer success and producer failure — conclude the step successfully; the
producer's own exit-0-only-after-atomic-write contract (PRD-306 R10/R13) is
relied on, not modified.

FAIL: Any producer failure mode (non-200, malformed body, admissibility
fail-loud, exception) yields a step exit code other than 0, OR leaves
logs/gex_snapshot.json present when the render step starts.

R4 — No persistence, no pipeline alteration
logs/gex_snapshot.json is NOT added to the restore step's argument list and
NOT added to the commit step's `git add` set; tools/ci_push_artifacts.sh and
tools/ci_restore_publish_state.sh are untouched. The artifact stays
run-local; the rendered ui/dashboard.html riding the EXISTING commit/publish
path is the durable output. The render, readiness, commit, and push steps'
conditions and contents are unchanged.

FAIL: "gex_snapshot" appears in the restore step line or in the commit
step's `git add` block, or the diff touches any file or workflow step other
than the single inserted block.

R5 — Guard test, mutation-verified red
tests/test_ci_artifact_hygiene.py gains workflow-content assertion(s), in
the file's established `_workflow_text` style, that fail RED when any of
the following mutations is applied to hourly_alert.yml:
  (a) the refresh step is deleted, moved after the render step, or its
      fresh == 'true' gate is removed;
  (b) the best-effort shape is broken — the pre-invocation `rm -f
      logs/gex_snapshot.json` or the on-failure `|| rm -f
      logs/gex_snapshot.json` is dropped;
  (c) "logs/gex_snapshot.json" is added to the restore step's arguments or
      to the commit step's `git add` block.
Each red case is demonstrated during implementation by applying the
mutation, observing the test fail, and reverting (PRD-198 invariant 4).

FAIL: Any of mutations (a)-(c) leaves the new test(s) green.

DATA FLOW
Success: Cboe delayed_quotes _SPX endpoint -> tools/gex_snapshot.py (one
keyless GET, in-runner) -> logs/gex_snapshot.json (run-local, ephemeral) ->
dashboard_renderer (existing gex_card.load_gex_snapshot read) ->
ui/dashboard.html -> existing commit + publish path.
Failure: producer nonzero -> rm -f logs/gex_snapshot.json -> renderer sees
absent -> card suppressed -> baseline dashboard publishes normally.
Next hourly run repeats from scratch (fresh observation, never a reused
artifact).

FAIL CONDITIONS
- Refresh step absent, mis-ordered (not before render), or not gated to
  fresh == 'true' (R1).
- Producer invocation reachable without prior removal of a pre-existing
  artifact (R2).
- Any producer failure yields step exit != 0 or leaves the artifact present
  at render time (R3).
- Artifact enters the restore list, the commit stage set, or any publish
  path; or the diff exceeds the single inserted workflow block plus the
  declared test/bookkeeping files (R4).
- Any guard-test mutation (a)-(c) fails to turn the new test(s) red (R5).
- Production/config delta exceeds 12 added lines in hourly_alert.yml, or
  any file outside FILES is touched (MAX EXPECTED DELTA / scope lock).
