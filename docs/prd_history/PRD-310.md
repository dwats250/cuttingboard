REQUIREMENTS

R1 — Insertion point and gating
One step, "Refresh GEX snapshot (best-effort)", after "Aggregate regime
history" and before "Render and stage hourly artifacts", gated
`if: ${{ success() && steps.freshcheck.outputs.fresh == 'true' }}`.
FAIL: Step absent, ordered after the render step, or missing that gate.

R2 — Bounded best-effort semantics (owner failure contract)
Step body is exactly:
`rm -f logs/gex_snapshot.json logs/gex_snapshot.json.tmp` then
`timeout --kill-after=10 120 python3 tools/gex_snapshot.py || rm -f
logs/gex_snapshot.json logs/gex_snapshot.json.tmp`.
Four exhaustive outcomes: (1) producer exit 0 within bound -> fresh atomic
artifact renders; (2) producer nonzero OR wall-clock expiry (SIGTERM at
120s, guaranteed SIGKILL at +10s; exits 124/137) -> both paths scrubbed,
step exit 0, baseline board publishes; (3) initial scrub rm failure -> step
fails CLOSED before invoking the producer; (4) cleanup rm failure -> step
fails CLOSED (never certify an absence not established; PRD-198 invariant
1). No `|| true` anywhere.
FAIL: Any outcome deviates: a producer failure/timeout with working rm
leaves either path present or the step nonzero; an rm failure lets the
step succeed; or the timeout/escalation is absent.

R3 — Run-local, deliberately unpersisted artifact
logs/gex_snapshot.json is never restored, never staged, never published;
each eligible hourly render gets a fresh acquisition attempt. RELIED-ON
INVARIANT: `logs/` stays gitignored, keeping BOTH artifact paths invisible
to ci_push_artifacts.sh's dirty-tree abort — guarded by R5(h).
FAIL: "gex_snapshot" appears in any restore invocation, commit add block,
publish/deploy path, or failure-upload list; or any hourly_alert.yml diff
exists outside the single inserted block.
