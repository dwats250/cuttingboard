WHY NOW
Add one frozen synthetic SPX GEX reference disclosure after WATCHING at the
DETAILS boundary for learning context; separate reference carrier, no
production/live GEX coupling.

MAX EXPECTED DELTA

files below (dashboard_renderer.py seam emit; gex_card.py minimal pure helper

GOAL
Expose exactly one native, collapsed "GEX REFERENCE · SYNTHETIC EXAMPLE"
disclosure at the WATCHING -> DETAILS boundary that renders one frozen synthetic
SPX example through the existing provider-neutral GEX profile/ladder/table
geometry, as an educational reference that is structurally separate from — and
can never be confused with or substituted for — current/live production GEX.

REQUIREMENTS

R1 — Disclosure exists at the WATCHING -> DETAILS boundary
Rendered dashboard HTML contains exactly one element with id="gex-reference",
emitted after the #watching-zone close and before the #details-history open, as
a native <details> (collapsed by default). Zone order remains VERDICT, TAPE,
SPY SESSION, NEXT EVENT, WATCHING, DETAILS.
FAIL: id="gex-reference" is absent, appears more than once, appears inside
#watching-zone or #details-history, is not a <details>, is open by default, or
the six-zone order changes.

R2 — Reference identity is unmistakable in every surface
"GEX REFERENCE · SYNTHETIC EXAMPLE" (or an equally explicit synthetic/reference
identity) appears in the collapsed summary, the expanded heading, the ladder's
visible label AND its SVG accessible name, and a provenance block naming
scenario_id "spx-structure-v1", instrument "SPX", and "Observation date: none
(synthetic)". The always-visible summary states current availability is shown in
TAPE.
FAIL: any of the five surfaces (collapsed summary, expanded heading, ladder
visible label, ladder accessible name, provenance block) omits synthetic/
reference identity, or the provenance block omits scenario_id, instrument, or
the null observation date.

R3 — Structural carrier separation from production GEX
The reference is carried by a distinct immutable GexReference type via
build_reference / render_reference_fragment in gex_reference.py, rendered under
data-gex-kind="reference", and the bundled JSON envelope contains
reference_schema_version, kind "synthetic_reference", scenario_id, instrument,
observation_date null, authoring basis SHA and helper path, synthetic source
text, and frozen numeric inputs. The envelope contains NONE of the production
identity fields schema_version, source, data_delay, fetched_at_utc, or any
production lineage/readiness identifier.
FAIL: the reference reuses the current card wrapper unchanged, emits id
"gex-context", omits data-gex-kind="reference", or the bundled JSON contains any
of the named production identity fields.

R4 — Two-way carrier rejection (no laundering)
Passing the complete reference envelope to current admission (build_gex_card) is
rejected (returns no current card). Passing any production snapshot — fresh,
stale, or invalid — to reference admission (build_reference) is rejected.
Renaming kind or removing a required provenance field rejects the reference with
no fallback.
FAIL: current admission accepts the reference envelope, reference admission
accepts a production snapshot, or a kind-rename / missing-provenance input yields
a rendered reference card.

R5 — No live-current implication
The reference instrument is SPX and its example spot is the frozen scenario spot
(7747.71), never today's SPY price. The reference subtree contains no current
timestamp, no "Cboe ~15m delayed" or as-of footer, no dealer-positioning /
support / resistance / magnet / pin / prediction language, and no SPY overlay.
FAIL: the reference subtree contains a current timestamp, a Cboe/as-of live
footer, any current SPY price value, or any of the prohibited directional/
predictive terms.

R6 — Current GEX path is byte-unchanged
With the reference present, current GEX behavior is identical to base: TAPE GEX
state derives only from the current artifact (:3150-:3162), the current detail
card is still conditionally emitted inside DETAILS (:3567-:3575), and
build_gex_card / render_fragment produce byte-identical output to the pinned
baseline for the same inputs and clock. Existing freshness (24h max age, 5m
future skew), validation, and suppression behavior are unchanged; no
mode/allow_stale/skip_validation flag is introduced.
FAIL: any current GEX fragment byte differs from baseline for identical inputs,
TAPE GEX state changes with reference presence/absence, or a
freshness/validation/suppression check is relaxed or bypassed.

R7 — Semantic isolation from all decision surfaces
Across TRADE, NO_TRADE, HALT, locked, zero/single/multiple setups, and
low-tier-primary fixtures, changing the reference data or its
availability leaves verdict, trade permission, grades, ordering, primary/chart
slot, sizing, alerts, readiness, regime, payload/run/contract inputs, MANUAL
CHECK, and WATCHING bytes unchanged. No reference dependency is imported by any
upstream/decision module.
FAIL: any listed decision/output byte changes when only reference data or
reference availability changes, or any non-delivery module imports gex_reference.

R8 — Fail-loud on invalid or missing reference
A missing resource, malformed JSON, wrong kind/instrument/scenario, boolean/NaN/
non-finite number, or aggregate/anchor contradiction yields the labeled
disclosure showing "Reference example unavailable." with no numbers and no
ladder, and NO fallback to logs, provider, network, or another fixture. Build
validation catches an invalid bundled resource before merge.
FAIL: an invalid/missing reference renders numeric content, falls back to any
other source, or silently omits the labeled disclosure; or the build validation
does not fail on a corrupted resource.

R9 — Geometry reuse without duplication or drift
The reference reuses the existing gex_card.py profile (31 half-open 25-point
bins, coverage, outside mass, raw-strike anchors), grayscale SVG ladder with its
own spot rail, and accessible full-bin table via minimal pure helper factoring.
No second geometry implementation is added.
FAIL: a duplicate profile/ladder/table implementation is introduced, or the
existing geometry tests (bins, boundary ties, outside mass, grayscale, table
parity) regress.

R10 — Markup class constraint at the seam
The new <details id="gex-reference"> does NOT use class="block operator-zone", so
the count of class="block operator-zone" elements before #details-history remains
exactly 4.
FAIL: test_prd318_four_full_weight_zones_before_details observes other than 4
class="block operator-zone" elements before details-history.

R11 — Narrow AST-isolation extension
test_gex_isolation_ast (tests/test_dashboard_renderer.py:4809-4835) is extended
ONLY to permit gex_reference.py as a gex_card importer and to keep gex_snapshot
references confined to the existing ("gex_card.py", "dashboard_renderer.py") set
(gex_reference.py must not reference gex_snapshot). No other loosening.
FAIL: gex_reference.py references gex_snapshot, gex_reference.py imports any
cuttingboard.* beyond gex_card, or the allowlist is widened beyond the single
new consumer.

R12 — Browser / mobile acceptance
At Chromium 1280x960, 390x844, and 360x780 (device-metric innerWidth asserted):
in default, reference-open, table-open, all-disclosures-open, each-setup-
selected, and SPY-LEVELS-toggled states, scrollWidth <= innerWidth (no page
horizontal overflow), no clipped labels/numbers, MANUAL CHECK position
unchanged, native keyboard (Enter/Space) opens the disclosure with visible
focus, summary touch height >= 44px, exactly the pre-existing single script, and
no new network requests or console errors.
FAIL: scrollWidth > innerWidth at any tested viewport/state, a summary touch
target < 44px, a second script appears, a new request/console error occurs, or
MANUAL CHECK position changes.

R13 — Bounded, reviewed oracle rebaseline
The D2 below-seam hashes (tests/test_dashboard_d2_seam.py) and the GEX and A1-C
dashboard goldens are regenerated THROUGH the renderer in a dedicated reviewed
step; the legacy oracle tests/data/setup_chart_legacy_oracle.json and all
upper-region / WATCHING assertions are unchanged; no assertion is removed or
weakened.
FAIL: setup_chart_legacy_oracle.json changes, any golden is hand-edited rather
than renderer-regenerated, or any upper-region/WATCHING/legacy assertion is
removed or weakened.

DATA FLOW
cuttingboard/delivery/data/gex_reference_v1.json (bundled, frozen synthetic SPX)
-> gex_reference.build_reference (strict envelope + numeric validation, immutable
GexReference) -> gex_reference.render_reference_fragment (reused gex_card pure
geometry helpers, data-gex-kind="reference") -> dashboard_renderer emits one
<details id="gex-reference"> at the WATCHING->DETAILS seam. The current GEX path
(gex_snapshot -> build_gex_card -> render_fragment -> TAPE / DETAILS card) is a
fully independent chain and is not read, written, or altered by the reference
chain.

  from current fixture. (R6)

  rejected with no fallback. (R4)

  with different current SPY/macro inputs yields identical reference bytes;
  current expiry still follows its injected clock. (R5, R6)
- Invalid reference matrix: missing / malformed / wrong kind-instrument-scenario
  / non-finite / contradictory yields reference-unavailable copy, no numbers, no
  fallback, current path unchanged. (R8)
- Semantic isolation across the fixture set: verdict/permission/grades/order/
  primary/chart/sizing/alerts/readiness/regime/payload/run/contract/MANUAL CHECK/
  WATCHING bytes unchanged under reference-only changes; dependency guard forbids
