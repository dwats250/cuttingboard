WHY NOW
Dustin's authorization message (this session, 2026-08-03) is the
design-direction ruling and Gate A. Origin: the product-rescue seam
inspection this session, which found that the dashboard already
computes a fully-precedented, already-tested trader-facing reason
string (`_ctx_reason`, `dashboard_renderer.py:2317-2339`) but never
surfaces it as its own labeled line -- it is folded into the
`.sys-context` regime line instead. Classified NOT MATERIAL per GOV-2
§1 (no new schema/contract/governance change, no new cross-layer seam,
no tracked finding resolved, presentation-only reuse of an already-
authoritative value, stays within dashboard/delivery). LANE is
HIGH-RISK regardless of diff size: `dashboard_renderer.py` is a
HIGH-RISK FILE for CLASS CONSUMER (same basis as PRD-279/PRD-280).

This PRD supersedes, for this one display behavior only, PRD-219's
narrow presentation choice that folded the stay-flat/halt reason into
the context line with "no separate Reason field" (see
`tests/test_dashboard_renderer.py` comments at the former
`test_permission_none_reason_in_context_line` /
`test_halted_state_reason_in_context_line`, and
`tests/test_dash_system_state.py`'s former
`test_system_state_reason_no_candidates` /
`test_system_state_reason_candidates_gated`). PRD-219's other
distillation choices -- one verdict line, one absolute timestamp, no
raw Permission field, no separate regime badge -- are untouched.

MAX EXPECTED DELTA
~25 production lines changed/added in `dashboard_renderer.py` (one new
`.sys-why` render block + CSS + a stripped `.sys-context` reason
clause); ~120 test lines across `tests/test_dashboard_renderer.py` and
`tests/test_dash_system_state.py` (existing assertions relocated, nine
new discriminating tests).

GOAL
Render the renderer's existing `_ctx_reason` value as a dedicated
`WHY: <reason>` line directly under the Decision State Header, reusing
its precedence unchanged, so `STAY FLAT` and `HALT` are immediately
explainable without a second, independently-derived reason source.

SCOPE
- Reuse `_ctx_reason` (`dashboard_renderer.py:2317-2333`, plus its
  existing `confidence=`/`(regime=...)` strip at 2335-2336) exactly as
  computed today. No new reason value, no new precedence branch inside
  that computation.
- Add one new line, `<div class="sys-why">WHY: {_ctx_reason}</div>`,
  inside `#system-state`, positioned immediately after the existing
  `.sys-verdict` line (2302-2303) and before `.sys-context` (2341) --
  i.e. visually bound to the Decision State Header block, above the
  regime context line.
- Suppress the WHY line (render nothing) when:
  - `_ctx_reason` is falsy (`None`), which already covers the
    TRADE-outcome / no-first_error / not-STAY_FLAT branch (2332-2333);
  - the decision state resolved to `STATE UNAVAILABLE` -- this
    includes `artifact_mixed=True` (`title == "MIXED_ARTIFACTS"`,
    2287-2291) and the existing R2-guarded exception fallback
    (2298-2299). This is a new guard: today `_ctx_reason` is computed
    and rendered into `.sys-context` without checking
    `_decision_state`/`artifact_mixed` at all, so a `NO_TRADE` outcome
    under mixed artifacts would otherwise still show a confident reason
    next to `STATE UNAVAILABLE`. The guard lives at the WHY-line render
    call site, not inside `_ctx_reason`'s own precedence.
- Strip the reason clause out of `.sys-context` (2337-2339): that line
  keeps only the regime phrase (`{_regime_plain} regime`); the ` · `
  reason suffix is removed. `.sys-context`'s halted-color class
  (2340) and the separate kill-switch context line (2342-2343) are
  unchanged.
- New CSS rule for `.sys-why` (near the existing `.sys-context` /
  `.decision-state` rules at 730-741), visually subordinate to
  `.decision-state` but more prominent than `.sys-context` (e.g. bold,
  same color family as the verdict).

OUT OF SCOPE
No new reason engine, taxonomy, field, or persisted schema. No change
to `_decision_title`, `_verdict_cls`, or the HALT / STAY FLAT / TRADE
PERMITTED / STATE UNAVAILABLE precedence (2286-2299). No change to
`_ctx_reason`'s own precedence order (halt reason > first_error > gated
setups > candidates gated > no qualified setups > None). No runtime,
output, notification, contract, pipeline, or schema file changes. No
broader dashboard redesign, no opportunity-survival summary, no
previous-state feature, no North Star or audit work.

REQUIREMENTS

R1 — The WHY line renders `WHY: {_ctx_reason}` verbatim (same string
that `.sys-context` renders today) whenever `_ctx_reason` is truthy AND
the resolved decision state is `HALT` or `STAY FLAT`.
FAIL: `system_halted=True` with `run.errors=["disk full"]` does not
render `WHY: disk full` (or any non-halted STAY FLAT case with a
computable `_ctx_reason` fails to render its matching WHY text).

R2 — The WHY line is absent (no `.sys-why` element in the output) when
the decision state is `TRADE PERMITTED`, when the decision state is
`STATE UNAVAILABLE` (including `artifact_mixed=True`), or when
`_ctx_reason` is `None`.
FAIL: a `TRADE PERMITTED` run renders a `.sys-why` element; OR an
`artifact_mixed=True` run with `outcome="NO_TRADE"` renders a `.sys-why`
element or any reason text (e.g. "no qualified setups") anywhere in the
`#system-state` block.

R3 — The reason text renders exactly once per page: present in
`.sys-why` per R1/R2, absent from `.sys-context`, whose content is
reduced to `{regime phrase} regime` only (no ` · reason` suffix), for
every case that previously showed a reason in `.sys-context`.
FAIL: `.sys-context`'s text still contains `no qualified setups`,
`candidates gated`, an `N setup(s) gated` string, `first_error` text,
or `stay_flat_reason` text for any fixture; OR the WHY-line reason
string and the `.sys-context` string both contain the same reason
substring on the same render.

R4 — The WHY line never leaks raw internals: no `(regime=`, no
`confidence=`, no literal `None`/`NULL` token.
FAIL: any WHY-line fixture with a `(regime=...)`-suffixed
`stay_flat_reason` or a `confidence=`-bearing string renders that raw
suffix inside `.sys-why`.

DATA FLOW
`run.system_halted` / `run.errors` / `run.outcome` /
`payload.sections.validation_halt_detail.reason` / `market_map` /
`alert_candidates` -> existing `_ctx_reason` precedence (unchanged,
2317-2336) -> new WHY-line guard (decision state / `artifact_mixed`
check, new) -> `.sys-why` render (new) and `.sys-context` render
(reason clause removed).

FAIL CONDITIONS
Each requirement's inline `FAIL:` line above is the complete, binary
condition for that requirement.

VALIDATION
Manual:
- HALT with `run.errors` set -> WHY shows the error text (R1).
- HALT with `errors=[]` and `validation_halt_detail.reason` set -> WHY
  shows the `stay_flat_reason` text (R1).
- Non-halt run with `run.errors` set (explicit refusal) -> WHY shows
  the error text (R1).
- `outcome=NO_TRADE`, no high-grade setups, no `alert_candidates` ->
  WHY shows "no qualified setups" (R1).
- `outcome=NO_TRADE`, `alert_candidates` non-empty, no high-grade
  setups -> WHY shows "candidates gated" (R1).
- `outcome=NO_TRADE`, N high-grade setups in `market_map` -> WHY shows
  "N setup(s) gated" (R1).
- `outcome=TRADE` -> no `.sys-why` element (R2).
- `artifact_mixed=True` (mismatched `generation_id`s), `outcome=
  NO_TRADE` -> no `.sys-why` element and no reason text anywhere in
  `#system-state` (R2).
- Every case above -> `.sys-context` contains only the regime phrase,
  no reason suffix (R3); no `(regime=`, `confidence=`, `None`, `NULL`
  substring anywhere in `.sys-why` (R4).
