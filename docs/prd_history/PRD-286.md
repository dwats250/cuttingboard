PRD-286 — Macro-pressure fail-closed: a macro-pressure COMPUTATION FAILURE must block, not silently degrade to "UNKNOWN" and allow full size (CB-05)

Status: DRAFT — awaiting Gate A (Stage-0 authored; production implementation NOT authorized). Registry status PROPOSED.

WHY NOW
`_compute_overall_pressure` (`runtime/__init__.py:1464–1471`) computes the macro
`overall_pressure` for the run by calling `_build_macro_drivers` and
`build_macro_pressure`. On ANY exception from either, it logs a warning and
returns the string `"UNKNOWN"` (`:1469–1471`) — the SAME value that
`build_macro_pressure` legitimately returns when macro data is merely absent
(`macro_pressure.py:93–96`, `_overall_pressure` returns `UNKNOWN` when every
driver component classifies to `UNKNOWN`). Execution policy then treats
`"UNKNOWN"` identically to `"NEUTRAL"` — allowed, unconstrained, full size
(`execution_policy.py:252–253`, `_apply_macro_pressure`:
`if pressure in ("UNKNOWN", "NEUTRAL"): return PolicyDecision(True, reason, size)`).

The result: a macro-pressure COMPUTATION FAILURE silently removes a live
blocking/sizing gate and lets trades through at full size, indistinguishable
from a run where macro pressure was successfully computed as "no directional
signal." Downstream consumers cannot tell the two apart, because nothing in the
system carries a "failed to compute" signal — the failure and the computed-
unknown collapse to the identical string `"UNKNOWN"` (`macro_pressure.py:95–96`
vs `runtime/__init__.py:1469–1471`). This violates VISION's
`description-not-prediction` (the system asserts an unconstrained macro read it
does not have) and `the-system-serves-the-trader` (a safety gate is silently
disabled by an error). This is CB-05.

GOAL
Distinguish a macro-pressure COMPUTATION FAILURE from a successfully computed
`UNKNOWN`, and make the failure fail-closed: when `_compute_overall_pressure`
cannot compute a pressure, execution policy blocks the affected decisions with a
distinct, truthful reason instead of allowing full size — while leaving computed
`UNKNOWN` (data merely absent), `NEUTRAL`, and every other pressure and gate
behavior exactly unchanged.

SCOPE
- Distinct failure sentinel (`cuttingboard/execution_policy.py`): add two module
  constants — `MACRO_PRESSURE_UNAVAILABLE = "UNAVAILABLE"` (the pressure-carrier
  sentinel that means "macro pressure could not be computed", distinct from the
  computed `"UNKNOWN"`) and `POLICY_MACRO_PRESSURE_UNAVAILABLE =
  "macro_pressure_unavailable"` (the block reason). Add
  `MACRO_PRESSURE_UNAVAILABLE` to `_VALID_PRESSURE_VALUES` (`execution_policy.py:38`)
  so `evaluate_execution_policy`'s guard (`:226`) accepts it and routes it to the
  macro stage rather than raising `ValueError`.
- Fail-closed predicate (`cuttingboard/execution_policy.py`,
  `_apply_macro_pressure` `:252–264`): add a branch AHEAD of the
  `("UNKNOWN", "NEUTRAL")` allow branch —
  `if pressure == MACRO_PRESSURE_UNAVAILABLE: return PolicyDecision(False,
  POLICY_MACRO_PRESSURE_UNAVAILABLE, 0.0)` — blocking regardless of direction.
  This reuses the EXISTING block mechanism (identical shape to the current
  `POLICY_MACRO_PRESSURE_CONFLICT` blocks at `:259,:263`); the decision becomes
  `BLOCK_TRADE` at `EXECUTION_POLICY` with the truthful reason.
- Fail-closed producer (`cuttingboard/runtime/__init__.py`,
  `_compute_overall_pressure` `:1464–1471`): on exception, return
  `MACRO_PRESSURE_UNAVAILABLE` (imported from `execution_policy`) instead of
  `"UNKNOWN"`; keep the warning log (reworded to state the fail-closed outcome).
  The success paths are unchanged — a successfully computed `"UNKNOWN"`,
  `"NEUTRAL"`, `"RISK_ON"`, `"RISK_OFF"`, or `"MIXED"` is returned verbatim.
- Unchanged by design: `build_macro_pressure` and its computed vocabulary/
  thresholds (`macro_pressure.py`) — computed `UNKNOWN` (drivers absent) stays
  `UNKNOWN` and continues to allow full size (existing intended behavior); the
  no-setups / halt / kill-switch `overall_pressure = "UNKNOWN"` defaults
  (`runtime/__init__.py:695,:978`) stay `"UNKNOWN"` (those paths gate no
  decisions and are not computation failures); the thesis, invalidation,
  explanation, and dashboard consumers (see CONSUMER CONSISTENCY).

OUT OF SCOPE
- Any change to `build_macro_pressure`, its thresholds, `_classify_driver`,
  `_overall_pressure`, or the computed `{RISK_ON, RISK_OFF, MIXED, NEUTRAL,
  UNKNOWN}` vocabulary. The fix adds a runtime-boundary sentinel; the computation
  is untouched.
- Any change to computed-`UNKNOWN` or `NEUTRAL` handling (both remain full-size
  allow). The defect is ONLY that a FAILURE masquerades as computed-`UNKNOWN`.
- The dashboard's independent `_build_pressure_snapshot`
  (`delivery/dashboard_renderer.py:1454–1460`), which already fails soft to
  `None` ("Macro pressure unavailable") on its own separate path and does NOT
  read runtime's `overall_pressure`. It is a parallel, non-decision surface; not
  in this slice (declared, not touched).
- A sidecar, service, persisted failure-flag schema, or new contract field. The
  sentinel is a transient policy input (never persisted); the reason is a new
  value on the existing free-string block-reason carrier.
- Reducing size (rather than blocking) on failure: rejected as not fully
  fail-closed — a reduced-size allow still trades on macro conditions that could
  not be assessed. Blocking is the smallest truthful fail-closed behavior.
- Letting the exception propagate to abort the whole run: rejected as broader
  than the gate — it would blank the entire pipeline (dashboard, non-macro
  info) rather than block the affected decisions. Blocking the decisions is the
  surgical fail-closed supported by the existing macro-gate architecture.
- CB-04 / PRD-285 brake dormancy and PRD-284 sizing: distinct, already-landed
  seams; not touched.

REQUIREMENTS

R1 — Computation failure yields the distinct sentinel, not "UNKNOWN"
When `build_macro_pressure` (or `_build_macro_drivers`) raises,
`_compute_overall_pressure` returns `MACRO_PRESSURE_UNAVAILABLE` (`"UNAVAILABLE"`),
never `"UNKNOWN"`.

FAIL: A `_compute_overall_pressure` call whose `build_macro_pressure` raises
returns `"UNKNOWN"` (or any value other than `"UNAVAILABLE"`).

R2 — Computed UNKNOWN is unchanged (distinction preserved)
When `build_macro_pressure` returns a genuinely computed `"UNKNOWN"` (all
drivers absent, no exception), `_compute_overall_pressure` returns `"UNKNOWN"`,
and execution policy allows at full size exactly as before.

FAIL: A drivers-absent computed `"UNKNOWN"` run returns `"UNAVAILABLE"`, or its
decisions are macro-blocked.

R3 — Unavailable pressure blocks, direction-agnostic
`_apply_macro_pressure` (and thus `evaluate_execution_policy` /
`apply_execution_policy`), given `overall_pressure == "UNAVAILABLE"`, returns a
BLOCK for both LONG and SHORT: `status == BLOCK_TRADE`,
`block_reason == policy_reason == "macro_pressure_unavailable"`,
`decision_trace == {stage: EXECUTION_POLICY, source: execution_policy, reason:
macro_pressure_unavailable}`, `size_multiplier == 0.0`.

FAIL: An otherwise-allowed LONG or SHORT decision with `"UNAVAILABLE"` pressure
returns `ALLOW_TRADE`, full size, or a reason other than the exact literal
`macro_pressure_unavailable`.

R4 — The sentinel is a valid pressure value (no crash), unknown strings still raise
`"UNAVAILABLE"` is in `_VALID_PRESSURE_VALUES`, so `evaluate_execution_policy`
routes it to the macro block rather than raising; a genuinely unrecognized
pressure string (e.g. `"GARBAGE"`) still raises `ValueError`.

FAIL: `evaluate_execution_policy` raises on `"UNAVAILABLE"`, OR stops raising on
an unrecognized string.

R5 — Every other gate and pressure behavior unchanged
`NEUTRAL`, `MIXED`, `RISK_ON`, `RISK_OFF`, computed `UNKNOWN`, the confidence/
regime/posture/ORB gates, PRD-284 sizing, and PRD-285 dormancy all behave
exactly as before; `POLICY_MACRO_PRESSURE_CONFLICT` is unchanged.

FAIL: Any existing `test_pressure_*` assertion (UNKNOWN/NEUTRAL/MIXED/RISK_ON/
RISK_OFF/conflict) changes result, or another gate's behavior changes.

R6 — No ALLOW_TRADE coexists with an unavailable read (consumer consistency)
On a computation-failure run, every otherwise-allowable decision is
`BLOCK_TRADE(macro_pressure_unavailable)`, so the thesis/invalidation/explanation
gates build no macro derivation from `"UNAVAILABLE"` (no
`catalyst="macro:UNAVAILABLE"`, no guidance embedding the sentinel, no false
alignment), and no consumer represents the failed read as a computed pressure.

FAIL: A failed-macro run produces a thesis `catalyst` or invalidation `reason`
containing `"UNAVAILABLE"`, or any `ALLOW_TRADE` decision on that run.

MALFORMED / MISSING-DATA BEHAVIOR
- Missing macro data (all driver blocks absent/None) is NOT a failure:
  `build_macro_pressure` computes `"UNKNOWN"` deterministically
  (`macro_pressure.py:57–63,93–96`) and the run allows at full size — unchanged.
- Malformed macro data (non-dict container, non-numeric/non-finite field,
  invalid enum) IS a failure: `build_macro_pressure` raises `ValueError`
  (`macro_pressure.py:38,44,49,51,53,124,135`) → caught → sentinel → block.
  Fail-loud is honored at the decision gate (an explicit BLOCK with a truthful
  reason), not silent-fallback (PRD-198 #1). The removed behavior is the silent
  substitution of `"UNKNOWN"`; nothing new fails silently.
- The `except Exception` breadth is retained deliberately: any unforeseen
  computation failure now fails CLOSED (block) rather than open (allow). The
  warning log is kept for observability (PRD-198 #1 spirit — the failure is
  recorded, not swallowed).
