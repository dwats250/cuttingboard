PRIMARY CHART VISIBILITY IS OBSERVATIONAL AND DOES NOT GRANT OR IMPLY TRADE
PERMISSION.

OPEN OWNER DECISION D1-Q1 — the C-grade canonical primary (REQ-1)
`select_primary_card_symbol` admits grade C (`primary_selection.py:35-39`),
so when no A+/A/B symbol is chartable the canonical primary is a C-grade card,
and the renderer emits that card inside `<details class="tier-group"
id="tier-c">` (`dashboard_renderer.py:3186-3187` at base). No change inside
`_render_candidate_card` can make that chart visible. The ruling says
"whenever a valid primary setup/chart exists" and also excludes C/D tier
redesign; the two cannot both hold for a C-grade primary. This is an owner
call. Both options are fully specified so the ruling is one word:

  OPTION A (author's recommendation): when a low tier's `tier_syms` contains
  `_primary_card_symbol`, emit that tier's wrapper as
  `<details open class="tier-group" ...>` (one attribute at
  `dashboard_renderer.py:3186`, roughly 3 net LOC in `render_dashboard_html`).
  The tier stays a collapsible disclosure; it merely starts open on the render
  where it holds the canonical primary. R10's cone gains exactly this hunk;
  R1 gains the C-grade assertion below; the depth walker treats `<details
  open` as non-hiding (or a direct attribute assertion is used).

  OPTION B: narrow "valid primary" for D1 to a primary whose tier renders as a
  plain div (grades A+, A, B). A C-grade primary keeps today's presentation
  (chart behind LEVEL MAP inside the collapsed tier) until candidate-row work.
  No code beyond `_render_candidate_card`; R1 applies to high-grade primaries
  only; FOLLOW-UP F1 records the residue.

Until D1-Q1 is ruled, this PRD is HELD: no Gate A can be requested and no
implementation may begin. Every other requirement below is written to be valid
under either option; the option-specific text is marked [A] / [B].

REQUIREMENTS

R1 — Primary chart undisclosed in every decision state
When the card whose symbol equals the renderer's `select_primary_card_symbol`
result produces a non-empty chart SVG (daily, or admitted intraday per
PRD-324), `_render_candidate_card` emits `<div class="setup-chart">` and its
`chart-caption` as direct children of that card, with no `<details` token
between the card's opening `id="card-<SYM>"` tag and that chart, under every
decision state: TRADE PERMITTED, STAY FLAT, OBSERVE ONLY (operator lock),
HALT (locked or unlocked), and STATE UNAVAILABLE. The chart keeps its current
position in the card (after the IN/OUT couplet and the DETAIL disclosure,
before the LEVEL MAP disclosure), which is where it already renders on a
permitted card. [A] When the primary is C-grade, its tier wrapper carries the
`open` attribute so the card and chart are visible on load. [B] R1 binds for
A+/A/B primaries; a C-grade primary is out of D1.
FAIL: for any non-permitted render with a chartable A+/A/B primary, the
substring between `id="card-<primary>"` and the first `class="setup-chart"` in
that card contains `<details`; OR `_charts_by_details_depth` on a
two-high-grade-symbol non-permitted render is not exactly `[0, 2]` (primary at
0, secondary behind `level-detail` then `chart-detail`); OR [A] a C-only
chartable map renders `<details class="tier-group" id="tier-c">` without
`open`, or its chart has a `<details` (other than that open tier wrapper)
between the card tag and the chart.

R3 — Existing neutral chart presentation on the one newly exposed surface
`_render_candidate_card` derives one local boolean,
`chart_neutral = operator_locked or (chart_slot_available and not
decision_permitted)`, and passes it as the `operator_locked` argument to the
two `render_setup_chart_svg` calls only. Effect: the primary-slot chart on any
non-permitted render (STAY FLAT, NO TRADE, unlocked HALT, lock) uses the
PRD-304/PRD-321 lock presentation (LEVEL / INVALIDATION words, `#6b7280`, no
`#e0a552` / `#e05252`) whenever a contract entry/stop is present. For every
non-primary card `chart_neutral == operator_locked`, so their bytes are
unchanged. Locked renders are unchanged (already neutral). Permitted renders
are unchanged (`chart_neutral == operator_locked` there too). The ladder call
and every other `operator_locked` consumer (IF NOW, PLAY, couplet labels,
`.value-actionable`, tier labels) stay keyed on `operator_locked` alone.
Reachability: the renderer accepts `contract_entry_map` / `contract_stop_map`
independently of permission (`_load_contract_entry_context`,
`dashboard_renderer.py:3810`), and an unlocked HALT is reachable through
`system_halted=True` with a non-lock permission string (lock derivation at
line 2498).

with `contract_entry_map` and `contract_stop_map` set shows `>ENTRY ` or
`>STOP ` or `#e0a552` or `#e05252` inside the primary card's SVG; OR the same
render's secondary card, primary ladder fragment, IF NOW, PLAY, IN → / OUT →
