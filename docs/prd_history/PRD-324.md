R2 -- Nested consumer admission (C4; defensive read of a possibly-corrupted file)
Beyond the top-level envelope, the consumer admits a symbol's bars only if the
persisted content it consumes is well-formed: `schema_version == 1`; `source`
matches the shipped producer contract by EXACT VALUES --
`source.producer == "hourly"`, `source.provider == "yfinance"`,
`source.interval == "1m"`, `source.adjusted == false` (not merely the key shape);
`columns == ["ts","Open","High","Low","Close","Volume"]`; `primary_symbol`
present (string or null); the symbol entry is `{through,row_count,bars}`;
`row_count == len(bars)`; `through == bars[-1][0]`; every bar row has six cells with
a tz-aware parseable `ts`, strictly ascending `ts`, and finite coherent OHLCV
(`High>=max(Open,Close)`, `Low<=min(Open,Close)`, positive prices, a numeric
integer-valued `Volume>=0`); and, mirroring the producer's per-bar guarantee
(`runtime/__init__.py:2698` drops the whole symbol if any bar's ET date differs
from the snapshot's session date), EVERY admitted bar's ET-normalized date must
equal the snapshot's TOP-LEVEL `session_date` (not a per-entry field; symbol
entries hold only `through`/`row_count`/`bars`). Any violation omits the WHOLE
symbol (=> daily fallback).
This is consumer-side defensive admission of a possibly-corrupted persisted file;
it adds no new PRODUCER guarantee and never raises.
FAIL: the consumer renders intraday from a sidecar with a wrong `schema_version`,
any wrong `source` value (`producer`/`provider`/`interval`/`adjusted`), wrong
`columns`, `row_count`/`through` mismatch, malformed bar row, non-integer/negative
`Volume`, incoherent OHLCV, or any bar whose ET date != the top-level
`session_date`; OR any such nested defect raises instead of falling back to daily.

R3 -- Freshness / session admission, ET-normalized and DST-safe (C3)
All comparisons occur after normalizing `now`, `generated_at`, `through`, and each
bar `ts` to ET via `ZoneInfo("America/New_York")` (reusing `time_utils` endpoints
`_MARKET_OPEN_ET = 09:30`, `_MARKET_CLOSE_ET = 16:00`; all inputs are tz-aware, so
this is deterministic across EDT/EST). A symbol is admitted only if:
- `session_date` == the current ET regular-session date of `now`;
- `generated_at` age = `now - generated_at`, admitted iff `0 <= age <= 90 min`
  (the lower bound rejects a future `generated_at`; this future-reject is an A1-C
  CONSUMER-SIDE STRENGTHENING beyond packet Section 6, labeled as such, NOT
  verbatim);
- per-symbol `through`: `now - through <= 90 min` AND `through <= now + 5 min`
  (future-skew tolerance) AND `through` falls within `[09:30, 16:00)` ET on
  `session_date`.
Boundaries are inclusive at 90 min and 5 min. A missing/naive/unparseable
`generated_at`/`session_date`/`through` omits the symbol.
FAIL: a symbol is admitted with `session_date` != current ET session, `generated_at`
age > 90 min or in the future, `through` age > 90 min, `through` > `now + 5 min`, or
`through` outside the ET regular session; OR any comparison is done without ET
normalization; OR a naive/unparseable field admits instead of omitting.

R4 -- Source timestamp semantics FROZEN (C1)
A1-P persists each 1m bar START-labeled (ts = the bar's OPENING minute) in UTC,
tz-aware, raw from the yfinance index (`runtime/__init__.py:2716`; UTC via
`ingestion.py:258-260`; START-label corroborated by fixture
`tests/fixtures/orb_reference_sample_intraday.csv` first row `09:30:00` and the
09:30 `between_time` windowing). The consumer treats each bar's ET-normalized
minute as its START label. This is an explicit, evidence-based ASSUMPTION (a
provider convention, not a fetch-time invariant); the completeness rule (R5) is
membership-based so it is robust to the label and rejects any misaligned minute.
FAIL: the derivation interprets the 1m ts as END-labeled or in a non-ET frame, or
anchors bins anywhere other than 09:30 ET.

R5 -- Deterministic, membership-complete 5m derivation (C1/C2/C5)
5m bins are 09:30-ET-anchored and half-open: bin k covers ET START-labels
`{09:30+5k, 09:30+5k+1, 09:30+5k+2, 09:30+5k+3, 09:30+5k+4}` =
`[09:30+5k, 09:30+5(k+1))`. A bin is a COMPLETED candle only if ALL FIVE expected
START-labeled minute bars are present. This is a DELIBERATELY STRONGER
display-integrity rule than the shipped ORB logic: A1-C requires the exact expected
source-minute membership for each rendered 5m candle. The existing ORB
implementations use their own inclusive/minimum-count semantics
(`intraday_state_engine.py:128,135` uses inclusive `09:30 <= t <= 09:35` and rejects
only `len < 5`; `watch.py:39` `ORB_MIN_BARS = 5` over the same inclusive window) and
are NOT the normative contract for A1-C's aggregation; A1-C does not change any ORB
production behavior. A missing interior minute drops that bin. No synthetic OHLC, no
forward-fill, no partial bin.
For a completed bin: O = first (09:30+5k) Open, H = max High, L = min Low, C = last
(09:30+5k+4) Close, V = sum Volume. The candle DISPLAY label is the bin START as ET
`"HH:MM"` (flows through `setup_chart._day_label` short-string passthrough). The
derivation is pure and deterministic: identical 1m input yields byte-identical 5m
output; no provider call.
FAIL: a 5m bin renders with a missing interior minute; OR aggregation uses any rule
but first-Open/max-High/min-Low/last-Close/sum-Volume; OR a partial/in-progress bin
renders; OR the same input yields two different outputs.

The proof is NOT leaf-versus-a-reconstruction-of-itself.

R10 -- Honest caption / provenance (C6/C7)
The intraday caption states the ET `session_date` and the COMPLETED-CANDLES-THROUGH,
defined as EXACTLY ONE value: the END / RIGHT EDGE of the last completed admitted 5m
bin (for a last bin `[09:30+5k, 09:30+5(k+1))`, its right edge `09:30+5(k+1)` ET).
This is a CONCEPTUALLY SEPARATE provenance field from both (i) the raw/source
`through` -- the timestamp of the final admitted 1m source bar (START-labeled under
the verified source convention, R4) -- and (ii) the candle's bin-START display label
(R5), which represents the bin's opening minute. There is NO FIXED NUMERIC ORDERING
between the raw source `through` and the completed-candles-through END: the raw
`through` may be EARLIER than, EQUAL to, or LATER than that END, depending on whether
the source ends inside, exactly on, or beyond the most recent completed-bin boundary
(e.g. START-labeled bars ending at 09:34 with a complete `[09:30,09:35)` bin give raw
`through` 09:34 < END 09:35; a 09:35 bar present gives them equal; a later partial bin
gives raw `through` > END). The caption/provenance must label each field's meaning
honestly and must not imply an ordering. The caption shape is deterministic (a fixed
template over `session_date` and the completed-through END) so tests pin it with at
least two session/through values, including one where the source `through` and the
completed-through END differ.
The daily fallback keeps its existing caption.
FAIL: the intraday caption states the raw source `through` (or the bin-start label)
as the rendered coverage, misstates `session_date` or the completed-through END,
conflates the completed-through END with the display label, or is shown on the daily
fallback.
