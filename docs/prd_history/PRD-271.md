CURRENT-MAIN PROVENANCE AND EXACT VERIFIED DEFECT (bd0401cb)
────────────────────────────────────────────────────────────────────────

Two independent, co-present defects, both current and both re-verified in this
reconciliation against `bd0401cb`. `cuttingboard/watch.py` and
`cuttingboard/ingestion.py` are BYTE-IDENTICAL between `15b2819` (scaffold
reference) and `bd0401cb` (`git diff 15b2819 bd0401cb -- <file>` empty for
both), so the mechanism has not drifted — only the scaffold's description was

DEFECT 1 — Positional mid-session ORB (the "opening range" is not the open).
`cuttingboard/watch.py:164-166` computes ORB as `orb_slice = bars[:N_RANGE]`
(`N_RANGE = 5`, `watch.py:28`) — the first five bars **of an already
tail-truncated window**, not of the session:
  - `cuttingboard/ingestion.py:207` returns `frame.tail(120)`.
  - `cuttingboard/watch.py:357` truncates again: `frame.tail(MAX_INTRADAY_BARS)`
    (`MAX_INTRADAY_BARS = 120`, `watch.py:30`). This second truncation is the
    effective one for any injected full-session frame (the default fetcher
    already returns ≤120).
A retained regular session (ET `between_time("09:30","15:30")`,
`ingestion.py:199`) is 361 one-minute bars. After `tail(120)`, `bars[0]` is at
minute index 241 ≈ **13:31 ET**, so `orb_high`/`orb_low` describe a ~13:31–13:35
window on every session long enough to exceed the 120-bar cap. The 09:30 open
is first evicted from the retained window at ~11:30 ET (bar 121); the full
09:30–09:34 formation window is gone by ~11:34 ET — so the defect bites on
roughly every full session past late morning. Wrong by construction, silent, no fail-loud path
(PRD-198 invariant 1). REPRODUCED TWICE independently (see EVIDENCE).

DEFECT 2 — No session provenance on the intraday layer.
Neither `IntradayBar` (`watch.py:52-59`) nor `IntradayMetrics`
(`watch.py:62-79`) carries a trading-date / session token; ORB is defined
purely positionally. `_bars_from_df` (`watch.py:356-371`) coerces every bar
timestamp to UTC (`pd.to_datetime(frame.index, utc=True)`) and trusts whatever
rows the fetcher returned — it re-derives and validates nothing.
`fetch_intraday_bars` DOES pin to a single trading date —
`latest_date = frame.index[-1].date(); frame = frame.loc[frame.index.date ==
latest_date]` (`ingestion.py:202-203`) — BUT `latest_date` is "the date of the
last bar yfinance returned," never compared to the intended current session or
to `time_utils.most_recent_completed_session_date` (`time_utils.py:37-55`), and
there is **no intraday freshness/staleness gate** (the PRD-193 freshness check
`_is_fresh_ohlcv_cache`, `ingestion.py:147-167`, guards only the DAILY OHLCV
cache). Consequently a stale prior-session frame (holiday run, pre-open run,
data lag) is returned as "current," its ORB flows to the execution gate and the
dashboard, and only the run-clock `session_date` string (`contract.py:124`,
from `date_str`) is stamped anywhere — a provenance mismatch nothing detects.

WHY IT MATTERS BEYOND DISPLAY
ORB is not display-only. It feeds the `orb_inside_range` **BLOCK_TRADE** gate in
`cuttingboard/execution_policy.py` (constant `POLICY_ORB_INSIDE_RANGE`,
`execution_policy.py:31`; gate at `execution_policy.py:254-256`; logic in
`_evaluate_orb_constraint`, `execution_policy.py:283-302`). A wrong or
wrong-session opening range can both block trades that should pass and pass
trades that should block, and the same values are rendered as dashboard key
levels and report lines.

────────────────────────────────────────────────────────────────────────
SESSION-IDENTITY MODEL (recommendation — Dustin rules at Gate A)
────────────────────────────────────────────────────────────────────────

Authoritative session identity for an ORB observation is the tuple:
  - `trading_date` — the ET calendar date the 09:30 open belongs to, derived
    from the ORB-forming bars' own ET timestamps (NOT from the run clock).
  - `market_session` — the regular session (09:30–16:00 ET); ORB formation
    window 09:30–09:35 ET (mirroring `intraday_state_engine._ORB_START/_ORB_END`).
  - `timezone` — `America/New_York` (already the canonical literal).
  - `observed_at_utc` — the UTC timestamp of the latest bar contributing to the
    observation (bars are already UTC-aware).

Validity requires `trading_date` to equal the run's intended current session
(reconciled against `most_recent_completed_session_date` / `date_str`). A
mismatch is a provenance failure, not a silently-accepted substitution.

────────────────────────────────────────────────────────────────────────
ORB LIFECYCLE STATE TABLE (recommendation)
────────────────────────────────────────────────────────────────────────

| State                 | Entry condition                                          | orb_high/low | Decision-surface behavior                                                        |
|-----------------------|----------------------------------------------------------|--------------|----------------------------------------------------------------------------------|
| PRE_OPEN              | No regular-session bar for the current trading_date yet  | absent       | ABSTAIN: no ORB signal; gate treats as ORB-unavailable (no block); NOT a failure |
| FORMING               | Current trading_date, <5 bars in 09:30–09:35 ET window   | absent       | ABSTAIN (same as PRE_OPEN); distinct label for observability                     |
| FORMED                | Current trading_date, ≥5 bars in 09:30–09:35 ET window   | immutable    | Live: ORB gate + zones + report use the session-true values                      |
| UNAVAILABLE           | Formation bars lost from retained window (trunc./gap)    | absent       | ABSTAIN with reason; Charter I4 — never relabel a formed ORB as AGED_OUT; no positional fallback |
| INVALID (fail-closed) | Session mismatch, malformed/NaN bars, or stale session   | REJECTED     | FAIL CLOSED: emit no ORB values; reason distinct from "not yet available"; never influence the gate as valid |

Distinctions the current code cannot make and the remedy must: **FORMED vs
UNAVAILABLE vs INVALID**, and **"not yet available" (normal) vs "invalid"
(fail-closed)**.

DIRECT-PATH BEHAVIOR (execution gate):
  - FORMED + session-valid: gate evaluates LONG/SHORT vs session-true ORB
    (`execution_policy.py:297-302`) exactly as today, but on correct values.
  - PRE_OPEN/FORMING/UNAVAILABLE: `orb_state` carries no ORB → existing
    `POLICY_ORB_UNAVAILABLE` allowed-but-flagged path (`:289-295,258`) — no
    hard block, no invented values.
  - INVALID: must map to a fail-closed reason, NOT to `orb_unavailable`'s
    allow-path — a session-mismatched ORB must not silently pass the gate.

CONTINUATION-PATH BEHAVIOR:
  - The `continuation_breakout` bypass (`execution_policy.py:287`) is retained:
    a CONTINUATION entry legitimately skips the ORB-inside-range block. Session
    provenance still governs any ORB **value** rendered on that path (zones,
    report), and an INVALID-session ORB must not be displayed as current. An ORB
    formed earlier in the SAME session MAY be reused on continuation/watch paths
    provided provenance confirms the same `trading_date`.

PRE-ORB BEHAVIOR:
  - Before the 09:30–09:35 window completes, ORB is NOT_YET_AVAILABLE — a normal
    state, not a system failure. Consumers abstain; the pipeline does not error.
    This mirrors `intraday_state_engine`'s `None`-before-09:45 discipline.

STALE / MALFORMED / SESSION-MISMATCH BEHAVIOR:
  - Stale prior-session ORB: FAIL CLOSED — reject; never present as current.
  - Malformed/NaN bars in the window: FAIL CLOSED — emit no ORB.
  - Session mismatch (trading_date ≠ intended session): FAIL CLOSED — reason
    distinct from unavailable.
  - Insufficient bars: FORMING (during window) or UNAVAILABLE (after window if
    data lost) — never positional fallback.

SCHEMA DETERMINATION
────────────────────────────────────────────────────────────────────────
