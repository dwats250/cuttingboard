WHY NOW
CANDIDATE, per the 2026-07-26 DECISIONS ruling on review-artifact replacement. Two checks in tools/validate_prd_registry.py: (1) a COMPLETE PRD's review artifact must pin the commit recorded in the registry's commit cell, not merely some commit on the branch - PRD-273's review pinned a96f16f7 while the PR merged at 8ca1969; (2) a .review.<model>.md file must never be MODIFIED after its first commit - a superseded artifact is renamed to .review.<model>.superseded-<sha>.md and retained, so a closeout reading the working tree sees the full review arc. PRD-273's ACCEPT WITH EDITS artifact with ten blocking findings was overwritten in place by a clean ACCEPT of a different implementation; HEAD showed no trace. Both checks are diffable facts, not judgment calls. Each guard ships a red test (PRD-198 invariant 4).

ancestor of `main`; the commit that landed is `4a1cb22`. Left in place above

BLOCKED — DO NOT IMPLEMENT AS SKETCHED
Connector review of PR #174 found, and verification confirmed, that BOTH checks
above are defective as written and that the ruling's prescribed filename opens a
gate hole. Six constraints are recorded in `docs/DECISIONS.md` under the
2026-07-26 append-only ruling ("KNOWN CONSTRAINTS"). In summary:

- Check (1) compares a review SHA against a commit cell that holds `#NNN` for
  same-PR closeouts — unsatisfiable as specified (constraint 2).
- Check (2) cannot detect the PRD-273 incident it exists to prevent: the
  original artifact lived on an unmerged branch, so merged history sees the
  canonical path added once, never modified (constraint 3).
- Check (2) unqualified would also reject the DRIFT-CHECK repair `CLAUDE.md`
  mandates (constraint 4).
- The `.superseded-<sha>.md` name still matches the validator's live
  second-model glob for non-Claude models, so an obsolete review can satisfy
  the HIGH-RISK disposition gate (constraint 1).
- `.claude/skills/prd-review-claude/SKILL.md` currently instructs the inverse
  layout and would refuse the prescribed filename (constraint 5).
- Renaming silently redirects existing DECISIONS artifact links (constraint 6).

This PRD stays a CANDIDATE. Its status header reads IN PROGRESS because PRD-159
requires the Stage-0 scaffold to land with an IN PROGRESS registry row before
any implementation commit — that is the repo's convention, not a claim that
implementation has begun. Resolving the six constraints is design work that
precedes any FILES declaration here.
