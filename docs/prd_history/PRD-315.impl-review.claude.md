## Special falsification check: `_top_ids()` discrimination

Finding: **NOT a required edit** (non-blocking observation only).

`_top_block()` is genuinely depth-aware (correct nested-div depth walk).
`_top_ids()`'s docstring says "depth-aware sibling scan" but the mechanism
scans occurrences of the substring `class="block` and records the following
`id="..."`. I tested whether this is discriminating for CURRENT production
markup:

- Every `class="block` occurrence in the rendered dashboard is a genuine
  top-level dashboard block. On a maximal render (all conditional blocks, tiers,
  candidate cards, removed symbols, macro, red folder), all `class="block`
  occurrences sit at a single uniform DOM depth (histogram `{2: 10}`); none is
  nested deeper. The Candidate card sub-tree (its richest sub-content) contains
  zero `class="block"`.
- No nested/non-top-level element currently matches `class="block`, so `_top_ids`
  cannot pick up a phantom id and cannot corrupt the asserted sequence. The
  sub-element `cb-updated` (no `class="block`) is correctly skipped.
- Moving Candidate back to its old seam RELIABLY fails the order tests (executed,
  item 10 above). The realistic invalid ordering is caught.

Therefore the current tests cannot falsely pass an invalid PRD-315 ordering, and
per the review instruction a helper rewrite is not required merely because the
docstring is imprecise. Recommended (non-blocking, no action required for
landing): correct the `_top_ids` docstring, or make it structurally depth-aware,
to future-proof against a later markup that introduces a nested `class="block"`.
