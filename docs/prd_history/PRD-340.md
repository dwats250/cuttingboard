WHY NOW
Slice 1 produced, persisted, and protected the ONE canonical EffectivePermission (carrier
+ resolver + exclusive-writer boundary + fail-closed persisted read). That carrier is
currently INERT: nothing consumes it. Every authoritative channel still re-derives
execution permission from PROXIES — system_state.tradable (ui/app.js:90,122), regime →

reads the EP projection instead, the guarantee Slice 1 built is unrealized and AVAILABLE
cannot open. Slice 2 makes the projection load-bearing and closes the proxy re-derivation.

CORE INVARIANT (this slice)
Authoritative action wording (TRADE PERMITTED / IF NOW=TAKE / PLAY / A+ ACTIONABLE /
READY / directional LONG-SHORT permission / "N trades" / EXECUTION) is emitted by an
authoritative channel ONLY from a resolver-provenanced EffectivePermission, never from a
proxy. Rendering or writing an authoritative channel before an EP has been resolved is a
type/argument error (R1). The set of authoritative channels is CLOSED and registered
(R2); no code outside the resolver can construct an EP (R3 in-process) and no downstream
process can forge a persisted one (R3 cross-process, via Slice-1's exclusive writer + a
per-channel read-boundary validator); the proxies are removed from authoritative inputs
(R4); and any channel with an absent/invalid/prior-session/stale/unverifiable EP emits
UNAVAILABLE, never a proxy claim and never a retained prior grant (fail-closed).

GOAL
Make EVERY authoritative output channel consume the Slice-1 EffectivePermission
projection through an approved, EP-required interface, strip the decision-bearing proxies
from authoritative inputs, register the channel set as CLOSED, and fail every channel
closed to UNAVAILABLE when the EP is absent/invalid/stale — proven by structural CI tests
T1-T4 — WITHOUT changing the resolver/carrier/exclusive-writer (Slice 1) and WITHOUT
opening AVAILABLE.

REQUIREMENTS (each has a binary FAIL line)

R1 — Resolution-before-every-render/write, by signature
Every authoritative render/write function in the registry requires an EffectivePermission
parameter; render_report (output.py:293) no longer accepts the raw outcome:str (:300) as
its authority source. Because an EffectivePermission exists only after
resolve_effective_permission (R3), calling any authoritative channel before resolution is a
missing-required-argument / type error.
FAIL: any registered authoritative channel function can be called (type-checks / runs to an
authoritative output) without an EffectivePermission argument; OR render_report still derives
authoritative action wording from the raw outcome string.

R2 — Closed authoritative-channel registry
The authoritative output channels are a CLOSED, registered, finite set: (1) publish
(tools/ci_push_artifacts.sh); (2) Telegram send (output.py build_notification_message:1144 →
send_telegram:729); (3) Markdown report writer (runtime _write_markdown_report:2306 fed by
render_report:293); (4) HTML report writer (delivery/transport.deliver_html:22 →
delivery/html_renderer.render_html:15); (5) JSON payload writer
(delivery/transport.deliver_json:34, payload built by delivery/payload
.build_report_payload:46); (6) CLI stdout (delivery/transport.deliver_cli:44); (7) served
contract for the browser (ui/contract.json → ui/app.js derivePosture:87); (8) workflow
commit message (cuttingboard.yml:479-510 / hourly_alert.yml parity). Each channel requires an
EP (R1) and emits authoritative wording only through the approved interface. A structural
test (T2) enumerates the registry and asserts it is closed.
FAIL: a new authoritative writer (one that emits execution-permission wording) is added
outside the registry and CI stays green; OR any of the eight channels emits authoritative
wording without going through the registered EP-required interface.

R3 — Non-forgeable provenance (same-project trust boundary; NO crypto/MAC/secret)
In-process: EffectivePermission is constructed ONLY by resolve_effective_permission (the
guarded constructor — effective_permission._TOKEN / _mint / __post_init__:59-62 shipped in
Slice 1), confirmed by an AST import-boundary test that fails if any other module constructs
it or imports the action vocabulary. Cross-process: no integrity signature; the guarantee is
(a) the persisted authoritative carrier holds ONLY the resolved field with proxies stripped
(R4), (b) Slice-1's single exclusive writer (effective_permission.persist), and (c) a
per-channel read-boundary validator (built on admit_persisted:218) that fail-closes.
FAIL: a module other than resolve_effective_permission constructs an EffectivePermission
(or a look-alike accepted by a channel interface) and a test does not go RED; OR a channel
accepts a persisted/served projection that did not pass its read-boundary validator.

R4 — Strip proxies from authoritative renderers/carriers
The decision-bearing proxies — system_state.tradable-as-authority (ui/app.js:90/:122,
payload.py:70, transport.deliver_cli:54), regime posture-as-permission
(dashboard_renderer._regime_to_permission_verb:1875/:1928, TRADE PERMITTED :2045-2071),
grade/setup_state → if_now/TAKE (market_map.py:93/:197), candidate/top_trades-presence
(payload.py:82), the permission text tables (output.py / market_control_card.permission
:96/:126-129), watch execution-posture — are removed from authoritative render/write inputs
and from the authoritative persisted/served carrier. Evidence/ranking/posture/framing may
still be shown as NON-authoritative context; authoritative action wording derives ONLY from
the EP.
FAIL: any registered authoritative channel reads a proxy field to produce authoritative
action wording; OR the authoritative persisted/served carrier still carries a decision-
bearing proxy field as an authoritative source.

FAIL-CLOSED — every channel
When the EP is absent, malformed, prior-session, stale/expired, or fails its read-boundary
validator, the channel emits UNAVAILABLE (or its channel-specific no-action equivalent) and
NO action wording — never a proxy-derived claim, never a retained prior grant.
FAIL: any channel, given an absent/invalid/prior-session/stale EP, emits action wording, a
fabricated grant, a retained prior grant, or a proxy-derived claim (instead of UNAVAILABLE),
OR raises an unhandled exception.
