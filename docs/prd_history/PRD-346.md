WHY NOW
Every pipeline or hourly run dirties ten tracked generated files the helper does not restore, so `git status` after a run is never clean and a session must hand-sort generated dirt from real edits (PROJECT_STATE has recorded this as known debt since July). The 2026-09-18 session hit it directly: the closeout skill's clean-tree preflight could not be satisfied because `git stash`/`git checkout` are denied to agents and the helper left the dirt behind.

MAX EXPECTED DELTA
`scripts/clean_generated_artifacts.sh` <= 12 lines (ten array entries plus comment); new `tests/test_clean_generated_artifacts.py` <= 90 lines; `docs/PROJECT_STATE.md` known-debt note retired (pointer-class edit).

GOAL
After a normal pipeline/hourly run dirties the tracked generated artifacts, one invocation of `scripts/clean_generated_artifacts.sh` restores every MUTABLE tracked generated runtime/display artifact the workflows commit (the seventeen fixed paths below), so `git status --short` shows none of them modified — while never deleting untracked files, never touching source files, and never touching durable/manual data outside that set.

SCOPE
- `scripts/clean_generated_artifacts.sh`: extend GENERATED from 7 to the 17 paths below; keep the existing `git ls-files --error-unmatch` skip guard (a GENERATED name that is untracked is skipped, never deleted), the `git checkout HEAD -- <file>` restore, the per-file echo, and the trailing `git status --short`; no other behaviour change.
- New `tests/test_clean_generated_artifacts.py`: builds a throwaway git repository under tmp_path (never the real repo), covers R1-R3.
- `docs/PROJECT_STATE.md`: retire the July known-debt note about the cleaner (and the active-PRD pointer per convention).

OUT OF SCOPE
- A generalized git-clean framework; deleting untracked files; the workflows' commit lists; the gitignore; reports/; run-history files (see the boundary under FILES).

REQUIREMENTS

R1 — Every mutable tracked generated artifact is restored.
In a throwaway repo where all seventeen paths are tracked and then modified, running the helper leaves `git status --short` listing none of them.
FAIL: any of the seventeen paths remains modified after the run. Mutation M1 (drop any one path from GENERATED) must turn this test RED naming that path.

R2 — Untracked, source, and durable files are untouched; an untracked GENERATED name is skipped, not deleted.
Setup: (a) one GENERATED entry (e.g. `logs/latest_hourly_market_map.json`) deliberately left UNTRACKED but present with known bytes; (b) one untracked sentinel outside GENERATED; (c) one TRACKED source sentinel outside GENERATED (`cuttingboard/x.py`) with an uncommitted modification; (d) one TRACKED durable/manual sentinel outside GENERATED (`data/manual.json`) with an uncommitted modification. After the run: (a), (b) still exist with identical bytes; (c), (d) keep their modifications byte-for-byte.
FAIL: any of (a)-(d) changes in existence or in a single byte.

R3 — Fail-loud outside a git work tree.
Run in a non-git directory containing a copy of the seventeen paths, the helper exits non-zero and makes no filesystem change (every file byte-identical, nothing created or deleted).
FAIL: exit code 0, or any filesystem change in that directory.
