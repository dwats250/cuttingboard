ROOT CAUSE
Ambiguous requirement. PRD-306's per-contract admissibility contract conflated
"semantic integer-valued open_interest" with "Python `int` representation."
`_valid_oi` required `isinstance(value, int)`. The Cboe `_SPX` delayed_quotes
endpoint emits whole-number OI counts as JSON numeric values that decode as
Python `float` (e.g. 2969.0). Every real contract therefore failed
`invalid_open_interest`, so the first live run exited fail-loud with
"zero eligible contracts after admissibility (included == 0)" and wrote no
artifact. GEX-0 evidence and a direct live probe (30282 contracts; all OI
Python `float`; 0 Python `int`; all integer-valued) confirm the provider
posture. The gamma predicate `_valid_gamma` was already representation-neutral
(int OR float); OI was the sole holdout.

WHY NOW
First real execution of `python3 tools/gex_snapshot.py` failed loud with
included==0. There was no prior good artifact to preserve, so the producer
delivers nothing against live data until this predicate is corrected.

MAX EXPECTED DELTA
<= 15 net production LOC, in exactly ONE production file (tools/gex_snapshot.py).
No new emitted field, schema key, provenance class, coverage key, exclusion
key, output, dependency, or CLI surface. Test file grows by one focused test
class.

GOAL
Change the open_interest admissibility invariant from representation-level
Python `int` to semantic integer-valued number, so the producer admits the
whole-number float OI the provider actually emits — while continuing to reject
non-integer, negative, boolean, and non-finite OI — and normalizes every
accepted OI to `int(value)` before it enters the Contract representation and
arithmetic.

SCOPE

  determinism are byte-identical to a Python-int feed.
- Add a focused test class discriminating provider-realistic float OI from the

  old strict-Python-int validator.

CHANGE SURFACE

- `_valid_oi(value)` — body replaced: was `isinstance(value, int) and >= 0`

REQUIREMENTS

The frozen PRD-306 matrix R1..R37 remains binding and green; this PATCH adds
R38..R43. Every R is a PRD-198 invariant-4 red test in
tests/test_gex_snapshot.py.

R38 — Integer-valued float OI is admitted and normalized.
An open_interest of 2960.0 (whole-number float) is admissible: the contract is
included, `coverage.excluded.invalid_open_interest` does not count it, and its
GEX is computed from the normalized integer 2960 (identical to int 2960 input).

FAIL: a feed row with open_interest 2960.0 is excluded as
invalid_open_interest, or drives included==0 fail-loud.

R39 — Zero float OI is admitted and counted as a zero-OI row.
An open_interest of 0.0 is admissible, included, and increments
`coverage.zero_oi_rows`.

FAIL: 0.0 is excluded, or `zero_oi_rows` does not increment for it.

R40 — Python-int OI representation is preserved.
An open_interest that is already a Python int (e.g. 2960) remains admissible
and normalizes identically.

FAIL: an int OI is excluded or its normalized value differs from the int.

R41 — Non-integer, negative, boolean, and non-finite OI are rejected.
open_interest of 2.5, True, False, -1, -1.0, NaN, +Inf, or -Inf is excluded as
invalid_open_interest.

FAIL: any of these values is admitted.

R42 — A Cboe-realistic all-float feed produces an artifact.
A feed whose every open_interest is a whole-number float (the live provider
posture) exits 0 with included == the number of otherwise-eligible rows and a
written artifact — never the included==0 fail-loud that the live run hit.

FAIL: such a feed exits non-zero or writes no artifact.

R43 — Coverage reconciles under a mixed int/float OI feed.
For a feed mixing float-valued, int, zero-float, non-integer-float, and
negative-float OI, `included + sum(excluded.values()) == contracts_total`, with
each exclusion counted exactly once in the fixed first-failure order.

FAIL: the reconciliation identity is broken, or a row is miscounted.

DATA FLOW

FAIL CONDITIONS

- open_interest 0.0 excluded, or zero_oi_rows not incremented (R39).
- int OI regressed to excluded or mis-normalized (R40).
- 2.5 / True / False / -1 / -1.0 / NaN / +Inf / -Inf admitted (R41).
- an all-float provider-realistic feed still drives included==0 (R42).
- coverage reconciliation identity broken under a mixed feed (R43).
- any change to an OUT OF SCOPE surface (schema, provenance, coverage keys,
