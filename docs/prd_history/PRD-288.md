GOAL
Add one compact, transient, read-only SPY observation card to the daily
dashboard — session date, freshness, session VWAP + price-vs-VWAP relation, and
the current-session ORB (projected verbatim from PRD-271) — present on every
relevant daily `_run_pipeline` run and independent of candidate availability,
while changing no execution, candidate, or decision behavior and adding no
durable schema. This is description, not prediction.

PRODUCT OUTCOME
One `#spy-observation` card on the daily dashboard. On a healthy run it shows
SPY's session date, observation timestamp, freshness, session VWAP and
price-vs-VWAP relation, and the current-session ORB state and bounds. When any
input is missing, stale, pre-open, zero-volume, or the run is halted, the card
states that explicitly through lifecycle truth rather than blanking or
fabricating a value. The card renders on the DAILY dashboard render only.

SIDECAR CONTRACT

`SpyObservation` (new frozen dataclass; transient; non-persisted):
| Field | Type | Notes |
|---|---|---|
| `observed_symbol` | `str` | Constant `"SPY"`. |
| `intended_session_date` | `Optional[date]` | ET date of `run_at_utc` (intended current session). |
| `timezone` | `str` | `"America/New_York"` (canonical literal). |
| `observed_at_utc` | `Optional[datetime]` | UTC timestamp of the latest bar of the SPY full-session fetch — the single authoritative headline observation time; `None` when UNAVAILABLE. |
| `state` | `str` | `PRE_OPEN` / `OBSERVED` / `STALE` / `UNAVAILABLE`. |
| `reason` | `Optional[str]` | Reason token for any non-OBSERVED state. |
| `session_vwap` | `Optional[float]` | Emitted only when `state == OBSERVED` AND session volume > 0; else `None`. |
| `current_price` | `Optional[float]` | SPY last price; emitted only when `state == OBSERVED`. |
| `price_vs_vwap` | `Optional[str]` | `ABOVE`/`BELOW`/`AT_LEVEL` when VWAP is formed; `"UNAVAILABLE"` on a zero-volume OBSERVED run; `None` in any non-OBSERVED state. |
| `orb` | `Optional[OrbObservation]` | The PRD-271 carrier, projected verbatim. |

Value-emission invariant:
- `current_price` and `price_vs_vwap` are non-`None` IFF `state == OBSERVED`.
- `session_vwap` is non-`None` IFF `state == OBSERVED` AND session volume > 0. On
  a zero-volume OBSERVED run, `session_vwap = None` while `price_vs_vwap =
  "UNAVAILABLE"` — a valid OBSERVED relation token meaning "cannot compare to
  VWAP", not a null; `current_price` remains present.
- `observed_at_utc` (the headline timestamp) is the latest bar of the SPY
  full-session fetch. The projected `OrbObservation` retains its own
  `observed_at_utc` for ORB provenance; it may differ and is never the card's
  headline timestamp.
- `orb_high`/`orb_low` are read only from `orb` and only when
  `orb.state == FORMED` (already guaranteed by `OrbObservation`).

Payload projection: `build_report_payload(contract, fixture_mode=False, *,
spy_observation=None)` adds `sections["spy_observation"]` (a plain-dict mirror,
dates/timestamps ISO-stringified) ONLY when `spy_observation` is provided. When
`None` (hourly path and every pre-existing caller), no section is added and the
renderer omits the card. One reader: the dashboard renderer.

Schema / persistence classification: no required `PipelineContract` top-level
key; the observation never enters `contract.py`'s `required_top` or
`SYSTEM_STATE_ALLOWED_KEYS`. The new optional `PipelineResult.spy_observation`
field is the in-memory return object of `_run_pipeline` (a transient carrier,
never serialized to a durable/decision-contract schema and never persisted across
runs), NOT the persisted `PipelineContract`. No new durable/decision-contract
schema and no cross-run persistence — the observation flows only through the
per-run render payload (`logs/latest_payload.json`), regenerated every run. The
single schema-surface touch is the additive payload section (one reader, one
presentation path); `delivery/payload.py` and `runtime/_types.py` are not the
decision contract.

FULL-SESSION FETCH BOUNDARY
- A new opt-in full-session path returns the complete current regular-session SPY
  frame for the intended session, UTC-indexed, with NO `tail(120)` truncation.
  Session window: 09:30–16:00 ET (regular session). This path MUST set its own
  `between_time("09:30","16:00")` and MUST NOT inherit the default fetcher's
  `between_time("09:30","15:30")` bound (which would silently drop 15:30–16:00 ET
  and make the session VWAP untruthful). Bounded to the single latest session
  date (~391 one-minute bars max; trivial memory for one symbol).
- Ordinary `fetch_intraday_bars` behavior is UNCHANGED for the short-permission
  state, post-trade evaluation, and every other contiguous-tail consumer;
  `fetch_intraday_orb_bars` (the watch ORB producer) is likewise unchanged.
- The full-session frame is consumed ONLY by `build_spy_observation` for SPY and
  must not leak into `IntradayMetrics`, `_bars_from_df`, `_watch_zones`, or any
  existing consumer.
- No persistence: the frame lives for the single run.

VWAP FORMULA AND ZERO-VOLUME
- Session anchor: 09:30 ET of the intended current trading date.
- Window: 09:30 ET (inclusive) through the latest observed bar, bounded by the
  16:00 ET close; regular-session bars only, over the SPY full-session frame.
- Formula (cumulative typical-price VWAP): `VWAP = Σ(TP_i · V_i) / Σ(V_i)`, where
  `TP_i = (High_i + Low_i + Close_i) / 3`.
- Zero-volume guard (fail-loud, PRD-198 #1): if `Σ(V_i) == 0`, VWAP is
  UNAVAILABLE — the observation does NOT seed VWAP with the last close. On a
  zero-volume OBSERVED run: `session_vwap = None`, `price_vs_vwap =
  "UNAVAILABLE"`, `current_price` present.
- Price relation: `price_vs_vwap` compares `current_price` to `session_vwap` with
  a neutral band (proposed: ±0.1% ≈ the sibling engine's `_VWAP_BUFFER = 0.001`
  semantics) → within band ⇒ `AT_LEVEL`, above ⇒ `ABOVE`, below ⇒ `BELOW`. The
  band value is proposed, not silently inherited; review confirms ±10 bps for SPY
  intraday granularity.

LIFECYCLE AND REASON-TOKEN CONTRACT
Two independent axes ride the card:
- ORB axis — reused VERBATIM from PRD-271 (states `PRE_OPEN/FORMING/FORMED/
  UNAVAILABLE/INVALID`; PRD-271's reason set). No new ORB truth.
- Observation/freshness axis (new): states `PRE_OPEN / OBSERVED / STALE /
  UNAVAILABLE`.
Observation reason tokens (annotate non-OBSERVED states only): `system_halted`,
`intraday_fetch_failed`, `insufficient_bars`, `pre_open`,
`pre_open_prior_session`, `session_mismatch`, `observation_lag`. VWAP-
unavailability within an OBSERVED run (zero volume) is NOT a state or reason
change — there is no `no_volume` reason token.

FRESHNESS SEMANTICS
Inputs: `intended_session_date`, `observed_at_utc`, `trading_date` (ET date of
the latest bar), `now` (`run_at_utc`), bar count, halt flags. Transition rules
(in order):
1. Run halted → `UNAVAILABLE / system_halted`.
2. No frame / bar count below the observability floor → `UNAVAILABLE /
   intraday_fetch_failed | insufficient_bars`.
3. `trading_date != intended_session_date`:
   - `now` ET ≤ 09:35 (intended open window not yet passed) → `PRE_OPEN /
     pre_open_prior_session` (benign; the ~13:00 UTC pre-open run normally sees
     the prior session with `prepost=False`).
   - else (session should be live) → `STALE / session_mismatch`.
4. `trading_date == intended_session_date`:
   - `now` ET < 09:30 → `PRE_OPEN / pre_open`.
   - `age = now − observed_at_utc`; `age ≤ SPY_OBSERVATION_STALE_AFTER_SECONDS`
     → `OBSERVED`; else → `STALE / observation_lag`.
Freshness threshold: `SPY_OBSERVATION_STALE_AFTER_SECONDS = 180` (3 min) — 2× the
60 s 1-minute-bar cadence plus one-cadence provider-lag margin; deliberately NOT
the 300 s quote-freshness / dashboard-page-age constants. The value is carried as
the packet specifies; review confirms it against real yfinance 1-minute lag
before Gate A. The card reuses the renderer's existing freshness/timestamp
display helpers (e.g. `_compute_timestamp_freshness`, `_timestamp_label`); the
only new elements are this threshold constant and the observation state machine.
(Note: the packet's §8 cited a helper `_freshness_label`; the actual renderer
helpers are `_compute_timestamp_freshness` / `_timestamp_label` /
`_run_snapshot_freshness_token` — a packet symbol-name imprecision corrected here
with no design change; the invariant "reuse existing render helpers, add only the
threshold + state machine" is unchanged.)

REQUIREMENTS

R1 — Card present on every relevant daily run, independent of candidates
On a daily `_run_pipeline` run (actionable TRADE, NO_TRADE, or STAY_FLAT), the
payload carries a `spy_observation` section and the dashboard renders one
`#spy-observation` card, whether or not any candidate qualified.

FAIL: A daily NO_TRADE / STAY_FLAT run with zero candidates produces no
`spy_observation` section, or renders no `#spy-observation` card.

R2 — Hourly path is out of scope; no card on hourly artifacts
The hourly artifact path (`build_report_payload(contract)` with no
`spy_observation` argument) produces a payload with NO `spy_observation` section,
and the renderer omits the card; the hourly writer path is unmodified.

FAIL: An hourly-published `ui/dashboard.html` contains a `#spy-observation`
element, OR the hourly payload carries a `spy_observation` section, OR the hourly
writer is edited to pass an observation.

R3 — One ORB truth (verbatim projection)
`build_spy_observation` holds and reads `intraday_metrics["SPY"].orb`; the card's
ORB `state`/`orb_high`/`orb_low` are identical to that object. It never calls
`_session_orb` and never recomputes an opening range.

FAIL: The card's ORB values differ from `intraday_metrics["SPY"].orb`, OR
`build_spy_observation` computes/recomputes an opening range or instantiates a
second ORB producer.

R4 — Transient carrier; no durable schema, contract key, or persistence
`SpyObservation` is a frozen transient dataclass. No `PipelineContract`
top-level key is added; nothing is persisted or carried across runs; the
producer writes no artifact.

FAIL: The change adds a `PipelineContract` key / `SYSTEM_STATE_ALLOWED_KEYS`
entry / durable schema, OR persists any observation state across runs.

R5 — Carrier reaches payload via an additive optional parameter
`build_report_payload(contract, fixture_mode=False, *, spy_observation=None)`
adds the section only when the argument is provided; every pre-existing caller
(passing `fixture_mode` only) is behavior-identical to pre-change.

FAIL: An existing `build_report_payload` caller changes output, OR the parameter
is required / positional / placed before `fixture_mode` / drops `fixture_mode`.

R6 — SPY-only full-session fetch; default intraday fetch unchanged
A new opt-in path returns the full 09:30–16:00 ET session frame for SPY, while
`fetch_intraday_bars` default still returns the contiguous `tail(120)` for
short-gate / evaluation / other consumers, and `fetch_intraday_orb_bars` is
unchanged. The full-session frame does not leak into any existing consumer.

FAIL: The default `fetch_intraday_bars` output changes for any contiguous
consumer, OR the full-session path inherits the 09:30–15:30 bound, OR the
full-session frame reaches `IntradayMetrics` / `_watch_zones` / `_bars_from_df`.

R7 — Session VWAP formula and zero-volume behavior
Session VWAP is the 09:30-anchored cumulative typical-price VWAP over the
full-session frame. On zero session volume: `session_vwap = None`,
`price_vs_vwap = "UNAVAILABLE"`, `current_price` present, no divide-by-zero, and
VWAP is not seeded from the last close.

FAIL: VWAP is computed over the rolling tail instead of the 09:30-anchored full
session, OR a zero-volume run seeds VWAP / raises / emits a non-`None`
`session_vwap` / omits `current_price`.

R8 — Value-emission invariant and headline timestamp
`current_price`/`price_vs_vwap` are non-`None` iff `state == OBSERVED`;
`session_vwap` is non-`None` iff `state == OBSERVED` and volume > 0;
`observed_at_utc` (headline) is the latest bar of the full-session fetch; the
nested `orb` keeps its own provenance timestamp.

FAIL: Any value is presented as current in a non-OBSERVED state, OR the headline
`observed_at_utc` is taken from the ORB frame instead of the full-session fetch.

R9 — Freshness lifecycle and reason tokens
The observation state is exactly one of `PRE_OPEN / OBSERVED / STALE /
UNAVAILABLE` per the FRESHNESS SEMANTICS rules, using
`SPY_OBSERVATION_STALE_AFTER_SECONDS = 180`; each non-OBSERVED state carries the
specified reason token.
