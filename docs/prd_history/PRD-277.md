WHY NOW
Corrective PRD against PRD-276 (merged `590dc75`, #178). Connector review of
`9e70fb2` landed after merge and found six defects, all verified. Three are
functional defects in the guard PRD-276 shipped; three are self-inconsistencies
created by PRD-276's own amendment 1.

Reproduced directly before filing:

1. **Unregistered PRD docs bypass the guard entirely.**
   `_validate_lane_payload_prohibition` iterates `registry_rows`, so a
   `PRD-NNN.md` absent from both the registry and the index is never inspected —
   and nothing else reports it as an orphan. A doc declaring `LANE: MICRO`,
   `CLASS: GOVERNANCE` and `M docs/PRD_PROCESS.md` passes
   `validate_prd_registry.py --skip-commit-resolvability` with **exit 0**.
   This is the same evasion PRD-276's R6 closed one layer down: R6 stopped
   scope-lock permitting an undeclared `PROJECT_STATE.md`, but the guard is
   keyed off a bookkeeping artifact, so omitting the REGISTRY ROW defeats it a
   floor higher. A guard seeded from optional bookkeeping inherits that
   bookkeeping's optionality as an attack surface (connector 3688543120).
2. **A one-character CLASS typo disables the control.** `_CLASS_GOVERNANCE_RE`
   does not match `CLASS\nGOVERANCE`, so the PRD takes the non-governance
   `continue` and is silently exempt. No other check validates CLASS against a
   closed set (connector 3688543123).
3. **The canonical micro-template annotation is rejected.**
   `docs/PRD_MICRO_TEMPLATE.md` emits `` `docs/PRD_REGISTRY.md` (PRD-NNN row) ``.
   `_POINTER_ANNOTATION_RE` accepts only `pointer` or `bookkeeping`, so a
   MICRO/GOVERNANCE PRD following the required template fails with a
   lane-downgrade error for ordinary row bookkeeping (connector 3688543111).

And three inconsistencies PRD-276 introduced when amendment 1 retained
`docs/PRD_REGISTRY.md` in the matrix without propagating that reversal:

4. `docs/PRD_PROCESS.md` § Scope Lock still states registry bookkeeping "is not
   enumerated in PRD `FILES` sections", while the amended Prohibition and the
   updated scope-lock skill now REQUIRE a GOVERNANCE PRD to enumerate and
   annotate it. An author following Scope Lock is rejected by the skill
   (connector 3688543112).
5. `PRD-276.md`'s VALIDATION step 8 still asserts the GOVERNANCE matrix row
   contains no `PRD_REGISTRY` token — the opposite of the state that shipped
   (connector 3688543116).
6. `PRD-171.md`'s STATED LIMITATION records that PRD-276 removed
   `docs/PRD_REGISTRY.md` from the GOVERNANCE cell. It does not; that claim is
   durable history and is now false (connector 3688543119).

GOAL
The PRD-276 lane guard cannot be bypassed by omitting bookkeeping or by
mistyping CLASS, does not reject the canonical micro-template annotation, and
the documents describing it agree with what shipped.

REQUIREMENTS

R1 — Every PRD document is inspected, registered or not
The guard enumerates `docs/prd_history/PRD-*.md` rather than `registry_rows`, so
a document absent from the registry and index is still checked.
FAIL: a `PRD-NNN.md` (NNN >= 276) declaring `CLASS: GOVERNANCE`, a non-HIGH-RISK
lane, and a payload governance file in FILES passes validation exit 0 while
carrying no registry row or index entry.

R2 — CLASS is validated, not pattern-matched
The guard parses the declared CLASS header and fails on a value outside the
closed base set, rather than treating an unrecognised value as exempt.
FAIL: a PRD (NNN >= 276) with `CLASS: GOVERANCE`, `LANE: MICRO` and
`M docs/PRD_PROCESS.md` in FILES passes validation, OR a PRD with no CLASS
header at all is silently exempted.

R3 — The micro template's registry marker is accepted
`_POINTER_ANNOTATION_RE` recognises the `(PRD-NNN row)` form
`docs/PRD_MICRO_TEMPLATE.md` emits, alongside `pointer` and `bookkeeping`.
FAIL: a MICRO/GOVERNANCE PRD whose FILES carries the unmodified template line
`` - `docs/PRD_REGISTRY.md` (PRD-NNN row) `` is reported as a lane downgrade.

R4 — Scope Lock and the Prohibition give one answer
`docs/PRD_PROCESS.md` § Scope Lock states the GOVERNANCE exception explicitly,
so an author reading it reaches the same conclusion as the scope-lock skill.
FAIL: § Scope Lock still says registry bookkeeping is never enumerated in
`FILES`, with no GOVERNANCE qualifier.

R5 — The durable records match what shipped
`PRD-276.md` VALIDATION step 8 verifies the registry token is PRESENT with the
qualifier, and `PRD-171.md` no longer claims PRD-276 removed it.
FAIL: either document still asserts the token was removed from the GOVERNANCE
matrix row.
