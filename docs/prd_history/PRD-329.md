disclosure taps before its chart is visible, and SPY SESSION OBSERVATION is

orientation. The packet proved both fixes are renderer-only.

GOAL
S1: one tap on a collapsed C tier reveals the candidate card, its LEVEL MAP
and its CHART, with initial-load bytes unchanged everywhere else. S2: SPY
SESSION OBSERVATION renders as a first-class block between WATCHING and
DETAILS / HISTORY with a neutral daily-bar chart and a neutral level ladder
when their existing inputs are honestly available, MARKET CONTROL stays in
DETAILS / HISTORY, and no permission semantics are created.

REQUIREMENTS

S1
R1 — Closed-tier evidence opens with the tier (S1-Q1)
Every card rendered inside a `tier-group` `<details>` emitted without `open`
emits `<details open class="level-detail">` (when that wrapper is emitted at
all, i.e. not `decision_permitted`) and `<details open class="chart-detail">`
(when the chart is disclosed). Mechanism: `_render_candidate_card` gains one
keyword `tier_closed: bool = False`, passed from the tier loop as
`tier_closed=(is_low_tier and not _open)`; `_render_setup_chart_block` gains
one keyword `open_when_disclosed: bool = False`. Attribute order mirrors D1:
`<details open class="...">`.
FAIL: a card inside a closed C tier renders `<details class="level-detail">`
or `<details class="chart-detail">` without `open`; or the closed-C-tier
render under TRADE PERMITTED (no `level-detail`) lacks
`<details open class="chart-detail">`.

R2 — Initial load and open tiers byte-identical
No `open` attribute is emitted on `level-detail` or `chart-detail` for any
card in an A+/A/B `<div class="tier-group">`, nor for any card in a C tier
emitted WITH `open` (the primary's tier; its sibling secondaries keep today's
closed wrappers). `card-detail` never carries `open`. Renders without a closed
C tier are byte-identical to the D2 baseline.
FAIL: any `<details open class="level-detail">`, `<details open class="chart-detail">`
or `<details open class="card-detail">` appears outside a closed C tier; or
any `tests/test_dashboard_d2_seam.py` golden hash changes; or the
`test_prd326_c_grade_primary_tier_opens` open-tier assertions (`[1, 3]` depth,
DDD closed `chart-detail`) fail.

R3 — HTML-only; no JavaScript; native collapsibility
The rendered page contains exactly the one pre-existing `<script>` (staleness
banner). Both nested disclosures remain native `<details>` elements the
operator can collapse. No new CSS selector targets `[open]`.
FAIL: `html.count("<script")` != 1; or the diff adds `<script`, `onclick`, or
a `[open]` CSS rule; or `level-detail` / `chart-detail` are replaced by
non-`<details>` markup.

R5 — Observational SPY chart from existing daily bars, neutral semantics (S2-Q2)
Resolution ladder, evaluated in order inside `#spy-observation` after the
`kv-grid`; every step uses `.get` on possibly-missing dicts and never raises:
 (a) MAP UNHEALTHY: `_mm_health != "OK"` (tokens `MIXED`, `STALE`, `MISSING`,
     `INACTIVE_SESSION`, `INVALID`) or `unhealthy_lineage`, which includes
     `market_map=None` -> exactly one line
     `<div class="lvl-unavail">Chart and levels unavailable — market map <state></div>`
     with `<state>` the `_mm_health` token (or the existing lineage wording
     family), then no chart and no ladder.
 (b) SPY RECORD ABSENT on a healthy map: `market_map["symbols"]` is a dict
     that lacks the key `SPY` -> the same single line with `<state>` =
     `no SPY record`, no chart, no ladder. (Non-dict `symbols` or a non-dict
     SPY record are NOT reachable through `render_dashboard_html`: existing
     consumers raise first at the TAPE slot builder (:1562-1565) and the
     candidate sort (:3178-3182); that pre-existing behaviour is outside this
     PRD's cone and is not changed. `_render_spy_session` itself must still
     treat a None or non-dict `spy_record` as (b), asserted by calling the
     helper directly.)
 (c) PRICE INVALID: `symbols["SPY"]["current_price"]` not a finite positive
     number -> no chart; the ladder call runs and emits only its existing
     `Chart unavailable — no price data` line.
 (d) BARS ABSENT or SVG EMPTY: `_price_bars` has no SPY entry, or
     `render_setup_chart_svg` returns "" -> exactly
     `<div class="lvl-unavail">Chart unavailable — no bars for SPY</div>`, no
     `<svg`; the ladder (R6) still renders.
 (e) CHART: `<div class="spy-chart">` containing
     `render_setup_chart_svg(bars, now_price, contract_entry=None, contract_stop=None, watch_zones=zones_or_None, fib_levels=fibs_or_None, operator_locked=False)`
     followed by `<div class="chart-caption">` whose text is the exact
     `_price_bars["SPY"][1]` caption string followed by
     ` · NOW per market map <label>` where `<label>` is
     `_timestamp_label(market_map_timestamp_value, market_map_timestamp)`, so
     OBSERVED AT (session observation), bars `as_of` (daily candles) and NOW
     (market map) are each named.
The wrapper class is `spy-chart`, never `setup-chart`, so PRD-321's
depth-aware candidate-chart assertions are untouched and the chart is never a
candidate chart. Observation state (PRE_OPEN / OBSERVED / STALE / UNAVAILABLE)
does not by itself suppress the chart or ladder. Legitimately empty zones/fibs
draw candles-plus-NOW and a NOW-only ladder.
