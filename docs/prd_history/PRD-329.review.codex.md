### REQ-1 - [schema ambiguity] MCC-only STAY renders have mutually incompatible byte requirements

An MCC-only render has no `spy_observation` but currently uses that wrapper, so both requirements cannot be satisfied as written.

Evidence: The no-observation invariance is absolute at `docs/prd_history/PRD-329.md:129-135` and `docs/prd_history/PRD-329.md:185-190`. R9 unconditionally removes the wrapper and heading while leaving MCC standalone at `docs/prd_history/PRD-329.md:300-310`. The current renderer opens and closes that wrapper whenever either observation or MCC is present at `cuttingboard/delivery/dashboard_renderer.py:3284-3289,3348-3349`; MCC-only rendering is an existing reachable test arrangement at `tests/test_dashboard_renderer.py:4357-4368`.

Smallest fix: Scope wrapper and heading removal explicitly to renders where `spy_observation` is present, preserving the MCC-only baseline, and narrow R9's corresponding FAIL condition to that case. Add an MCC-only regression case that pins the full existing wrapper plus MCC bytes. No new Helm design ruling is needed if the explicit no-observation byte invariant remains controlling.
