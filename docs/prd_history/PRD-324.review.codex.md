## BLOCKING findings

1. DESIGN DEFECT: R3/R4 do not define an authoritative or sufficient completed-bin rule.

   - The packet requires "right-closed" resampling at `audits/intraday-session-chart-material-packet-2026-08/INTRADAY_SESSION_CHART_MATERIAL_PACKET_2026-08-30.md:181-183`.
   - PRD-324 instead says "right-labeled", defines left-closed bins `[09:30 + 5k, 09:30 + 5(k+1))`, and emits the bin-start label at `docs/prd_history/PRD-324.md:222-240`.
   - Those are not equivalent descriptions. A bar cannot simultaneously be right-labeled and labeled with its bin start without an explicit distinction between aggregation closure and display label.
   - More seriously, `through` is only the timestamp of the last written bar: `cuttingboard/runtime/__init__.py:2740-2743`. The writer validates timezone awareness, ordering, uniqueness, and OHLCV, but it does not validate one-minute alignment or contiguous coverage: `cuttingboard/runtime/__init__.py:2690-2719`.
   - Therefore `bin.right_edge <= through` does not prove that all five source minutes exist. For example, valid rows at 09:30 and 09:35 satisfy the shipped writer, and R4 would admit the 09:30-09:35 bin even though four minutes are missing.
   - The normal fetch converts the full-session frame to UTC at `cuttingboard/ingestion.py:245-260`, while the design never explicitly requires conversion to ET before anchoring.
   - Smallest Helm ruling needed: ratify the exact bin closure, display label, source timestamp meaning, and completeness rule. The corrected rule must address missing minutes and exact boundary cases before implementation.

2. DESIGN DEFECT: invalid or admitted-but-unrenderable intraday data is not guaranteed to fall back to the daily chart.

   - R1 only names top-level envelope fields at `docs/prd_history/PRD-324.md:193-200`.
   - R2 defines structural failure only for `generated_at`, `session_date`, and `through` at `docs/prd_history/PRD-324.md:203-220`.
   - The shipped schema also binds `schema_version == 1`, exact `source`, exact `columns`, `row_count == len(bars)`, `through == bars[-1][0]`, row shape, ordered aware timestamps, and coherent OHLCV: `cuttingboard/runtime/__init__.py:2735-2758` and `docs/SCHEMA_MAP.md:190-204`.
   - A persisted artifact can be malformed after the producer writes it. PRD-324 does not require the consumer to reject nested record corruption, wrong schema version, wrong columns/source, `row_count` mismatch, `through` mismatch, malformed bars, or sparse/non-minute-aligned bars.
   - R9 says R2+R6 admission always selects intraday at `docs/prd_history/PRD-324.md:285-294`. But an admitted early-session snapshot can derive zero completed bins, and even admitted data can yield an empty SVG. The existing guarded renderer only emits a chart when `chart_svg` is non-empty: `cuttingboard/delivery/dashboard_renderer.py:2284-2302`.
   - Required contract: intraday substitution occurs only when admission succeeds, at least one complete bin is derived, and the intraday SVG is non-empty. Every other state must execute the untouched daily branch.

3. DESIGN DEFECT and SCOPE STOP: the FILES cone is incomplete.

Deleting the renderer definition necessarily requires editing this test.
   - `docs/renderer_decomposition_map.md:27` and `docs/renderer_decomposition_map.md:222` explicitly identify `_GRADE_ORDER` and `_TIER_DEFS` as renderer globals and decision-bearing renderer values. Moving them necessarily changes those assertions.
   - The only independent HTML golden is `tests/data/dashboard_pre_gex_golden.html`. It contains a `SOURCE_MISSING` candidate board, not a chart-bearing daily baseline: `tests/data/dashboard_pre_gex_golden.html:101-104`. It cannot prove chart-slot ownership or daily-chart fallback.
   - FILES renewal is required before Gate A.

## REQUIRED findings

1. DESIGN DEFECT: R5 claims runtime input-source parity but does not specify a real surviving oracle.

   - Their "renderer winner" is a test-side reconstruction that walks renderer constants and calls `_render_candidate_card`: `tests/test_primary_selection.py:53-82`.

2. DESIGN DEFECT: R2 does not pin actual timezone handling or exact session endpoints.

   - `generated_at` is UTC: `cuttingboard/runtime/__init__.py:2746-2749`.
   - The normal producer's bar index is UTC: `cuttingboard/ingestion.py:258-260`; the writer preserves that timezone in each serialized timestamp: `cuttingboard/runtime/__init__.py:2716`.
   - The renderer supplies UTC `now` in production: `cuttingboard/delivery/dashboard_renderer.py:3929-3930`.
   - PRD-324 merely says evaluation occurs against ET `now`: `docs/prd_history/PRD-324.md:203-212`.
   - Require aware timestamps, normalize `now`, `generated_at`, every bar timestamp, and `through` through `America/New_York`, and then apply date/time/bin rules. Tests must cover equivalent UTC and ET encodings, EDT and EST dates, naive rejection, exact age 90m, exact future skew 5m, and the producer's 09:30/16:00 endpoints.

3. DESIGN DEFECT: moving tier authority has an unenumerated decision-bearing consumer and an overbroad "exactly one" claim.

   - `_TIER_DEFS` feeds `_build_integrator_input`, not just chart ordering: `cuttingboard/delivery/dashboard_renderer.py:1816-1831`.
   - It separately drives the candidate tier loop at `cuttingboard/delivery/dashboard_renderer.py:3111-3131`.
   - `docs/renderer_decomposition_map.md:222` classifies grade/tier ordering as decision-bearing.
   - A separate public `GRADE_ORDER` remains in `cuttingboard/market_map_lifecycle.py:16-27`, so the repo-wide claim that `GRADE_ORDER` exists in exactly one place is false.
   - There is no reverse dependency if the renderer imports the leaf; the architecture is viable. The defect is the unenumerated consumer and false uniqueness boundary. R7 must be narrowed to the renderer/primary-selection duplicated pair and must prove `_build_integrator_input` bytes and outputs unchanged.

4. DESIGN DEFECT: R10 conflates source `through` with rendered candle coverage.

   - The caption must distinguish "source through" from "completed candles through", or Helm must rule which one the product caption represents. A single raw `through` value cannot truthfully assert both.
