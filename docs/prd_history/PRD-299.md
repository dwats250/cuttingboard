WHY NOW
PRD-298 made a valid market-stress HALT an executor-success that publishes and
concludes success, so an OPEN run's conclusion is now trustworthy execution
evidence. With Cloudflare as the preferred OPEN clock (owner-ratified) and a
delayed GitHub cron as the resilience fallback, the live morning observation must
run exactly once per OPEN slot — no missing board, no redundant second execution
— using GitHub-native run evidence only, with no repo-persisted coordination
state. Today the workflow has no slot vocabulary, no run-name carrier, no
first-success proof, and the existing 06:00-PT live cron would race a CF dispatch.

GOAL
Implement GitHub-native first-success OPEN-slot coordination exactly as specified
in the review-clean packet: a typed `check_open_slot_satisfied.py` proof; a
`CB-SLOT:OPEN`/`CB-SLOT:PRE` `run-name` carrier; slot/mode dispatch inputs with
fail-closed validation ordered before the no-op decision; the existing 06:00-PT
live cron replaced by a delayed (~13:05 UTC) OPEN fallback cron that carries the
OPEN token and runs the pre-check; a fixed dedicated OPEN concurrency group with
native non-evicting (`queue: max`) semantics; and an undeployed, transport-only
Cloudflare Worker. No persisted coordination state; `latest_run` semantics
unchanged; `source` is provenance only.

REQUIREMENTS

R1 — Dispatch inputs. `workflow_dispatch` gains `slot` (choice: OPEN, PRE) and
`source` (string), alongside the reused `mode`. `source` is recorded/logged as
provenance only and is NEVER read by any coordination predicate or authority
check.
FAIL: `source` value influences slot satisfaction, execution, or authority; or
`slot`/`mode` inputs are absent from the dispatch surface.

R2 — Slot/mode consistency, fail-closed, ordered first. `OPEN` requires
`mode==live`; `PRE` requires `mode==prefetch`. A mismatch fails closed (non-zero,
no market execution). This validation runs BEFORE the first-success no-op decision,
so a malformed OPEN invocation concludes FAILURE and can never become a satisfying
no-op.
FAIL: a slot/mode mismatch executes or concludes success; OR the first-success
no-op decision can run before slot/mode validation.

R3 — Slot carrier in `run-name`/`display_title`. Every automatic OPEN run carries
exactly one `CB-SLOT:OPEN` token; every automatic PRE run exactly one
`CB-SLOT:PRE`; Sunday / non-slot / default-named runs carry NO `CB-SLOT:`
substring. The token derives from `inputs.slot` for `workflow_dispatch` and from
the cron→slot map for `schedule`.
FAIL: an OPEN/PRE run lacks its token; a non-slot run contains `CB-SLOT:`; or the
token can be set from `source`.

R4 — First-success proof `check_open_slot_satisfied.py`. Returns typed SATISFIED /
UNSATISFIED / PROOF_ERROR. SATISFIED requires ALL of: workflow path
`.github/workflows/cuttingboard.yml`; `event ∈ {workflow_dispatch, schedule}`;
`head_branch == main`; `display_title` contains `CB-SLOT:OPEN`; the run falls in
today's OPEN eligibility per the event-aware bound in R5; `status == completed`;
`conclusion == success`; and the run is not the current run (`github.run_id`
excluded). A malformed run record, missing/invalid API field, HTTP error, network
error, or missing repo/token env yields PROOF_ERROR — never an inferred UNSATISFIED
or SATISFIED. TRADE, NO_TRADE, and a valid MARKET_STRESS HALT (PRD-298) all qualify
as `success`; a crash, VALIDATION halt, or publish failure conclude `failure` and
do NOT qualify.
FAIL: any missing clause promotes a non-qualifying run to SATISFIED; OR malformed/
unavailable evidence is promoted to SATISFIED or UNSATISFIED; OR a crash/VALIDATION
halt/publish-failure run satisfies; OR a valid MARKET_STRESS HALT does not.

R5 — Event-aware OPEN eligibility bound anchored to an authoritative boundary, NOT
a guessed lateness cutoff (corrects Sol S1). Today's OPEN eligibility for the R4
membership clause is computed on the run's ORIGINAL `created_at` (UTC), bucketed to
today's trading date (the UTC calendar date of the slot, which coincides with the
PT/ET trading date for this ~13:00-UTC premarket slot), and split by GitHub-native
`event` type:

- `event == schedule` (the automatic OPEN fallback — the sole `5 13 * * 1-5` OPEN
  cron; PRE `50 12` and Sunday `30 23` carry different/no OPEN token): satisfies
  for the trading date with **NO intra-day upper bound**. A schedule event is
  automatic by definition and can never be a manual run, so a legitimately DELAYED
  fallback — even one GitHub creates well after the nominal 13:05 UTC, including
  the observed >30-minute scheduler-delay case — still satisfies. This closes S1
  (a real successful automatic fallback is never "forgotten") without asserting
  any lateness cap. Previous-day / rerun handling is by the original-`created_at`
  date bucket (per the rerun rule).
- `event == workflow_dispatch` (CF automatic OR manual): satisfies only when the
  run is premarket — `created_at` (UTC) `>= 12:55 UTC` (lower bound, tied to CF's
  UTC ~13:00 trigger; rejects off-hour-early and previous-day) AND
  `convert_utc_to_et(created_at) < _MARKET_OPEN_ET (09:30 ET)` (upper bound = the
  AUTHORITATIVE market-open boundary, `cuttingboard/time_utils.py`, DST-correct:
  13:30 UTC in EDT / 14:30 UTC in EST). This contains the punctual CF OPEN
  (~13:00 UTC, low dispatch latency), admits a genuine near-slot in-window manual
  OPEN (T20 policy), and excludes later operator/recovery/post-open manual runs —
  using an existing authoritative boundary, not a guessed cutoff.

The bound is helper logic over GitHub-native fields (`event`, `created_at`,
`display_title`) plus the canonical `time_utils` constants; it adds no persisted
state. The window is deliberately NOT a single fixed UTC upper cutoff (which would
either forget a delayed automatic fallback — Sol S1 — or, if widened by guess,
admit unrelated later runs).
FAIL: a schedule-event OPEN fallback delayed past a fixed upper cutoff is excluded
and a later OPEN-class run double-executes (the S1 regression); OR a
workflow_dispatch OPEN run created after market open (its trading date, ET) or
before 12:55 UTC satisfies; OR the bound is anchored in PT (PST-winter seasonal
double-execution); OR a previous-day run satisfies.

R6 — Automatic-OPEN pre-execution gate. Before the live execute step, on an
automatic OPEN invocation, the workflow runs `check_open_slot_satisfied.py` with
the ambient `github.token` (existing `actions: read`; no new credential):
SATISFIED → no-op successfully before market execution; UNSATISFIED → execute;
PROOF_ERROR → execute, with the degraded-coordination evidence logged. The proof
never suppresses the only fallback on uncertain evidence.
FAIL: SATISFIED still executes; UNSATISFIED/PROOF_ERROR no-ops (suppresses); or the
gate requires a credential beyond `actions: read`.

R7 — Delayed OPEN fallback cron replaces the 06:00-PT live cron. The `0 13 * * 1-5`
live cron is REMOVED; `5 13 * * 1-5` is ADDED as the delayed OPEN fallback,
resolves to `live`, carries `CB-SLOT:OPEN`, and runs the R6 pre-check.
`resolve_run_mode.py` maps `5 13 * * 1-5 → live` and no longer maps `0 13`.
FAIL: both `0 13` and `5 13` OPEN crons exist (double execution); OR the fallback
cron does not carry the token / does not run the pre-check.

R8 — Fixed dedicated OPEN concurrency group, non-evicting. Coordination-
participating OPEN runs use a fixed dedicated concurrency group with native
non-evicting queuing (`concurrency: { group: <fixed OPEN group>, queue: max }`;
`queue: max` NOT combined with `cancel-in-progress: true`). A later OPEN-class
enqueue (third valid OPEN, malformed `slot=OPEN`, or duplicate CF dispatch) MUST
NOT cancel/replace a pending OPEN fallback; OPEN runs serialize and the first
completed successful OPEN satisfies the slot.
FAIL: a later OPEN-class enqueue evicts a pending OPEN fallback; OR the OPEN group
is shared with non-OPEN slots such that an unrelated run evicts the fallback.
STOP/RED CONDITION: if `queue: max` (or an equivalent guaranteeing full
non-eviction) is not actually available, the missing-board hazard is unclosed —
return RED (packet §14 item 13), do not ship an evicting group.

R9 — Undeployed transport-only Worker. `workers/cuttingboard-clock/` contains
Worker source that, on a scheduled event, resolves PRE/OPEN and POSTs
`workflow_dispatch` (ref=main, {mode, slot, source}) using an Actions-write-only
secret; logs accepted vs rejected dispatch (HTTP status); makes NO
observation/publish claim; contains NO market logic, `latest_run` interpretation,
dedup state, or KV/Durable Objects; and no secret value is committed. It ships
UNDEPLOYED with a config example + README of the owner-held deploy/secret steps.
FAIL: the Worker reads a credential scope beyond Actions:write; claims observation/
publish success; holds coordination/dedup state; or a secret value is committed.

R10 — Non-regression of settled surfaces. `logs/latest_run.json` and the contract
schema are unchanged (no new persisted field). The HOURLY path
(`alert_runner`/`_execute_notify_run`), Sunday behavior, PRD-298 exit/publish/HALT
semantics, and `check_readiness`/publish gating are unchanged.
FAIL: any of those behaviors change.

INVARIANTS
I1 No persisted coordination/idempotency/attempt state; all evidence read live
   from the Actions API at query time.
I2 `source` is provenance only; the satisfaction predicate is source-blind, so a
   spoofed `source` cannot grant authority.
I3 Fail-toward-availability: on proof uncertainty the fallback executes; the only
   fallback is never suppressed on uncertain evidence.
I4 `∃ qualifying OPEN success in-window ⟺ the slot was really published` — a
   SATISFIED no-op concludes success without publishing but can only occur
   downstream of a prior real published success (validation-before-no-op ensures a
   malformed no-op cannot masquerade as a qualifying success).
I5 Run conclusion is execution-control evidence only; it never promotes dashboard
   freshness or market validity beyond existing artifact truth.
I6 `latest_run` / contract schema / HOURLY / Sunday / PRD-298 semantics unchanged.

FAIL CONDITIONS

item 12); slot satisfaction cannot be proven from GitHub-native evidence without
persisted state; `source` cannot remain source-blind; credential scope must widen
beyond Actions:write; or `latest_run`/observation semantics must change.
