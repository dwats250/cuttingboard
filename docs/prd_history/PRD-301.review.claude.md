The PRD gated the legacy-directory branch on "the acquisition `ln` fails and the path is a directory" (contract line, SCOPE.2, DATA FLOW), which is unreachable: a live legacy owner would not block, `_have_lock=1` would be set wrongly, and a stray hardlink would be dropped inside the legacy directory — defeating ruling #3. FIX: detect the directory case EXPLICITLY with `[ -d "$LOCKFILE" ]` BEFORE attempting `ln`, and never rely on `ln`'s exit status to distinguish a directory target. (Incorporated: acquisition loop checks `[ -d "$LOCKFILE" ]` first and routes to legacy handling; `ln` runs only when the path is absent or a regular file.)
2. The identity-safe reclaim grave `.dev_bootstrap.lock.stale.$$` is an unswept artifact. R4's dead-owner sweep covered only the `.new.$$` acquisition temp; a reclaimer killed between creating and removing its grave would leave a permanent untracked `.stale.$$` hardlink, falsifying I7 and the no-`.gitignore` justification. FIX: extend the sweep (and I7's artifact enumeration) to remove dead-owner `.stale.$$` graves (file and empty-dir forms) as well as `.new.$$` temps. (Incorporated: `_sweep_stale` globs both `.new.*` and `.stale.*` and removes those owned by dead pids.)
