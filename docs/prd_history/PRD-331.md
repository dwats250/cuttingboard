WHY NOW
The engine's MANUAL_CHECK state (chain_validation.py:74,
MANUAL_CHECK = "NEEDS_MANUAL_CHECK") already reaches the operator dashboard, but
only as an unlabelled bold row in the ALERT WATCHLIST subsection of WATCHING
(render_dashboard_html in cuttingboard/delivery/dashboard_renderer.py), printed
as "SYM DIRECTION [sep] BLOCK_REASON" (e.g. "^TNX LONG -- CHAIN DATA UNAVAILABLE
FROM ALL SOURCES"). PREMISE CORRECTION (TRUTH): the literal runtime warning
"<symbol>: needs manual chain check" is produced in cuttingboard/runtime and
lands only in the run-summary warnings list, which the dashboard never reads;
there is no renderer string to replace, and the reviewer should not look for
one. On a phone the manual-action state is visually identical to any other gated
candidate, so the operator can miss it. This PRD makes that one state unmissable
without changing its meaning.

GOAL
Render a labelled, color-independent "MANUAL CHECK" flag on the ALERT WATCHLIST
row of any candidate whose contract classification is NEEDS_MANUAL_CHECK, so the
operator cannot miss the manual-action state, while every other row and all
underlying data stay byte-identical.

SCOPE

  WATCHLIST loop only: for an alert candidate whose setup_quality ==

  replace the row in place with a div of class "candidate-state manual-check"

REQUIREMENTS

R1 -- Labelled manual-action row
An alert candidate with setup_quality == "NEEDS_MANUAL_CHECK" renders inside
#alert-watchlist as a div of class "candidate-state manual-check" with
data-raw-state="NEEDS_MANUAL_CHECK" whose first child is
<span class="manual-check-flag">MANUAL CHECK</span>, followed by the unchanged
symbol, direction, and (when present) block-reason text. The existing separator
and spacing between symbol/direction/reason are preserved byte-for-byte, and no
separator is emitted when the block reason is falsy.
FAIL: the manual row lacks the manual-check class, the data-raw-state attribute,
or the label span; or its symbol/direction/reason text differs from the current
render.

R2 -- Every other row byte-identical; single surface
Every alert candidate whose setup_quality is not "NEEDS_MANUAL_CHECK" renders
byte-identically to today's div of class "candidate-state". The token "MANUAL
CHECK" appears nowhere in a render that has no such candidate, appears exactly
once per manual candidate, and only inside #alert-watchlist.
FAIL: any non-manual row changes; or "MANUAL CHECK" appears outside
#alert-watchlist, more than once per manual candidate, or in a render with none.

R3 -- Keyed on classification, not reason text
The flag is keyed on the contract classification only: a candidate whose
block-reason text mentions the chain but whose setup_quality is not
"NEEDS_MANUAL_CHECK" gets no flag; a NEEDS_MANUAL_CHECK candidate whose block
reason is None still gets the flag (and no trailing separator).
FAIL: either case renders the opposite.

R4 -- Presentation-only, color-independent, no collateral
The input candidate dicts are not mutated. The new CSS lives outside the
protected phone media block. The text "MANUAL CHECK" is real HTML body text, not
CSS-generated content. The flag box uses border:1px solid currentColor and the
row a border-left rule, so the state is legible in grayscale. The below-seam
sha256 of both goldens (tests/test_dashboard_d2_seam.py), the _BASE fixture
shas, and the PRD-330 oracle region shas are unchanged; the only golden diff is
in the <style> block (CSS-only).
FAIL: any input dict is mutated; the CSS is inside the phone media block; the
label is CSS-generated; a pinned below-seam or oracle sha needs re-pinning; or a
golden diff reaches below the watching-zone seam.
