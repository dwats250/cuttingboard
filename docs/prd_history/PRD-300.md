WHY NOW
PRD-298 (merged @ #245) made a valid market-stress HALT conclude executor-SUCCESS (exit 0) and traverse the publish stages. That closed one hole and, by design, left the one PRD-298 recorded as KNOWN LIMITATION (connector P1 #302): a valid market-stress HALT whose single owed Telegram send returns FAILED_TRANSPORT now exits 0, so the workflow terminal notifier (cuttingboard.yml `Notify on failure`, `if: failure() && env.CB_NOTIFIED != 'true'`) is structurally unreachable, and the runtime's own send already failed. The FAILED_TRANSPORT status is captured in-process (cuttingboard/output.py get_last_notification_result) but the daily path never reads it (unlike the hourly path), so it dies with the process. Net: the morning HALT alert can reach ZERO recipients with a green job and no failure signal. This is the trader-safety gap PRD-298 deferred here.

GOAL
Close the silent window without changing any PRD-298 or PRD-299 semantics: when a valid market-stress HALT's owed notification returns FAILED_TRANSPORT, resend the IDENTICAL owed notification (reconstructed from the current validated contract via the existing formatter + dispatch) exactly once from the workflow, on the same channel/audience/credentials, so a transient transport outage does not silently swallow the HALT alert. The decision to resend is carried by an ephemeral runtime->workflow stdout sentinel; no persisted state is added and executor-success is invariant to notification-result health.

INVARIANTS
I1 Domain truth preserved: a halt stays status=FAIL / system_halted / outcome=HALT / errors=[] / halt_cause=MARKET_STRESS in every persisted artifact.
I2 Executor success is invariant to notification-result health: the sentinel/resend never change execution_success, the exit code, or the publish decision (fail-safe read, fail-open resend).
I3 Decision by authoritative in-process status, not proxy: the resend is gated on the FAILED_TRANSPORT NotificationResult status (PRD-198 #3), never on the persisted notification_sent flag.
I4 Identity, not a new class: the resend is the same owed build_notification_message(contract) message via the same send_notification path; no new notification class, no new user-visible semantics, no publication claim before render/commit/push.
I5 No persisted schema added: ephemeral stdout sentinel + env flag only; no schema/latest_run/contract field and no new authoritative record. The durable side effects of a successful resend are an ordinary audit row plus the existing dedup-state write (save_last_state -> logs/last_notification_state.json) mirroring the original successful-send path (:989) — a pre-existing file committed via the existing `git add -f logs/`, not a new schema surface (this tightens, not weakens, NON-MATERIAL).
I6 Ownership and isolation preserved: CB_NOTIFY_OWNED_FAIL ownership, should_send, the terminal notifier, and the hourly path are unchanged; the backstop fires only when the delivered count is otherwise ZERO (FAILED_TRANSPORT), so it never double-sends after a SENT (SENT = confirmed HTTP 200).

NOTE (at-least-once, intentional): the resend is at-least-once by design. FAILED_TRANSPORT includes the ambiguous case of a Telegram timeout that may have actually delivered; resending then produces a duplicate HALT alert. For a market-stress HALT this is the correct safety tradeoff (a duplicate alert is strictly better than zero), and it is bounded to a single independent attempt.

DATA FLOW
_run_pipeline (market-stress kill switch trips -> system_halted, halt_cause=MARKET_STRESS, errors=[], outcome=HALT, status=FAIL) -> _build_and_finalize_contract sends the single owed HALT notification (:981); transport fails -> send_notification returns False, get_last_notification_result().notification_status=="FAILED_TRANSPORT" -> _emit_delivery_failed_signal prints `::CB_NOTIFY_DELIVERY_FAILED::` (fail-safe) -> execute_run persists domain summary (status=FAIL) AND execution_success=True -> cli_main exits 0 -> workflow live/sunday execute step greps the log, sets CB_DELIVERY_FAILED=true -> backstop step invokes resend_owed_market_stress_halt_notification() -> load LATEST_CONTRACT_PATH -> assert_valid_contract(finalized=True) -> build_notification_message/classify_notification_priority/notification_state_key -> send_notification(notify_mode="premarket") -> on success save_last_state. SENT / SKIPPED_NO_CONFIG / NOT_REQUESTED / non-MARKET_STRESS / normal success -> no sentinel -> no backstop. Any resend error -> fail-open, exit 0, no crash.
