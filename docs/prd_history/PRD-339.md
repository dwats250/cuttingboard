WHY NOW
The frozen MATERIAL packet established (completeness-by-construction) that Cuttingboard needs
ONE canonical effective-permission authority that every actionability surface consumes, and
that the authority state must be produced/persisted/protected before any projection. Slice 1
delivers that core (produce + persist + protect); Slice 2 makes the channels consume it. AVAILABLE
stays locked until both land.

CORE INVARIANT (this slice)
Effective permission is originated/restored only by an admitted, valid, fully-evaluated daily
decision via the canonical resolver; it is carried through the session (Q1) and made more
restrictive only by an authoritative restriction; it is lowered/restored only by a new admitted
redecision (Q4); it is persisted by exactly one approved writer (no other module may author it),
it never regresses to an older/less-restrictive state through ordering/retry/replay, and it is
fail-closed (absent/invalid/prior-session/stale -> UNAVAILABLE).

GOAL
Introduce the canonical EffectivePermission carrier + resolver in the decision-authority layer,
with session/decision/run/authority-version identity, monotonic restriction + Q4 recovery
semantics, a code-enforced exclusive persisted-state writer, stale/replay/out-of-order
publication non-regression, and fail-closed canonical state -- WITHOUT yet changing how
consumers render (that is Slice 2).

SCOPE (Slice 1 -- Authority Core; from the frozen packet)
- Canonical EffectivePermission carrier: a frozen dataclass in the resolver layer
  (Q6; exact seam per packet s3/s13), carrying the resolved verdict + restriction_rank +
  decision_uid + session_date + run_uid + authority_version + valid_until + recovery_basis.
- Canonical resolver resolve_effective_permission(): the ONLY constructor, called ONCE at the
  converged boundary (packet s13 R1 / finding 4: at runtime/__init__.py ~1136-1147, before
  render_report:1464 and the execute_run report writes :417/:481), producing every verdict
  incl. HALT/UNAVAILABLE, from the finalized decision + operator snapshot + safety state +
  restored accepted-authority state.
- Identity: session_date (ET), decision_uid (unique originating daily run identity), run_uid
  (unique per invocation, breaking the mode+second generation collision at :3127-3134),
  authority_version = [session_date, decision_seq, restriction_rank] as the sole ordering key.
- Monotonic restriction + Q1 carry + Q4 recovery: within a session, restriction_rank is
  non-decreasing across observation runs; the hourly path CARRIES the admitted daily decision
  forward (observation, never reconfirming/revoking); only a new daily redecision (higher
  decision_seq + validated recovery_basis, satisfying current restrictions) lowers restriction.
- Exclusive persisted-state writer (packet s14 R3): exactly one approved resolver/persistence
  path writes the canonical field to the authoritative carriers (latest_run/contract/payload,
  ui/contract.json via the workflow cp, the report files' persisted state); all other modules
  read-only; an AST/CI test forbids any other writer (a second writer fails CI).
- Publication non-regression (stale/replay/out-of-order): the publisher admits a bundle only if
  its authority_version is not behind and does not lower restriction (across every publish
  route); older/replay/lower is refused (fail-closed).
- Fail-closed canonical state: absent/invalid/prior-session/stale canonical state resolves
  UNAVAILABLE at the read boundary.
- The accepted-authority restore/persist loop across both lanes (the carrier is restored before
  composition and persisted by the exclusive writer).

REQUIREMENTS (Slice 1; each has a binary FAIL line)

R1 -- Canonical origination + carry (Q1)
The resolver produces PERMITTED only for an admitted daily decision with a surviving actionable
candidate; an hourly observation carries the admitted daily decision forward (same decision_uid,
unchanged valid_until, restriction not lowered) and never originates or reconfirms permission;
absence of hourly reconfirmation does not revoke it.
FAIL: an observation originates/reconfirms PERMITTED, or a benign hourly demotes a still-valid
admitted daily PERMITTED, or a daily run with no actionable candidate yields PERMITTED.

R2 -- Monotonic restriction within a session
Accepted restriction_rank is non-decreasing across observation runs; a benign hourly carries the
prior rank; an hourly HALT/lock raises it.
FAIL: an accepted same-session observation lowers restriction_rank.

R3 -- Recovery only by redecision (Q4)
restriction_rank is lowered / PERMITTED restored ONLY by a new daily decision with a strictly
higher decision_seq, a validated recovery_basis, and satisfied current restrictions. Never by
observation/render/retry/replay/publication-order/stale-artifact/scheduler/operator-var-alone.
FAIL: any non-redecision event lowers restriction_rank or restores PERMITTED; or a redecision
without an incremented decision_seq / valid recovery_basis does so.

R4 -- Exclusive persisted-state writer (packet s14)
Exactly one approved resolver/persistence path writes the canonical effective_permission field
to any authoritative carrier; no other module authors, serializes, replaces, or mutates it; the
ui/contract.json cp is a verbatim copy.
FAIL: any module other than the approved path writes/mutates the canonical field (the structural
test does not fail when a second writer is introduced).

R5 -- Publication non-regression
A bundle is admitted to publish only if its authority_version is not behind the accepted one and
does not lower restriction (compare session_date, decision_seq, restriction_rank), on every
publish route (bootstrap/overlay/retry); behind/replay/lower/older-session/future is refused.
FAIL: a behind/replay/lower-restriction/older-session/future bundle overwrites the accepted
canonical state on publish.

R6 -- Identity sufficiency
Two invocations in the same wall-clock second produce distinct run_uid; ordering uses
authority_version, never generated_at.
FAIL: two same-second invocations share run_uid, or ordering uses a second-resolution timestamp.

R7 -- Fail-closed canonical state
Absent/malformed/prior-session/stale canonical state resolves UNAVAILABLE at the read boundary;
no fabricated NO_TRADE, no retained prior grant, no exception escapes.
FAIL: absent/invalid/prior-session/stale canonical state yields PERMITTED, a fabricated decision,
or an unhandled exception.

R8 -- Slice-1 isolation (no projection change)
The consumers (renderer decision-state/directives, viewer, Telegram, reports, CLI) are unchanged
by Slice 1; whole-dashboard goldens remain green (the added carrier field may be present but is
not yet consumed authoritatively -- that is Slice 2).
FAIL: a consumer's authoritative output changes in Slice 1, or a golden flips for a reason other
than the additive carrier field.
