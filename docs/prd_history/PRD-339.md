ONE canonical effective-permission authority that every actionability surface consumes, and

CORE INVARIANT (this slice)
Effective permission is originated/restored only by an admitted, valid, fully-evaluated daily
decision via the canonical resolver; it is carried through the session (Q1) and made more
restrictive only by an authoritative restriction; it is lowered/restored only by a new admitted
redecision (Q4); it is persisted by exactly one approved writer (no other module may author it),
it never regresses to an older/less-restrictive state through ordering/retry/replay, and it is
fail-closed (absent/invalid/prior-session/stale -> UNAVAILABLE).

GOAL
Introduce the canonical EffectivePermission carrier + resolver in the decision-authority layer,
with session/decision/run/authority-version identity, monotonic restriction + Q4 recovery
semantics, a code-enforced exclusive persisted-state writer, stale/replay/out-of-order
publication non-regression, and fail-closed canonical state -- WITHOUT yet changing how
consumers render (that is Slice 2).

REQUIREMENTS (Slice 1; each has a binary FAIL line)

R1 -- Canonical origination + carry (Q1)
The resolver produces PERMITTED only for an admitted daily decision with a surviving actionable
candidate; an hourly observation carries the admitted daily decision forward (same decision_uid,
unchanged valid_until, restriction not lowered) and never originates or reconfirms permission;
absence of hourly reconfirmation does not revoke it.
FAIL: an observation originates/reconfirms PERMITTED, or a benign hourly demotes a still-valid
admitted daily PERMITTED, or a daily run with no actionable candidate yields PERMITTED.

R2 -- Monotonic restriction within a session
Accepted restriction_rank is non-decreasing across observation runs; a benign hourly carries the
prior rank; an hourly HALT/lock raises it.
FAIL: an accepted same-session observation lowers restriction_rank.

R3 -- Recovery only by redecision (Q4)
restriction_rank is lowered / PERMITTED restored ONLY by an AUTHORIZED REDECISION, defined
precisely as: a full daily decision run (mode LIVE/SUNDAY through the canonical decision chain
runtime:1012-1055, NOT a hourly/observation run and NOT a republish/rerun of a prior run's
persisted artifact) that produces a NEW ADMITTED VALID decision under CURRENT inputs. Its
identity requirements: (a) decision_seq is a durable per-session counter of ADMITTED DAILY
DECISIONS, read from the restored accepted-authority carrier and incremented by exactly one on
each new admitted daily decision (observations never increment it); the redecision's decision_seq
must be strictly higher than the accepted one; (b) recovery_basis is a closed-schema record
{superseded_authority_version, superseding_decision_uid, reason in a fixed enum} referencing the
accepted prior authority; (c) the redecision must itself satisfy all CURRENT restrictions (a
still-CANNOT_MONITOR operator setting is not cleared by it). The VALIDATION PREDICATE for a
lower-rank admission is: incoming.decision_seq > accepted.decision_seq AND recovery_basis
references accepted.authority_version AND current restrictions are satisfied. An ordinary daily
RETRY/RERUN that re-publishes or re-derives a prior run's artifact WITHOUT producing a new
admitted daily decision (same decision_uid / no decision_seq increment) is NOT a redecision and
cannot recover. Never recovered by observation/render/retry/replay/publication-order/
stale-artifact/scheduler/operator-var-alone.
FAIL: any non-redecision event lowers restriction_rank or restores PERMITTED; or a redecision
without an incremented decision_seq / valid recovery_basis does so.

R4 -- Exclusive persisted-state writer (packet s14)
Exactly one approved resolver/persistence path writes the canonical effective_permission field
to any authoritative carrier; no other module authors, serializes, replaces, or mutates it; the
ui/contract.json cp is a verbatim copy.
FAIL: any module other than the approved path writes/mutates the canonical field (the structural
test does not fail when a second writer is introduced).

R5 -- Publication non-regression
The publish guard compares the incoming vs accepted authority_version LEXICOGRAPHICALLY
(session_date, then decision_seq, then restriction_rank) on every publish route (bootstrap/
overlay/retry) and admits ONLY when ALL hold:
(a) not behind: incoming session_date is not older; at equal session_date, incoming decision_seq
    is not older;
(b) no intra-decision downgrade: at an EQUAL decision_seq, restriction_rank is not lowered;
(c) recovery-gated downgrade: a LOWER restriction_rank is admitted ONLY across a strictly higher
    decision_seq carrying a validated recovery_basis (the R3 predicate) -- so the Q4-authorized
    recovery IS publishable while ordinary regression is refused;
(d) identity-qualified equality: an EQUAL authority_version is an idempotent NO-OP only when the
    incoming canonical envelope is byte-identical to the accepted one (same decision_uid); an
    equal-version DIFFERING envelope is REFUSED fail-closed.
A behind / intra-decision-lower / non-recovery-downgrade / equal-version-differing / older-session
/ future bundle is refused. (This makes R5 consistent with R3's recovery exception.)
FAIL: a behind/replay/intra-decision-lower/non-recovery-downgrade/equal-version-differing/
older-session/future bundle overwrites the accepted canonical state; OR a valid higher-decision_seq
recovery is refused publication; OR an equal-version byte-identical replay is treated as anything
other than an idempotent no-op.

R6 -- Identity sufficiency
Two invocations in the same wall-clock second produce distinct run_uid; ordering uses
authority_version, never generated_at.
FAIL: two same-second invocations share run_uid, or ordering uses a second-resolution timestamp.

R7 -- Fail-closed canonical state
Absent/malformed/prior-session/stale canonical state resolves UNAVAILABLE at the read boundary;
no fabricated NO_TRADE, no retained prior grant, no exception escapes.
FAIL: absent/invalid/prior-session/stale canonical state yields PERMITTED, a fabricated decision,
or an unhandled exception.

R8 -- Slice-1 isolation (no projection change)
The consumers (renderer decision-state/directives, viewer, Telegram, reports, CLI) are unchanged
by Slice 1. SINGLE ISOLATION RULE (PRD-review finding 6): golden comparison NORMALIZES/STRIPS the
additive effective_permission envelope from the artifact before comparing, and the remaining
existing human-facing output MUST be BYTE-IDENTICAL to the pre-Slice-1 golden. Any authoritative
visible-output delta is RED. (No "regenerate the goldens" option; the additive field is removed
before comparison, not baked into a rewritten golden.)
FAIL: after stripping the additive envelope, any existing human-facing golden output differs
(byte-level) from the pre-Slice-1 golden; OR any authoritative visible output changes in Slice 1.
