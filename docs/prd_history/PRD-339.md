WHY NOW
Confirmed on main @ 1e91f897. Cuttingboard has a canonical decision PRODUCER (the
daily pipeline that materializes logs/latest_contract.json plus the post-gate
TradeDecision set at runtime/__init__.py:1012-1055, and the daily run summary at
:1705-1768) but NO canonical carrier of EFFECTIVE PERMISSION over time. Every
confirmed defect in the Astra/Sol forensic packet is the same shape: a downstream
consumer independently reconstructs permission-like semantics from a proxy
(notify_mode, tradable, posture, filename, or publish arrival order) instead of
reading one resolved state. Reproduced on this exact SHA: F7 hourly NO_TRADE
placeholder rendered as STAY FLAT over a daily TRADE; F3 contract viewer derives
TRADE_READY from status+tradable ignoring outcome and lock; F1 a delayed older TRADE
overwrites a newer HALT on the publish branch; F2 a benign hourly render loses a
prior HALT (no restriction continuity); F5 same-second generation-id collision and
split latest bundle; F8 A+/IF NOW action language survives a NO_TRADE/HALT board.
The fail-closed operator lock currently masks the positive-permission variants; an
AVAILABLE unlock would expose them. The minimum coherent correction is one carrier
that all surfaces consume and that publication refuses to regress.

CORE INVARIANT (the rule this PRD encodes)
Effective permission is ORIGINATED only by an admitted, valid, fully evaluated daily
decision, projected as a single resolved carrier that names its decision, session,
operator provenance, applicable restrictions, and a monotonic authority version.
Within a session, restrictions are MONOTONIC: observations, renderers, schedulers,
retries, and publication ordering may raise a restriction or leave it unchanged, but
may never lower one, originate a grant, or restore an expired or revoked grant. The
ONLY event that lowers restriction or re-originates permission is a new admitted full
daily decision (a full redecision), which publishes a strictly higher authority
version carrying an explicit recovery basis. Every permission-asserting surface
consumes this one carrier; publication accepts a bundle only if its authority version
is strictly newer than the accepted one.

GOAL
Introduce one persisted effective_permission carrier, composed once at the daily
decision boundary and carried forward (never re-originated) by hourly observations,
so that the board headline, the action directives, the contract viewer, and the
publisher all obey a single monotonic effective-permission state, and no observation,
render, retry, scheduler, stale artifact, or publish ordering can grant, resurrect,
or regress permission.

EFFECTIVE_PERMISSION CARRIER (schema)
A single object attached to the daily/hourly run summary and the contract root:
- state:            PERMITTED | NO_TRADE | OBSERVE_ONLY | HALT | UNAVAILABLE
- decision_uid:     stable id of the originating daily decision (session_date + the
                    daily generation_id at :3133-3134)
- session_date:     ET calendar date (exchange/session identity, consistent with PRD-338)
- origin_event:     daily_decision | observation
- operator_provenance: ci_repo_var | local_env | absent (which channel resolved the
                    frozen operator availability for this run)
- restriction_rank: monotonic integer 0 PERMITTED < 1 NO_TRADE < 2 OBSERVE_ONLY(lock)
                    < 3 HALT
- authority_version: [session_date, seq] monotonic ordering key; seq increases on each
                    accepted state transition within a session; the ONLY ordering key
                    consumers and the publisher compare (never generated_at alone)
- run_uid:          unique per invocation (mode+second generation_id plus a
                    monotonic/random disambiguator) so two same-second invocations do
                    not collide
- valid_until / as_of: validity boundary (session close by default; any ruled expiry
                    is a Gate-A parameter)
- recovery_basis:   null unless origin_event=daily_decision lowered restriction, in
                    which case it names the authorizing redecision

REQUIREMENTS

R1 — Origination: only a full daily decision originates permission
effective_permission.state == PERMITTED appears ONLY on a daily run summary/contract
whose origin_event == daily_decision and whose finalized decision had a surviving
actionable candidate (:1051-1055). No observation, grade, posture, tradable, delivery
success, or scheduler input produces PERMITTED.
FAIL: any artifact with origin_event == observation, or any daily artifact with no
actionable candidate, carries state == PERMITTED.

R2 — Single-carrier headline
The rendered decision-state (data-raw-state / data-raw-title) is derived from
effective_permission.state whenever the field is present. When absent (legacy
artifact), the renderer falls back to today's outcome mapping (:2989-3002) byte-for-byte.
FAIL: with a present effective_permission whose state is X, the rendered
data-raw-state disagrees with the canonical mapping of X (e.g. state == HALT rendering
TRADE PERMITTED, or state == PERMITTED rendering STAY FLAT).

R3 — Hourly observation cannot re-author the verdict
Given a daily effective_permission with state == PERMITTED and a same-session hourly
observation run (origin_event == observation, hourly NO_TRADE placeholder), the hourly
render's decision-state reflects the carried-forward daily state per the Gate-A
session-validity policy (Q1), and NEVER STAY FLAT derived from the hourly placeholder
outcome.
FAIL: the hourly render emits data-raw-state == STAY FLAT / data-raw-title == NO TRADE
sourced from the hourly placeholder while the carried daily state is PERMITTED (this
is today's reproduced F7 behavior).

R4 — Restriction monotonicity within a session
Within one session_date, restriction_rank on the accepted effective_permission is
non-decreasing across observation runs. An hourly observation whose own evaluation is
benign carries forward the prior restriction_rank unchanged; an hourly observation
that evaluates HALT/kill-switch may raise it to HALT.
FAIL: an accepted same-session observation lowers restriction_rank (e.g. a prior HALT
becomes NO_TRADE/PERMITTED after a benign hourly), or a benign hourly discards a prior
HALT (reproduced F2/D).

R5 — Same-run HALT precedence preserved
Given effective_permission.state == HALT for the current run (daily or hourly
kill-switch/validation HALT), the render emits data-raw-state == HALT /
data-raw-title == SYSTEM HALT regardless of any carried decision_uid.
FAIL: any HALT-state artifact renders TRADE PERMITTED or STAY FLAT.

R6 — Operator lock precedence preserved
Given a run whose frozen operator availability is CANNOT_MONITOR (permission ==
config.OPERATOR_LOCK_PERMISSION), effective_permission.state == OBSERVE_ONLY (unless
a higher HALT applies), and the render emits data-raw-state == OBSERVE ONLY with
IF NOW / PLAY / A+ actionable directives suppressed.
FAIL: a locked run renders TRADE PERMITTED, or emits IF NOW / PLAY / an A+ ACTIONABLE
directive.

R7 — Explicit recovery only
restriction_rank is lowered (or state returns to PERMITTED after a prior restriction)
ONLY on a daily run summary/contract with origin_event == daily_decision, a strictly
higher authority_version, and a non-null recovery_basis. No observation, render,
retry, scheduler invocation, or stale artifact lowers it.
FAIL: any non-daily-decision event, or a daily decision lacking a strictly higher
authority_version, lowers restriction_rank or restores PERMITTED.

R8 — Publication non-regression
The publisher accepts and overlays a bundle onto origin/publish ONLY if the incoming
effective_permission.authority_version is strictly greater than the one currently on
origin/publish (comparing session_date then seq). On tie, older, older session_date,
or a bundle whose as_of is in the future beyond tolerance or past its validity, the
semantic overlay (ui/*, latest run/contract/payload) is refused (guard exits non-zero;
ci_push_artifacts.sh aborts the overlay). Audit append is unaffected.
FAIL: a delayed/retried/older/older-session/future-dated bundle overwrites a newer
accepted effective_permission on publish (reproduced F1/B/C/E/G/I).

R9 — Accepted-bundle identity
The daily/hourly run summary, contract, and payload written by one invocation share
the same run_uid and authority_version, and the publish guard treats them as one
bundle: a split (mismatched run_uid/authority_version across latest run/contract/
payload) is refused publication.
FAIL: latest_run.json and latest_contract.json carrying different run_uid /
authority_version are published together (reproduced F5 split-bundle).

R10 — Identity sufficiency (no timestamp-only collision)
Two invocations occurring in the same wall-clock second produce distinct run_uid, and
their ordering is resolved by authority_version, not by generated_at.
FAIL: two same-second invocations produce identical run_uid, or ordering is decided by
a second-resolution timestamp (reproduced F5/J collision at :3127-3130).

R11 — Viewer obeys the carrier
ui/app.js derivePosture resolves from effective_permission.state. A contract with
status OK and system_state.tradable == true but effective_permission.state in
{NO_TRADE, OBSERVE_ONLY, HALT, UNAVAILABLE} does NOT render a TRADE_READY / actionable
posture. When effective_permission is absent or malformed, the posture defaults to a
non-actionable UNAVAILABLE state, never TRADE_READY.
FAIL: derivePosture returns TRADE_READY (or an actionable posture) for a locked /
NO_TRADE / HALT / absent effective_permission (reproduced F3).

R12 — Missing / malformed / prior-session / future authority is UNAVAILABLE
When effective_permission is absent, malformed, references a prior session_date, or
carries an as_of in the future beyond tolerance, every consumer resolves state ==
UNAVAILABLE (fail-closed) rather than fabricating NO_TRADE or retaining a positive
grant. No exception escapes the renderer or the guard.
FAIL: a missing/malformed/prior-session/future carrier yields PERMITTED, a fabricated
NO_TRADE presented as a decision, or an unhandled exception.

R13 — Action language consistent with the effective verdict
IF NOW, PLAY, and A+ ACTIONABLE directives are emitted only when
effective_permission.state == PERMITTED. Under NO_TRADE / OBSERVE_ONLY / HALT /
UNAVAILABLE the board retains analytical context (grades, levels, maps) but emits no
current action/permission directive.
FAIL: A+ ACTIONABLE or IF NOW appears on a board whose effective_permission.state is
not PERMITTED (reproduced F8).

R14 — Additive-only for daily default renders
When effective_permission is present on a daily default render, the whole-dashboard
goldens and the PRD-334 verdict-translation guard
(tests/test_dash_verdict_translation.py) remain green, with only the intended
decision-state/directive attributes changed by the resolved state.
FAIL: an unintended golden diff, or a green->red flip of the verdict-translation
guard, on a coherent daily PERMITTED render.

CONCURRENCY / ATOMICITY BOUNDARY (code guarantee vs operational containment)
Requires a CODE guarantee in this PRD:
- Publication non-regression (R8) — reachable even with a single authorized lane via
  publish retry (ci_push_artifacts.sh:180-198) and Pages-on-completion (pages.yml).
- Accepted-bundle identity + unique run_uid (R9, R10) — cheap, and it is the ordering
  primitive R8 depends on.
- Consumer fidelity (R2/R3/R11/R13) and monotonic carry-forward + recovery (R4/R7).
Becomes safe by RETIRING unauthorized lanes (OWNER ACTION, not PRD code):
- Multi-writer shared-directory execution (local cron L6, hidden external-trigger
